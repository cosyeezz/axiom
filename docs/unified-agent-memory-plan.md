## 交付范围

1. 将子代理执行机制与职责拆开：显式角色、可自定义职责提示词、能力配置及持久化；复用 Tasks 的预算、取消、通知、恢复和计费。
2. 主代理直接工具收敛为 read/bash/edit/write/question/ask_axiom/let_axiom。任务与 Todo 经 ask/let 调用；移除 history_read（不替换为 history.read）和 obs_recall 的模型入口，保留会话历史保存、压缩、检查点与恢复。
3. 简化常驻提示词，保留准确能力目录、重要授权/暂停/验收边界和输出协议；详细正式规程按需取得，不能被经验整理覆盖。
4. 长期记忆采用全局和项目索引及自由格式 Markdown 卡片。记忆查询作为只读独立 Pi 任务；整理读取明确的原始材料与相关旧记忆、仅修改授权记忆目录。只整理材料支持的事实，先合并旧记忆，没有价值则不产出。不接 Jev/Laya，不引入单独 memory 工具。
5. 功能完成后至少五轮不同侧重的检查优化，记录发现、处理与验证；最后按仓库规则提交、推送工作分支、同步合并并推送 master，清理本任务 worktree。

每轮在实现完成后执行；不是只重复同一测试。问题修复后重跑受影响检查；无发现也记录范围和依据。

2. **生命周期与恢复**：任务持久化、恢复、预算、取消/追加、通知投递、结果读取、用户暂停不被后台任务解除。

4. **提示词与记忆质量**：能力可发现性、正式规程与经验隔离、全局/项目范围、先索引后卡片、原文事实与增量更新、没有新信息不写入。
5. **最终回归与交付**：仓库回归、差异审查、文档一致性、最新 master 同步后再次验证、提交推送及清理。

## 设计边界

- 自定义提示词不是权限凭据；访问控制由代码执行。
- 记忆中的文字是参考资料，不是当前授权。后台整理不主动执行卡片引用的脚本。
- 正式操作卡片与参数契约由版本库管理；记忆整理不能修改。
- 后台整理使用可追溯的明确材料，不把摘要中的推断当事实；避免自我复制、并发覆盖和恢复时重复启动。
- 任务读取消用同一套 task 指令，不增加 memory.read/memory.cancel。
- 移除原文读取工具后，模型不能再按消息 ID 回读被压缩内容；界面与落盘历史保留。文档明确这一取舍，不声称检索仍然可用。
- 不改动主 checkout 的现有未提交文件；所有实现位于专用工作分支/worktree。
