# 原生压缩与会话任务状态：执行基准

## 1. 目标与优先级

本文件是本次实现与后续开发的执行基准。用户已授权直接完整实现，不再等待方案确认。它替代旧方案中要求摘要逐字摘录、生成消息来源标记及失败后无核验回退的生成路径；原文归档、精确历史读取、提交安全和过程可观察性继续保留。

摘要只承担上下文压缩。任务状态只承担跨压缩保留目标、约束、决策与未完成事项。不得将其重新演变为逐句引文协议或主代理日常维护任务。

## 2. 已确定行为

1. 摘要保持SDK原生提示词与原生结构，不要求逐字抄写、来源标签或额外事实数组。
2. 仅在压缩时生成/更新一份简短Markdown任务状态文档。主代理不在每轮手工维护，不委派缺失完整输入的子代理代写。
3. 状态维护的事实基准是同一冻结快照中的：上次已应用摘要、上次已提交任务状态文档、本次待压缩消息。不得以本次失败草稿作为事实或已确认状态。
4. 状态按原文档增量更新语义生成：无明确变化则保留约束；用户新指令可改变旧决策；区分计划、实现、验证；信息不足标待确认，不能默认完成。
5. 建议内容：当前目标；有效约束与已确认决策；当前阶段；未完成/待验证事项。避免操作流水和冗长历史。
6. 原生摘要与状态文档属于一个压缩版本，全部成功并通过提交检查才能一起生效。状态失败不能只应用摘要并假称状态已更新。
7. 状态文档明确截止于本次压缩切点；切点后的原消息优先表示更新，不被旧状态覆盖。
8. 每个独立会话隔离：主代理状态描述总体任务；子代理状态仅描述自身任务。短任务不压缩则不额外生成文档；子代理结果经主会话正常消息进入下一次维护，不直接改主状态。
9. 自动、手动异步、手动同步使用相同生成与提交规则。异步冻结的是输入范围，不冻结主代理；保留现有失效、取消、窗口预算、工具配对、归档持久化和提交不确定保护。
10. 摘要与状态的实际请求、完整输出、阶段失败原因可观察且刷新可恢复；不记录认证密钥，不显示隐藏推理。旧历史及已有尝试记录可读。

## 3. 实现边界

- 优先使用现有会话权威日志的同一compaction记录持久保存两份产物，避免两个文件分别提交造成版本错配。若提供外部Markdown文件，只能作为可重建投影，不另立权威。
- 恢复/执行上下文要独立提供状态正文，而非让主代理自己记得读取。不得将状态混作原生摘要生成结果。具体SDK适配点在源码核对后补充于本文件。
- 输入完整性按实际SDK序列化能力说明，不宣称摘要模型看到了已截断的工具全文。状态请求必须有明确预算与取消支持，不通过无界全历史请求绕过窗口限制。
- 生成失败保留原历史，不无限重试，不用失败状态草稿污染下一轮。高水位无法继续时明确阻塞，不能为了继续运行静默跳过状态更新。

## 4. 必须验证

- 首次压缩、连续两轮继承、旧会话无状态兼容、重开恢复。
- 主/子会话隔离，未压缩无额外维护调用。
- 状态请求含上次摘要与原状态及冻结原始输入；新增消息不漂入本次状态覆盖范围。
- 摘要或状态失败/取消/失效均不部分应用；归档及持久提交屏障仍有效。
- 纯原生摘要无增强来源指令；真实请求、输出及状态过程可取回。
- 全量自动测试、适用浏览器验收、有界真实供应商历史副本验收；真实验收不得改原会话或泄露配置。

## 5. 交付规则

先以本文件约束实现，随实现同步README和devlog并记录测试事实。工作分支基于最新master；验证成功后按仓库约定提交、推送、合并master及清理本任务worktree。不重启当前运行服务，不修改用户已有工作区内容。

## 6. 实施记录

- 执行基准已落盘。明确采用同一compaction记录：summary保持原生正文，details.stateDoc保存Markdown状态，details.stateBoundary记录范围。请求context钩子从当前分支最新compaction派生独立状态消息，置于摘要之后、保留原消息之前；不新增权威文件，不依赖可漂移缓存。
- 首版在原生摘要成功后串行维护状态，以减少额外同时请求并避免摘要失败时浪费状态调用；两者均属于后台压缩流程，不占主代理维护轮次。状态请求复用同一观察器、取消信号及请求窗口检查；完整输入超预算时失败，不静默截断约束。
- 用户进一步明确：不需要保留任何旧原生回退机制。生成层回退与手动同步紧急回退已移除，测试按失败不应用更新。实现与验收结果见以下记录。
- 连续两轮测试发现SDK读取压缩后缺少usage的助手消息时抛异常，导致第二轮未启动。压缩控制器在usage不可读时按既有本地估算继续执行窗口校验，而非跳过安全检查；两轮继承测试已通过。自动、异步、同步三种模式的双持久屏障与配对提交测试已通过。
- 审查补齐状态请求的供应商env传递；无compactionSummary时不注入派生状态。明确拒绝状态超窗沿用旧文档或length截断结果直接提交：这些降级破坏同版本要求，仍应整体失败并保留原历史。
