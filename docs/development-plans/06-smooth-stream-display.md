# 06 平滑流式显示：独立开发任务书

> 2026-09-16 状态更新：**已集成并通过本轮回归验证**。下文原方案及当时测试声明保留为历史记录；当前实现、验证和限制以[集成交付记录](../current-runtime-integration-status.md)为准。

日期：2026-09-15。待实施方案，未运行实现测试。

## 1. 用户目标与现状

用户接受一点显示延迟，希望成批到达的文字连续出现，例如每秒到10字，不瞬间贴10字再停一秒，而是在时间上平滑展开。

当前 `public/app.js` 接收delta累计raw后通知renderer，`public/stream-renderer.js`已有合并/交互让路，`public/markdown.js`负责解析与净化。已有节流不等于平滑播放；本组复用现有调度入口，不再叠加第二套抢占DOM的定时器。

```text
真实事件 -> 唯一消息归并数据（立即更新）
                     -> 显示游标（稍延迟） -> 可见消息DOM
```

## 2. 范围和不变量

只对当前可见的活动回复实现短缓冲、平滑推进和有界追赶。历史、配置、工具卡片不统一逐字动画；代码和表格允许按块更新。

- 不减慢WebSocket，不延迟任务完成数据，不修改raw、SDK上下文或落盘内容。
- 06不接原始delta、不处理seq、不做第二reducer，只读已经归并的完整正文。
- 05负责mount/unmount和滚动窗口；06只拥有显示游标，不缓存历史DOM、不请求历史页。
- Markdown净化、链接安全、键盘/选择/辅助技术不因动画退化。
- 平滑不等于每帧解析整段Markdown；主线程真卡顿需要05和解析治理共同处理。

## 3. 拟议最小契约（非已有）

```js
updateVisibleMessage({ key, text, revision, terminal, mounted });
disposeMessage(key);
```

key目标为sessionId+agentId+messageId。现有start事件不能假定已有稳定messageId；05与集成负责人统一身份，03维持会话seq作用域。独立测试使用人工稳定key。过渡实现可用当前活动item对象加generation标识，但不能只用sessionId+agentId导致上一回复游标污染下一回复。

05卸载仅销毁显示状态，权威正文不变；重新挂载默认直接对齐最新内容，不从头播放。06需通过现有布局变化通知入口让05测高/维护锚点，不自行抢滚动所有权。接口具体名字集成前确认。

## 4. 播放策略

初始短暂缓冲，按近期到达速度平滑调整目标显示速度，用requestAnimationFrame按真实经过时间推进，而非逐字符setTimeout。数值集中为少量参数：启动缓冲、目标滞后、最大允许滞后、结束收尾时间。先用假时钟验证，再实机调参，不把1秒写死为产品承诺。

- 新数据到达时pending可以增加，不能错误要求它始终单调减少；没有新输入时显示游标应单调前进，最终追平。
- 正常播放维持适量缓冲；积压过大逐渐加速，达到硬上限时允许直接对齐或按块追赶，不能为了动画无限落后。
- 缓冲空了等待真实内容，不制造文字。长网络空窗无法靠有限缓冲保证永不暂停。
- 帧间断层限制本帧工作预算，不按后台消失的时间补做几万步；不可见时直接停动画，恢复时对齐最新。
- 不把正文副本反复入队：权威文本一份，游标/必要索引有界；若权威活动消息本身超大，需已有内容按需加载策略，不能声称本组限制了所有消息内存。

## 5. 字素与Markdown正确性

使用Intl.Segmenter按字素处理中文、组合字符、emoji ZWJ和旗帜。UTF-16切片与字素偏移要明确区分；流末尾字素可能被后续字符扩展，应重分段未稳定尾部，不用固定几个码点假装覆盖任意组合序列。超大未稳定尾部走预算降级；不支持Segmenter时直通批量显示而非截断字符。

Markdown不能凭空行就认定前缀永久稳定：列表、围栏、引用定义等可能改变前文解释。**第一版不自写尾窗Markdown解析器**，复用现有解析/净化，降低解析频率并按真实预算更新；对已经确认可安全增量的普通文本节点才平滑推进。结构复杂或长块可按批更新，保持正确性。

不得对每个显示字素重跑整段解析；若现有renderer无法在正确性下满足预算，应明确先只交付普通文本平滑、复杂块批量显示，随后独立优化解析路径。最终收口也必须可让出主线程，不能把全部开销藏到结束一帧。

辅助技术避免每字触发live-region播报；复制全文从权威文本读取，用户已有DOM选区不因重建突然消失。流中选择文本时可以暂停视觉推进或采用保留节点策略。

## 6. 生命周期与失败安全

| 场景 | 行为 |
|---|---|
| 正常到达 | 数据立即归并，视觉按预算推进 |
| 任务结束 | 真实终态立即更新，剩余文字在有界时间内收口 |
| 用户取消 | 停止的是业务请求；保留已收到文字并迅速对齐，不抹掉尾部 |
| 断线 | 保留已有正文；重连快照revision变化后重置显示，不重复动画 |
| 消息被替换/压缩 | 按revision失效旧游标，不把新正文当旧文本追加 |
| 切会话/卸载 | 取消调度并释放局部状态；不删权威数据 |
| 页面隐藏 | 停止播放，回来直接对齐，不能补播后台全部输出 |
| reduced-motion | 取消逐字动画，合并批量显示；运行中设置变化立即生效 |
| 显示异常 | 降级现有安全renderer、可见报告；不关闭连接或影响其他回复 |

## 7. 文件归属与独立开发

本组拥有最小播放状态机和对应测试，建议 `public/stream-playback.js`；现有stream-renderer改动也归本组统一负责。`app.js`与共享Markdown模块由集成负责人接线，防止05/06同时改同一渲染入口。

首个里程碑只接当前可见回复普通文本，直接改善观感。无需等待历史虚拟列表：用假mounted状态与权威文本提供器开发，05后续替换挂载适配器。

## 8. 实施步骤

1. 测当前renderer调用链与解析次数，确定已有调度可复用点。
2. 假时钟实现游标/缓冲/终态和生命周期，无DOM无网络。
3. 普通文本挂载适配，验证字素与不可见降级。
4. 复用Markdown安全路径，复杂块预算化，测结束收口。
5. 与05联调测高/阅读锚点，与04联调区域更新，真实节奏验收。

## 9. 最小可运行测试计划

拟新增 `tests/stream-playback.test.js`，执行 `node --test tests/stream-playback.test.js`。文件尚未实现，命令是后续交付要求，不是本轮通过证据。

注入now/schedule/cancel与假正文源：

- 每1秒10字持续输入：缓冲后显示逐步推进，而不是每批只一次跳变。
- 变速、突发大量正文、空窗、低帧率：无输入时追平，最大滞后到限会加速/降级，内存不随待播放副本无限增长。
- 所有显示都是当前真实文本的合法字素前缀；emoji跨批、组合字符、旗帜不截断。
- 终态/取消完整收口，切换和旧回调不污染新消息；相同revision更新幂等。
- 隐藏/恢复/reduced-motion/mount/unmount无残留定时器。
- Markdown围栏、列表、引用链接、表格和恶意HTML最终与现有安全渲染一致；不能只测普通文本就声称全Markdown平滑。

真实浏览器串行记录帧耗时/长任务、解析次数、显示滞后分位与最大值、峰值缓冲、最终正文一致性。慢CPU下输入、停止、滚动仍响应；菜单节点不动。低于设备帧预算等数值需记录机器和测试数据，不能用主观“丝滑”代替验收。
