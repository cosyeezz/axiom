# Axiom

## 通用指令组件

`src/instructions.js` 提供 `createInstructions()`，实例只暴露 `register({ name, description, parameters, handler })` 和 `execute(name, arguments)`。注册名称唯一、精确匹配；`parameters` 为可信程序提供的对象 JSON Schema，注册时保存快照，执行前使用 TypeBox 校验参数，不自动转换类型。`handler(arguments)` 返回结果或抛错，不接收执行上下文。

会话新增两个英文 schema 工具：`ask_axiom({ name })` 获取已知指令的调用说明；`let_axiom({ name, arguments })` 执行已知指令，无参数传 `{}`，名称不得猜测。`ask_axiom` 只是 `execute("axiom.describe", { name })` 的封装；内置说明指令同样通过注册接入，返回 `name`、`description`、`parameters`。`instructionTools(registry)` 可将注册实例封装为两个 Pi 工具；默认每个会话创建独立实例，目前只注册说明指令，现有业务工具不迁移。

组件不提供搜索、列表、模型推理、任务状态、取消、超时、重试或其他生命周期管理。宿主原有准备/总结阶段工具限制保持不变；两个新入口暂不作为 Todo 的执行验收证据。新增指令无需改变工具 schema。验证：`node --test tests/instructions.test.js tests/goal-pi.test.js`（后者使用本地假供应商，不产生模型费用）。

### 供应商与模型并发配置

在 **设置 → 模型与供应商 → 选择供应商 → 模型 → 并发与限流配置** 中点击「读取限额」，设置供应商总并发、供应商 RPM 和各模型并发后保存。自定义和内置供应商均支持；原用量页保留审计展示与历史导入，不再编辑限额。

限额保存在 SQLite 的 `usage/limits`，旧供应商配置继续有效。模型限制使用 `limits[provider].models[modelId].concurrency`，不混入 SDK 模型连接配置；0 或未配置表示不限。供应商和模型并发同时检查，受限模型不会占住供应商额度阻塞其他模型。保存对后续请求生效，不中断在途请求；沿用原有租约/排队超时故障放行策略，因此不是供应商硬配额保证。外部 Pi 扩展仅在会话启动时注册已有限额的供应商，新启用限额需重新启动外部会话。

## 会话安全点

会话安全点用于保留当前位置之前的上下文，包括该点已应用的压缩。回退复用 Pi 原生树导航，Fork 使用独立 SessionManager 创建新会话，不恢复文件或命令副作用。恢复后暂停，允许回填下一条用户消息或直接继续执行。入口在历史边界悬停/键盘聚焦时显示；安全点与消息保持接近原有的间距，触屏入口保留 40px 点击区域而不撑开历史。主会话模型与上下行用量保留在原消息中，位于对应安全点标识线上方。连续工具调用仍合并折叠，组内安全点随所属消息或工具详情展开显示，不再为了展示安全点拆分调用组。操作前需停止主会话与子任务、处理排队消息；目标模式需先退出。Fork 在新标签页打开，源会话保持不变。回退不回滚 SQLite Todo，但会暂停清单，核对后需显式恢复；继续安全点本身不解冻 Todo。Fork 使用独立空清单，不继承源会话事项。


## Todo 长会话控制与原生压缩

Todo 行为规则仅在主代理静态系统提示词中统一说明，不在每次请求、每轮或工具调用后追加清单概览与读取提醒。工具照常返回实际数据；空闲推进仅发送简短继续工作通知，不重复注入规则。已移除“三次重复读取即暂停／停止”限制，读取次数不会改变任务状态；用户主动暂停、重启冻结、版本校验和有界空闲推进保持不变。

Todo 工具返回可直接复用：持有同版本且包含相关事项的 `todo_read`／`todo_update` 返回时，无需再次读取；缺少相关事项或版本冲突时才按需读取。查询采用有界分页，更新按 `baseVersion` 原子提交，失败整批回滚。一级目标包含范围与验收标准，创建或变更须经用户确认；二级步骤由主代理维护。步骤全部完成不等于目标验收通过，一级目标完成仍须提供可核对的验收记录与引用。

当前开发执行基准：[统一任务生命周期执行方案](docs/Axiom-Todo统一任务生命周期执行方案-v1.0.md)。仅主代理拥有 `todo_read`／`todo_update`，以稳定 ID 维护最多两级清单；SQLite 的 `todo_lists`、`todo_items`、`todo_events` 是任务状态与审计记录的权威存储。子代理不维护主清单，由主代理验收其结果。首次建单确认前不写任务表，拒绝或取消不会遗留半成品清单。

输入框上方展示清单，可折叠为 SVG 状态图标与数字；折叠时不保留任务行，展开后有界加载，详情按需读取，折叠偏好按浏览器全局保存。Axiom 仅在主会话空闲且没有其他待处理工作时督促继续。用户停止会持久暂停并冻结子任务通知，普通输入不解除暂停；服务重启后须核对产物并显式恢复。`/goal` 仅为准备清单的入口，不再有独立 Goal 状态机、轮次工具或正文完成标记。

自动、手动异步及同步压缩均直接调用 SDK 底层 `compact()`，只通过 `customInstructions` 追加可选标题和简述要求。不生成或注入任务状态文档，不自建摘要协议，不核验 facts／摘录，不作失败回退。展示字段缺失使用默认 UI 文案，不增加模型请求；split-turn 的 turn-prefix 请求沿用 SDK 自身规则。保留冻结输入、窗口检查、取消、原文归档和提交屏障。工具输出沿用 SDK 序列化边界，不宣称看到所有工具全文。

## 压缩切点恢复

- 最新一批工具结果超过最近保留 tokens 预算时，压缩会向前回退到对应助手消息，完整保留工具调用与结果，继续摘要更早的历史；保留 tokens 是切点目标，不会为满足目标拆散工具配对。
- 若保留尾部与摘要仍超过安全窗口，仍保留原文并阻止无效请求；此修复不绕过预算、归档或摘要校验，也不解决供应商并发限制与请求拒绝。

## 压缩与能力选择界面

- 手动压缩确认框沿用统一主题弹窗与自定义下拉菜单，切换同步／异步模式不改变窗口尺寸。

- 子代理能力模式使用统一下拉菜单；能力与压缩模式不提供模型收藏星标。

## 配置作用域与生效时机

- 全局「默认配置」不再列举工作空间，未独立配置的工作空间使用全局默认。
- 侧栏每个工作空间标题右侧（新建按钮旁）的配置按钮编辑该工作空间的新会话默认值，不切换当前会话，可恢复全局默认；侧栏会话已有的下拉菜单包含「配置」，点击非当前会话时先切换到目标会话，再编辑其配置。配置入口统一使用标准齿轮图标；工作空间齿轮与同排「＋」按钮共用尺寸、悬停显现与高亮样式，触屏常显。页头不再保留重复入口。工作空间和会话配置使用独立标题的作用域弹窗，隐藏全局设置导航及浏览器复制、配置预览、全局任务预算等无关区块；表单置于首位，并明确说明仅修改当前会话或该工作空间之后的新会话，不修改全局默认。
- 编辑器区分热更新、新会话与重启服务：当前会话的模型、思考、压缩设置用于下次请求；子代理模型选择保存在当前会话，并从已有子代理的下一次模型请求生效，不中断已发出的请求；新建或续接子代理使用该选择，选「跟随主代理模型」时随主模型更新。子代理思考等级与压缩设置仍仅在新建/续接时采用，无需重启当前会话。能力装配与重试词表在空会话首次发送前可连续修改，点击「应用能力与重试配置」统一提交；关闭或切换配置会放弃未应用选择。模型等热字段仍自动保存，不夹带能力草稿。已开始的会话保持只读，应修改默认值后新建会话。
- 修改全局或工作空间默认值不推送到已存在的会话，包括压缩设置。服务监听参数与启动环境变量需重启服务，不属于会话覆盖。

点击「新会话」先返回内存会话和 UI 快照，创建回执到达即插入侧栏新行，权威列表在后台校正、不阻塞交互；请求在途时按钮不置灰，重复点击由在途守卫拦截。打开已有会话先读取历史；回执发出后后台静默准备进程，不等待进程就绪才显示会话。发送消息立即在 UI 展示等待状态，后台在初始化完成后继续处理。没有用户消息的新会话不写入会话库，改名和配置不会保存空壳；第一条用户消息进入会话后开始持久化。单次创建复用能力目录用于默认过滤和选择校验，不跨请求缓存。后台准备前的存在性检查对 Sessions 替身宽容：只有确知会话已被移除才跳过，浏览器预览与测试桩没有内部 `items` 表也不会把进程弄崩。连续修改的浏览器回归使用 `tests/empty-session-config-preview.mjs`（默认端口 4393，真实 Sessions 与慢装配模拟代理），再运行 `python tests/empty-session-config-ui.py`。

## OP 复核修复（历史记录）

> 以下记录旧 OP 方案的修复，不代表当前请求处理机制。当前 `AXIOM_OBSERVATION_PACK` 已弃用并被忽略，不能启用旧折叠策略；旧归档取回兼容仍保留。

- 仅 `obs_recall` 工具结果参与回显折叠与摘要去重，普通工具正文中的标记不再被当作归档来源。
- 新归档先完整写入、同步，再原子发布；manifest 损坏直接拒绝取回。同内容跨调用共享 `blobs/<SHA256>.txt` 硬链接，旧 observation ID 与取回路径兼容，取回 details 增加稳定 `sliceId`。
- `AXIOM_OBSERVATION_PACK` 严格检查布尔类型和未知字段。新增 `minContextTokens`（默认 0，原始消息粗估低于门槛不新增折叠）与 `reportFullSends`（默认跟随 fullSends，单独保护 read_result 报告）。默认行为兼容；可按任务启用压力门槛和较长报告保留期。
- 元数据/占位符跨投影缓存限制为 256 项、8 MiB 原文预算，取回校验缓存限制 256 项；文件变化仍重新校验。摘要应用前后按原始历史估算比较，投影 usage 单独保留。
- 启用请求审计时，OP ledger 的 `request-usage` 将实际 input/cacheRead/cacheWrite/费用、审计 requestId 与投影 seq 配对；未启用审计时不伪造请求级成本。该关联用于分析，不自动宣称因果节省。
- 面板显示“本次投影减少约 … tokens”，不等于净成本节省；不包含取回、额外轮次、缓存变化。无折叠样本显示“样本不足”，只有取回失败标红。
- `query`、`startLine`、`offset` 定位模式互斥，`contextLines` 必须与 query 使用，零页预算拒绝。原始旧归档无 manifest 时仍支持宽松读取并标 unverified；严格校验可拒绝。

桌面端基于 [Pake](https://github.com/tw93/Pake) 轻量壳（Tauri/WebView），不再使用 Electron。壳内置本地「连接入口页」（`desktop/connector/`）：服务地址不在构建期烘焙，启动后可配置本机或远程地址（`host:port`，默认端口 4319，也接受完整 `http(s)://` 地址），点连接后整页跳转到该地址加载网页工作台；已连接页面的右上角连接状态可点击直达设置的「连接」面板切换地址，断线时也可用。

远程连接：在被连接机器上以 `AXIOM_HOST=0.0.0.0`（或内网 IP）启动服务并放行端口，桌面壳或其他设备即可通过 `http://<地址>:<端口>` 直连；WebSocket 升级仍要求 Origin 与 Host 同源（或无 Origin 的非浏览器客户端）。不要将本地 Agent 服务暴露到公网。
会话按需加载：打开历史只读取数据库和 JSONL，不初始化会话 SDK；发消息或执行需要代理的操作时才恢复。持久化会话空闲5分钟后按分钟检查释放；运行任务、通知、待保存、队列和活动Goal会话不释放。释放不删除历史或订阅，失败会保留错误信息。

应用内标签：打开过的会话显示在顶部，可切换并保留草稿、附件和滚动状态；关闭标签不删除会话、不取消任务，重新打开仍恢复本次窗口内的草稿。关闭最后一个标签仅隐藏标签，不新建业务会话。跨工作区切换与侧栏“打开”均使用应用内标签，不弹出外部浏览器。

直接用浏览器打开 [`pelican-bicycle.html`](./pelican-bicycle.html)：自行车骑在鹈鹕背上的抽象 2D 循环动画，纯内联 SVG + CSS，无外部依赖，支持暂停和系统减少动态效果设置。

Axiom 是独立开发、独立发布的项目，唯一代码仓库为 [`cosyeezz/axiom`](https://github.com/cosyeezz/axiom)。

多智能体协作的可靠基础。独立 Node.js 服务，通过 Pi SDK 运行主 Agent，以 `delegate` 并行启动子 Agent、以 `read_result` 读取结果，通过 WebSocket 输出实时事件。

会话运行中保持吸底：正文流式输出、工具记录、图片解码、折叠展开等任何内容增高都贴到最新，用户主动上滚（滚轮、触摸、键盘、拖动滚动条）才暂停跟随，滚回底部或点「回到最新消息 ↓」自动恢复；上方「回到最早消息 ↑」跳到开头并暂停跟随。跟随状态只由“是否贴底”和“用户意图”决定，布局重排、程序跳转与内容增高引发的滚动事件不会误判成用户离开底部；两个按钮上下分开，沿用现有按钮样式。浏览器回归：先运行 `node tests/conversation-preview.mjs`，再执行 `python tests/autoscroll-ui.py`。

执行过程按正文分段：连续思考与工具调用共用一行 `Working`，模型名和用量统计不分组，回答前的 thinking 并入紧邻的前段工具组，不重复堆叠 Completed；出现后续用户消息或模型正文后，前段变为 `Completed` 并自动收起。工具返回不会触发最新执行段完成或折叠；子任务卡片等分隔出的旧段若已无待执行记录，则显示 Completed，不再跟随最新段一起 Working。执行过程的 Working 还受 Agent 实际状态约束：中断、结束、断线或恢复空闲快照后不再转圈；有失败/停止记录时显示 Stopped，否则显示 Completed。状态变化不会强制折叠用户正在查看的记录。子代理详情内的执行、思考和工具标题随正文滚动，不吸顶叠层遮字；Working 行沿用面板背景，不出现突兀黑条（主会话吸顶行为不变）。主动中断后不会自动重放命令，发送“继续完成任务”可让 Agent 根据历史接着处理。消息底部以 `供应商 · 模型 · 思考级别    113,494↑  1,234↓` 展示元信息；思考级别只在消息有记录时显示，箭头分别代表输入/输出 tokens，窄屏整体换行。

## 停止运行

输入框右侧运行操作下拉中的 `stop` / `force` / `steer` / `followUp` 点击即执行，无需再点击主按钮；`force` 仍需通过原有确认弹窗。不可用操作保持禁用。

运行中输入区提供两级停止，都会先把队列里的 Steer / Follow-up 退回输入框：

| 按钮 | 行为 | 代价 |
| --- | --- | --- |
| `Stop ■`（安全停止） | 等当前这一步（一个完整 turn，含正在跑的工具）自然结束再停 | 不丢产出，停下后可发「继续完成任务」或手动继续 |
| `Force ⚠`（强制停止） | 立刻中断请求与工具（Goal 目标模式例外，见下） | 本轮未完成的回答与工具产出会丢失，需弹窗确认 |

```text
安全停止： 工具跑完 → turn 结束 → 停在边界 → 产出全留
强制停止： 立刻切断 ───────┤ 本轮未完成内容丢弃
```

- 安全停止只标记「下一个安全点停」，不杀进程，因此长命令或大批并行工具可能要等一会儿；等不及就用强制停止，两者始终并存。
- 等待期间输入框上方显示绿色提示条「安全停止中，等待安全点」（带图标与跳动省略号，遵循系统「减少动态效果」设置），此时安全停止按钮隐藏、只留强制停止。刷新或换页重连后提示条按会话快照恢复。
- 双按 Esc 触发安全停止；强制停止只能点按钮并确认，不绑快捷键。
- 停下后会话标题前出现提示圆点，点一下消失（与侧栏「待查看」同一套已读标记，仅当前页面内存态，不跨标签页同步）。正常跑完不显示。
- 主代理安全停止后，已运行的子代理可在自身预算内继续；普通会话强制停止则同时向活跃子任务发出统一停止信号，待其停止并总结后交付。两种会话级停止都会暂停通知自动唤醒，下一次用户运行恢复投递，待通知结果仍保留；子任务详情的单独停止不停止主代理或兄弟任务。
- 若停止时正处于自动重试的等待退避中，安全停止会取消该重试并当作收工上报，不当失败报错；真正跑失败（未请求停止）仍照旧抛错。
- 队列排队中的 Steer / Follow-up 本轮一律不消费：停下的运行不会因为“还有排队消息”而自动再接一轮。
- Goal 目标模式下两颗停止按钮都走 Goal 自己的安全暂停（保留目标进度、等子任务收尾后落定到 `paused`），因此目标模式下没有「立刻中断、丢弃未完成产出」的强停止。
- Stop 按钮右侧的方块使用现有危险提示红色，文字与按钮边框保持不变。

## 子代理位置与恢复

- 子代理入口按 `delegate` 返回的任务 ID 绑定委派工具，显示在对应执行段之后，而不是最终回答末尾；刷新、迟到状态和同批多任务保持同一顺序。压缩后的入口仍归入对应摘要。
- 子代理过程使用独立 Pi JSONL 落盘，并与原 task ID 关联；重启后恢复历史，重启前尚未完成的任务自动继续，已完成或用户主动取消的任务不自动执行。
- 子代理详情底部可直接对话：选择「立即插入」或「本轮结束后」，点击发送或按 Ctrl/Cmd+Enter；已结束且保有历史的子任务会沿原会话续接。启动/停止/总结期间消息排队，执行通知送达并确认清理后续接；无历史或停止未确认时不强行重跑，发送失败保留输入。
- 详情中的模型选择复用主代理模型菜单与收藏能力，修改的是当前会话的子代理模型：已有活动子代理的下一次请求及后续新建子代理都使用新选择，不修改主代理模型、其他会话或全局默认。
- 子代理详情提供「↻ 重试」，仅在服务端确认可续跑时显示；沿用原任务与上下文，不重新委派。重复点击被阻止，断线时不可操作。
- 本次不迁移旧任务过程；没有历史文件的旧任务不能恢复完整执行过程。

## 会话用量与账单

- 历史会话无需启动模型即可从只读 JSONL 恢复最近已报告用量。上下文优先使用运行态统计，缺失时估算当前上下文并标注「估算」；未配置窗口时仍显示 token 数，不把未知容量当成零。
- 模型设置提供输入、输出、缓存读取、缓存写入四项价格，单位 **USD / 百万 tokens**；0 合法，非负数校验，`cost.tiers` 仍可在高级 JSON 中配置。价格只影响后续请求，不追溯改算历史。
- 浏览器对话验收 `tests/conversation-ui.py` 可用 `PREVIEW_PORT` 指定隔离预览端口（默认 4321，与 `tests/conversation-preview.mjs` 保持一致）；会话 fixture 通过 hash 路由切换。
- 当前模型后追加会话累计估算费用，包含主代理与全部子代理。「会话账单」打开独立详情弹窗，按代理查看输入/输出/缓存读写明细，也可按模型归并查看；任务卡显示本任务费用，任务详情另有独立账单。总账由服务端在用量与任务状态边界更新，从各代理完整 entries 累计，包含历史分支、压缩/分支摘要与工具自报用量，不受历史下发范围影响；恢复时从各自 Pi JSONL 重算，子任务文件缺失则保留最后已知账单，无可恢复用量时提示缺失。未记录价格的条目明确标注，SDK 已记录的零费用不能据此判断是否真实免费。账单不是供应商实际扣款凭证。
- 模型选择、操作按钮和用量信息按可用宽度自动换行；窄屏展开后完整统计可见，收起状态的摘要也允许换行。

### 请求级审计与共享限流

设置 →「用量与限流」提供实时记账启用后的全局每日汇总、会话/代理分账及请求明细分页。费用是 SDK 按配置价格计算的估算，不是供应商扣款；reasoning 可能包含在 output 内，不能再加一次费用。记录保存在 `axiom.db` 的 `llm_requests`，删除会话不会级联删除审计记录，也不自动清理历史。原有会话账单继续从 JSONL 读取，与新审计的启用时间和覆盖范围不同。请求明细的 `waitMs` 表示并发闸门等待，`rpmWaitMs` 累计可计数的 HTTP 尝试在 RPM 闸门等待的时长；`backoffMs` 不把供应商 `Retry-After` 建议值误当实际退避。仅配置 RPM 且支持自定义 fetch 的路径能统计物理 HTTP 尝试；未配置 RPM、Google 客户端等路径不能据 `httpAttempts=0` 断言没有发起网络请求。

限额按供应商配置，例如 `{"oa173":{"rpm":30,"concurrency":3}}`（仅为格式示例，不代表账户额度）。0 或省略表示不限。只有纯 FIFO，无优先级；并发按完整逻辑请求，RPM 按 HTTP 尝试，内层重试也占 RPM。租约及排队最长默认 120 秒，超时放行意味着故障时不保证严格限额。Google 自定义 fetch 不受支持，WebSocket 绕过 fetch；这些传输只能限制并发，不能保证 RPM。未配置 RPM 不改供应商 fetch。

共享闸门按数据根（`AXIOM_HOME` 的规范路径）隔离：同根实例共用端点与限额，不按 dev/prod 拆额度；不同根使用不同端点及审计库。首个持有端点的 worker 提供闸门并保存审计。外部 pi 窗口可在仓库根目录运行 `pi -e ./extensions/usage-gate.ts` 显式加载扩展（先启动 Axiom，并在面板配置供应商限额）；它是独立进程，连接默认 `~/.axiom`，目标为开发实例（默认 `~/.axiom-dev`）或自定义数据根时，须在启动外部 pi 前设置与目标实例相同的 `AXIOM_HOME`（建议绝对路径，防止工作目录不同导致相对路径解析错位）。不自动修改 `~/.pi/agent` 的个人配置。外部扩展只审计配置了限额的供应商，新增供应商限额后需重载扩展。认证密钥位于 `~/.axiom-gate/token-<数据根哈希>`，首次创建经同目录临时文件原子发布，不可分享。升级端点方案时先退出旧版本实例；旧固定端点不会自动转接到新端点。连接中断后只读请求可重连重试一次，写入及租约申请不自动重放；共享闸门初始化失败时服务启动失败，不会退化为无共享限流；Unix 遗留 socket 不会被自动删除，需排查端点／密钥文件、确认没有活实例后再人工处理并重启。外部 pi 扩展连接失败时仍只提示本窗口暂不限流、不记录审计。审计不存提示词，但模型错误可能含敏感内容，分享前检查。

模块：`usage-store.js` 管记录和聚合，`request-gate.js` 管 FIFO/RPM/租约，`usage-stream.js` 透明转发 SDK 流，`gate-ipc.js`/`shared-gate.js` 管跨进程共享，`usage-backfill.js` 提供按启用时间分界、指纹去重的历史导入核心。面板「供应商限流配置」中可显式点击「导入现存历史用量」，在共享闸门所属实例执行；不会自动扫描或导入。历史仅能恢复仍存在的 JSONL 用量，不能恢复真实排队、HTTP 重试与失败请求，不能声称历史完整。

## 子代理执行治理

执行与验收规范见 [`docs/subagent-execution-governance.md`](docs/subagent-execution-governance.md)。会话历史、一次执行、一次工具调用分别管理：停止不删除会话，也不回滚已发生的改动。

- 子任务详情提供「停止并总结」「立即结束」及可选理由。UI、主代理 `cancel_task`、预算硬截止共用停止机制；先取消在飞工作，确认停止后才在同会话中禁工具总结，最终交付一次。立即结束跳过模型总结，但仍返回包含副作用提醒的系统报告。无法确认资源停止时如实标记，不并发启动总结或续接。
- 默认工作 600 秒，随后 180 秒收尾，硬截止后独立总结最多 60 秒；清理等待有界。外部计时器不依赖模型轮次，输出、在飞重试与运行中追加不延长截止。停止结果保留「部分成果」身份，不因总结成功标为任务完成。
- 终态 `append` 可在保留的子会话继续新问题，使用新执行标识；停止/总结期间追加排队，确认旧执行停止并交付后才续接。任务链累计耗时保留，主代理应利用已有结果、缩小缺口，不原样反复重派。
- bash/powershell 未填 `timeout` 时注入默认 **180 秒**；显式合法正数不覆盖，600 秒仅为建议。主代理显式 `-1` 表示不限工具时长，子代理禁止不限时；不向 read/write/edit 等工具补字段，不覆盖 mcpScript 自身超时。超时反馈提示来源及副作用风险，不自动重试。
- 工具记录显示实际耗时、有效时限与来源；子任务显示执行阶段、截止剩余时间和任务链累计时长。没有单工具取消按钮，不以无输出判死或以输出续期。

## 会话标题与子代理执行预算

- Axiom 自有提示词集中在 `src/prompts.js`，按主代理、子代理、压缩代理组织。主代理的 `MAIN_AGENT_PROMPT` 使用 Pi 风格的标题与指令列表，经 `appendSystemPromptOverride` 追加，不替换 Pi 默认系统提示词或用户已有追加内容；统一包含交流表达、只读调研委派、跨平台、Git/worktree 与 UI 输出协议，子代理不加载这些主代理规则。项目 `AGENTS.md` 保留分支交付、文档和提交规范，并明确授权验证通过后主动合并、推送 `master`；通用提示词本身不自动授权合并。注入时机仍由各模块控制；用户全局/项目规则及 Pi、插件提示词保持原加载链路。主代理正式答复应独立、完整、清晰易懂，并用独占行的 `<axiom_display>...</axiom_display>` 标记（不兼容旧标签）；标签仅用于界面展示，不是停止指令、任务完成或终止条件。需要执行的任务应继续调用工具，直到完成并验证，或遇到确实需要用户决策的阻塞，不得仅以确认需求、复述计划或承诺执行作为最终答复。交流格式按需使用段落、列表或表格；子代理和压缩代理不加载该格式，不强制 ASCII 图，也未新增 Mermaid 渲染。
- 主题按钮旁的 `</>`「原文对照」打开逐条消息阅读面板：宽屏左侧保留正常对话、右侧显示输入/模型输出的原始文字，1000px 及以下切换为原文阅读，点击「返回对话」恢复正常视图。点击左侧消息或「对照原文」定位右侧对应项并高亮；右侧可定位回对话、逐条复制。标签、Markdown 标记和换行原样保留，不显示消息外层 JSON；思考/工具参数单独折叠，图片仅标注附件类型而不铺开 base64。历史与实时消息使用同一视图，关闭后仍接收更新，切换会话时重建；原文保留压缩历史、内部通知及子代理记录（有明确标注，压缩后的精简条目标注「压缩节选」并提示展开摘要卡看完整原文），未进入模型消息历史的队列输入不会伪装成已接收消息。这里不是供应商 HTTP 报文或完整模型请求，分享原文前请检查隐私内容。
- 主会话 UI 从原始消息提取回答正文，标签不展示；同一用户轮已有明确回答时，先前进度和工具记录可折叠查看。流式开标签到达即可展示正文，代码围栏/行内代码不解析；标记通常独占行（缩进不超过 3 空格），也识别紧接过程说明行尾的 `<axiom_display>` 开标记；缩进 4 空格或 Tab 的同名行按代码原样保留。先拆正式答复，再分别过滤记忆标签，避免标题标签漏进完成卡正文。漏标、重复/嵌套标签回退原文，回退时先删掉正文里落单的裸标记行（丢协议不丢内容）；未闭合答复保留已输出内容。历史压缩逻辑和原始消息存储不变。用户输入按纯文本显示，保留换行、空白，长文本自动折行，不执行输入中的 HTML。
- 标题指令随正常模型请求附带，不额外调用模型；标题定案前的整轮每次请求（含工具后续轮）都持续注入，首轮直接委派漏报时后续轮还有机会补，自报成功即停注。首个合法标题不超过 10 个字，直接更新会话名，不覆盖手动改名。模型漏报或格式不合法不固化失败：下一条用户消息会继续索要，直到自报成功或手动命名；恢复会话时，旧版本固化的超长兑底标题（超过 10 字）按未定案处理自动重新索要。标题标签可跨行，正文换行折叠为空格；网页正文隐藏 `<title>` 标签，并继续过滤旧会话历史里的 `<axiom_summary>` / `<summary>` / `<progress>`（含落单的闭合标签与流式残片），不让它们漏进展示；代码围栏（``` 与 ~~~）、缩进代码块与行内代码内的同名标签是讨论内容，原样保留不剥离、不提取。`<title>` 只在正式答复首个非空非代码行内提取和剥离，正文中间讨论用的行内 `<title>` 不当自报标题；识别到正式答复块时，会话标题从答复块提取，不误用前置过程说明中的标题。同名的正经 HTML 不被吞：`<details><summary>` 折叠块标题保留，带属性的 `<progress value=… max=…>` 等元素保留。落单的开启标签只删标签本身，不再把后面的正文一起截掉；只有流式未完成时才裁掉尾部残片。
- 不做增量摘要：没有摘要提醒、摘要记录对话框，也没有子代理进度回报。上下文靠 Pi 原生 turn 上下文与本文档「上下文自动压缩」一节的后台压缩维持，主代理在收到子任务完成通知后主动 `read_result` 取回结果。完成通知分双通道：主代理运行中子任务交出结果时，经 SDK 自定义消息（task-notification）注入 steering 队列，在轮次边界（安全点）送达，不打断在飞工具，当前运行自动延长到通知消化完；空闲时则由通知直接唤醒会话。送达确认以消息历史为准：通知未进历史（如被 clear_queue 误清）时保持未通知并自动补投，文本幂等。通知以单行素文本展示（强调色小圆点 + 「任务通知: 子任务完成」，子代理转投补 「· 子代理」），左边缘与普通会话消息对齐、不占多行；taskId/resultId 等原文不进转写，悬停看 `title` 或在「原文对照」面板查看。旧会话的前缀文本通知同样识别。刷新/重启后通知随历史恢复。
- `delegate` 每次调用必须带批内共享的 `context` 字段：交代委派原因、当前进展、已知信息与共同约束，子代理不继承主会话历史。任务专属的问题、范围、必要信息和交付要求放入 `tasks[].task`，关键结论需要验证时注明证据要求；每个任务只做一件几轮内可独立验证的事。所有信息收集（代码/文档/外部资料/运行行为）一律走 delegate：子代理结论必须附可验证出处（代码 path+行号、文档 file+节、外链 link+引文、运行命令+关键输出），主代理不亲自展开调研，只对关键结论抽查出处。子任务运行期间主代理继续不依赖结果的工作；无可做时简短说明状态后收尾等通知自动唤醒，不用 sleep 或轮询空转。
- 子代理同时有软轮次提示和独立时间预算：默认 20 轮，最后 2 轮为轮次收尾窗口。累计 turn 达到 `maxTurns - wrapUpWindow` 后每轮追加 `[轮次预算] …`，要求交付已确认事实、未查清部分和下一步拆分。轮次提示本身不 abort；时间硬截止则走上述统一停止总结。轮次仅在子代理进程内计数，时间截止与累计耗时落盘；主代理没有子任务预算。
- 在「设置 → 默认新会话设置 → 子代理执行预算」配置轮次上限（3-200）、轮次收尾窗口（1-10）、工作秒数（60-7200）、收尾秒数（30-3600）及总结秒数（10-600），默认 20/2 轮、600/180/60 秒，保存到 SQLite；新建会话生效，已有会话保持原预算。预算随会话创建定死并写入会话 selection：重开旧会话仍用它创建时的预算，改全局值只影响此后新建的会话。库中记录含未知键（旧版本/未来字段）时只取已知键校验，不因此丢掉用户设过的合法值。非法值在建会话时直接报错，早于任何模型请求。
- 标题与任务状态按变更增量落盘：记忆钩子用 `save(change)` 描述本轮变更（标题、压缩/重试事件、单任务、事件删除），无变更不落盘，不再每个事件全会话重写；任务事件附 `saved` 完整单条快照（含 parentContext/resultId/notified/runtime/createdAt/updatedAt）供单任务保存，广播前剥离，前端只收安全视图。运行开始那一笔状态落盘顺带写入当前标题与 `updatedAt`：这两个值在运行开始前就已确定（首条输入推导的临时标题，图片输入剥掉 `[imageN]` 占位符后取前 60 字、剥完为空回退「[图片]」；本轮开始时间），长任务跑到一半进程被杀时不退回「新会话」和旧时间，侧栏排序仍按真实活动时间。模型自报的标题另有一笔即时落盘，与 `titleRequested`（已定案标记，只在真正拿到标题后才为真）同事务，不必等整轮结束。

## 本地开发与安装版分离

- 源码目录运行 `npm run dev`：默认 `http://localhost:4320`，右上角显示 `DEV`，点击连接状态可进入「设置 → 服务与更新」，界面不展示源码位置；会话和日志放在 `~/.axiom-dev`，不影响日常数据。
- npm 全局安装版运行 `axiom`：默认 `http://localhost:4319`，不显示 DEV，继续使用 `~/.axiom`。
- 开发入口默认以当前源码为工作空间，不读取 `.env.local` 中的旧工作空间值；可在启动前显式设置 `AXIOM_PORT`、`AXIOM_CWD`、`AXIOM_HOME` 覆盖默认值。`AXIOM_HOME` 给相对路径时会先按启动时的当前目录解析成绝对路径，再传给守护进程与 worker（worker 以项目根为工作目录启动，不解析就会各自算出不同的数据目录、打开两个库）。
- 开发服务（`npm run dev`）下修改前端静态文件无需重启，刷新页面即可；修改后端 `src/` 仍需重启服务载入。开发测试通过后推送 master，Mac 安装版通过「检查更新」安装最新 master 并重启；不要直接修改全局安装目录，也不要把开发服务注册成日常自启动。

## 启动

需要 Node.js 22.13+（22.x）或 24+；安装和服务入口在加载内置 SQLite 前检查版本，旧版本提示升级，无需额外安装 SQLite 或修改全局安装命令。安装程序检查 Pi CLI，未安装时自动全局安装最新版 `@earendil-works/pi-coding-agent@latest`，已有 Pi 不强制升级。无需预先配置模型或凭据：没有可用模型时仍启动网页，并引导进入「设置 → 模型与供应商」；添加供应商、模型及 API Key 后即可新建对话，无需重启。订阅登录可直接在「设置 → 模型与供应商」内完成（授权链接/设备码，凭据仅保存到 Axiom SQLite），无需回到终端 Pi `/login`。首次使用时，主 Agent 和子 Agent 的 Skills、插件、MCP 默认选择全部为空，无需安装这些可选资源；需要时在默认新会话配置中手动启用。主 Agent 不装配导航类技能（如 codebase-map）：探索与导航一律经 delegate 交给子代理，系统提示里不出现这些技能的可用性；选择集本身不变，子代理 inherit 主代理选择集时仍装配全部选中技能。已有保存配置和 Pi 配置不被清空，提示词模板及目录上下文维持原有规则；基础编码工具为 read/bash/edit/write，主 Agent 额外获得 delegate/read_result/append/cancel_task 四个协作工具。可选能力清单来自终端持久配置，未选择 MCP 时不加载适配器入口，不继承另一终端进程的临时参数、会话状态或已执行的模式命令。纯 TUI 组件和终端快捷键不适用于网页；当前无插件交互 UI 桥，需要审批的 MCP 调用按适配器规则拒绝，不自动批准。

### 一键安装（macOS / Windows）

本仓库即 npm 包，两种路线任选；缺 Node 时安装脚本会经 Homebrew / winget 自动安装，随后装依赖、注册登录自启、在后台启动服务，并在就绪后打开浏览器。交互终端逐项确认（默认注册登录自启、打开浏览器）；脚本调用可用 `--no-autostart` / `--no-browser` 关闭。自定义端口写项目根 `.env.local`（`AXIOM_PORT=…`），安装、自启、服务读取同一来源。

注意 `npm install -g` 只装代码，不会启动任何进程、也不会注册自启，装完必须再运行 `axiom-setup`。若跳过它直接运行 `axiom`，首次会在交互终端补问一次注册登录自启与是否打开页面（问过即记下，删掉 `~/.axiom` 才会再问）。

npm 路线（推荐）：

```sh
npm install -g github:cosyeezz/axiom
axiom-setup
```

git 路线（macOS 终端）：

```sh
git clone --depth 1 git@github.com:cosyeezz/axiom.git ~/axiom; sh ~/axiom/install.sh
```

Windows（PowerShell）：

```powershell
git clone --depth 1 git@github.com:cosyeezz/axiom.git "$env:USERPROFILE\axiom"; & "$env:USERPROFILE\axiom\install.ps1"
```

Windows 也可直接双击 `install.cmd`。更新版本：网页「设置 → 服务与更新 → 检查更新」（按 GitHub master 提交比对，先检查、确认目标提交后才安装；DEV 不提供安装版更新），或重跑安装命令。卸载自启：`npm run autostart:disable`。

命令行帮助：`axiom help`（也支持 `axiom --help`、`axiom -h`），列出后台启动、前台运行、停止、卸载命令及数据保留说明；查看帮助不会启动服务。

停止后台服务：终端运行 `axiom stop`（默认 4319；`AXIOM_PORT` 可指定其他端口）。有运行任务时拒绝停止；空闲时保存会话，退出服务及守护进程，命令等待退出确认，超时不强杀。只停止当前运行实例，不取消登录自启。新版 worker 启动失败并处于重试等待时，可通过守护进程的本地通道停止；worker 仍活跃时不绕过任务检查。旧版本没有停止接口，需要首次完整重启升级后才可使用。

服务停止后重新拉起（守护进程 + 服务进程）：终端运行 `axiom`，**默认在后台启动**并立即返回——进程脱离终端，关闭终端窗口或断开 SSH 都不会停服；已在运行时不重复启动，只提示访问地址与日志路径。首次在交互终端运行会补问一次登录自启与打开页面，之后不再询问。要在前台运行（日志直接打在终端、`Ctrl+C` 停止，排查问题用）加 `--foreground`：`axiom --foreground`。

首次没有可用模型时，网页保持连接并打开「设置 → 模型与供应商」，不会反复新建失败会话。保存供应商、模型及凭据后，点击「＋ 新会话」开始；无需重启。已有会话引用和页面内草稿会保留。

### 卸载 npm 安装版

统一卸载（Windows / macOS / Linux）：

```sh
axiom uninstall
```

命令核对当前 npm 全局安装位置，安全停止服务、取消自启，再移除当前包 `@cosyeezz/axiom`。忙碌、停止超时或取消自启失败均中止卸载；服务未运行可直接继续。保留 `~/.axiom` 和 `~/.pi`，不卸载共享 Pi。

旧版不支持该命令时，使用以下手动步骤（任一步失败应停止，不要继续删除包）。包名以本机实际安装为准：打开 `npm root -g` 下的包目录，读取其 `package.json` 的 `name` 作为下文 `<包名>`；它不是安装来源 `github:cosyeezz/axiom`。

Windows PowerShell：

```powershell
$npmRoot = npm root -g
node "$npmRoot/<包名>/scripts/autostart.mjs" disable
axiom stop
npm uninstall -g <包名>
```

macOS / Linux：

```sh
node "$(npm root -g)/<包名>/scripts/autostart.mjs" disable
axiom stop
npm uninstall -g <包名>
```

若提示任务运行中，先停止任务再重试；服务本来就未运行时可跳过停止。取消自启须在卸载包之前执行。卸载保留 `~/.axiom` 会话数据及 `~/.pi` 配置，不卸载共用的 Pi；不需要的数据请确认备份后自行删除。

### 从旧包名迁移（一次性）

本项目独立发布，npm 包更名为 `@cosyeezz/axiom`，macOS 登录自启 Label 同步改为 `com.cosyeezz.axiom`。更名不支持原地自动迁移：旧版本不要用「检查更新」过渡，它会按新包名另装一份，旧包与旧自启仍在，容易同时运行两个服务。手动迁移一次：

1. 结束运行任务后安全停止旧服务：`axiom stop`（更早版本无停止接口时，退出旧守护进程并确认 4319 端口空闲）。
2. 取消旧自启：`node "$(npm root -g)/<旧包名>/scripts/autostart.mjs" disable`（PowerShell 用 `$npmRoot` 写法同上节）。`<旧包名>` 从旧安装目录 `package.json` 的 `name` 读取，不要凭记忆输入；macOS 上该步骤同时移除旧 Label 的 LaunchAgent。
3. 卸载旧包：`npm uninstall -g <旧包名>`。
4. 安装新包并初始化：`npm install -g github:cosyeezz/axiom`，再运行 `axiom-setup`（可重新注册登录自启，macOS Label 为 `com.cosyeezz.axiom`）。

`~/.axiom` 会话数据与 `~/.pi` 配置跨更名保留，无需搬移。迁移期间及之后都不要同时运行新旧两个服务：两者默认占用同一端口并读写同一数据目录，同时启动会端口冲突或互相干扰；先确认旧服务已完全停止，再启动新服务。

Axiom（npm 安装、独立更新） <-- http(s)://<可配置地址>/ -- Pake 桌面窗口（内置连接入口页）

桌面壳打开后先显示内置连接入口页：填入本机或远程地址点「连接」即可进入（上次地址可达时自动直达）；也可从网页右上角连接状态点击进入「连接」面板切换地址。壳不内置 Node.js、Pi、网页副本或后端，不启动/停止服务。Axiom 更新后刷新窗口即可，通常无需重打壳；关闭窗口不停止后台任务。壳的版本在 `desktop/pake.json` 独立维护，不跟随 npm 包版本。

使用：先按上文 `npm install -g github:cosyeezz/axiom` 安装本体，再运行 `axiom-setup --no-browser`（可注册登录自启），最后安装并打开桌面壳。本机连接时先运行 `axiom`，再在入口页连接（默认 `127.0.0.1:4319`）；连接远程时在该机器上以 `AXIOM_HOST` 绑定对外地址并放行端口。桌面窗口与浏览器的 localStorage 不共享，但会话仍由所连接的服务保存。

构建产物由 GitHub Actions「**Build Axiom Desktop**」生成（手动触发，或推送 `desktop/**` 变更自动构建），产物保存 30 天：

- `Axiom-Windows-x64`：`Axiom.msi`，Windows x64，运行需要 WebView2。
- `Axiom-macOS-universal`：`Axiom.dmg`，同时支持 Apple Silicon 与 Intel，打开后拖入 Applications；CI 含 DMG 完整性与双架构校验。

旧版下载：[Desktop v0.1.0](https://github.com/cosyeezz/axiom/releases/tag/desktop-v0.1.0)（固定地址 127.0.0.1:4319 的历史版本，不含连接入口页）。

目前产物未配置代码签名/公证，系统可能提示未知发布者或拦截；仅安装可信来源的产物，不建议关闭系统安全机制。macOS 若拦截可信下载，可在「系统设置 → 隐私与安全性」批准打开。

本机构建命令（可选，通常直接用 CI 产物）：

```sh

```

macOS 同时支持两种芯片时，先执行 `rustup target add aarch64-apple-darwin x86_64-apple-darwin`，然后 `pake --config desktop/pake.json --targets universal`；Windows x64 可显式加 `--targets x64`。需要 Node.js 22、Rust ≥1.85；macOS 需要 Xcode Command Line Tools，Windows 需要 Visual Studio Build Tools 的 C++ 桌面开发组件。npm 安装的是打包工具，不是免编译的桌面客户端。详见 [Pake CLI 文档](https://github.com/tw93/Pake/blob/main/docs/cli-usage.md)。

配置复用 `public/favicon.svg`，保留系统标题栏，允许新窗口与拖放；`forceInternalNavigation` 保证连接跳转留在壳内；无需启动 Axiom 就能打包。壳默认入口是本地连接页而非固定端口，不会误连 `npm run dev` 的 `4320`；自定义地址在入口页/连接面板配置，不需要重新打包。不要将本地 Agent 服务暴露到公网。Pake 只作为构建工具安装，不加入 Axiom 运行依赖。

### 维护：发布更新

本仓库独立发布，公开仓库就是 `cosyeezz/axiom`，没有上游镜像或同步步骤。发布流程：任务完成后，在独立功能 worktree 验证（构建、测试、复核）→ 提交 → 拉取最新 `master` 并合并进功能分支 → push 功能分支 → 合并回 `master` 并推送 → 清理附加 worktree（保留主仓库）。批量清理前核对未提交与未跟踪内容，先备份，再确认全部更新已集成；不得用旧工作区草稿覆盖主分支的新版本。已迁移至新包名的安装实例，在推送后可通过「检查更新」发现并自动升级（按提交比对，内容变更即发现）。发布时顺手把 `package.json` 的 `version` 升一档——页面服务设置会显示当前版本，便于确认更新生效（检测本身不依赖它）：

```sh
git push origin master
```

### 自动启动与服务控制

跨平台当前用户登录后自动启动（无需管理员；默认不是登录前的系统服务）：

| 平台 | 系统原生方式 |
|---|---|
| Windows | 当前用户启动文件夹，隐藏窗口 |
| macOS | `~/Library/LaunchAgents`，LaunchAgent |
| Linux | `~/.config/systemd/user`，systemd 用户服务（需可用的用户服务管理器） |

以下命令仅注册/取消注册，不启动或停止当前进程，下次登录生效。Linux 如需未登录即运行，可由用户另行配置 `loginctl enable-linger`；脚本不会自行提升权限。

```powershell
npm run autostart:enable
# 取消自动启动
npm run autostart:disable
```

右上角显示连接状态、DEV 和版本，点击状态进入「设置 → 服务与更新」，不展示源码位置。维护操作使用统一暗色确认弹窗，默认聚焦取消、支持 Esc；仅确认后发送请求。面板提供：

| 操作 | 行为 |
|---|---|
| 重启服务 | 保存会话、停止服务并重新启动，不安装依赖 |
| 修复依赖并重启 | 在暂存目录安装锁定依赖并验证 SDK → 保存并停止 → 备份、切换依赖 → 按需构建 → 启动并核验 |
| 检查更新 / 安装更新 | 先检查 GitHub master 完整 SHA，用户确认后安装固定提交；暂存新包与私有依赖、校验提交和 SDK，再停止切换，新实例就绪后才记录提交和清理备份；DEV 隐藏更新 |

检查更新由用户点击触发，不是后台定时更新；提交必须推送到公开仓库 `cosyeezz/axiom` 的 `master`。更新固定本次检查得到的 SHA，安装期间若又有新提交，下次检查会继续发现。安装前后均通过 `npm root -g` 核对目标包与当前服务的真实目录；不一致则报错，不写提交记录，安装前发现不一致时不会执行安装。网络/安装失败不记录新提交，安装失败会尝试重启服务并向页面报告错误。首次升级此更新机制后，需要完整重启守护进程一次（而非仅网页快速重启），使新的安装逻辑生效。

Axiom 使用原生 JavaScript，目前没有编译脚本，因此重建时不会假装执行编译。安装可能访问网络并执行依赖安装脚本；失败信息会记录到日志并反馈到菜单。准备失败不触碰在用依赖；发现残留 `.node_modules-backup` 时在停止服务前拒绝重建，保留运行中的服务和备份，请先检查备份来源、不要直接删除或覆盖。切换前保留旧依赖，构建或启动失败恢复备份；维护失败后的兜底实例若也退出，会恢复有上限的崩溃重试，不再静默离线；构建脚本自身修改的产物不自动回滚。启动核验默认 60 秒，超时后先确认新进程优雅退出再回滚，不强杀或并行拉起第二个进程。重启不拉取 Git 更新、不改变锁文件，也不删除会话历史。运行中的会话会阻止重启，请先停止任务；页面保留草稿并自动重连。页面与服务断开且业务进程退出时，「设置 → 服务与更新」提供「尝试恢复服务」按钮，经守护进程独立维护通道拉起；自动重试与限流由守护进程负责，维护端点也不可达时页面提示终端运行 `npm start`。

`npm start` 使用独立守护进程。直接 `node src/main.js` 仍可使用聊天，但不能从网页重启。首次从旧的直接启动迁移时，先停止旧进程，避免端口冲突。自动启动和安装输出日志位于 `~/.axiom/service.log`（POSIX 下权限收紧至 `600`，与数据库同口径；写入前按白名单脱敏——维护 token、安装目录、用户目录都换成占位符，凭证与本机路径绝不明文落盘，方便直接贴到 issue）。维护结果按安装根与端口隔离保存在数据目录 `axiom.db`（旧版 `service-state-<标识>.json` 只读导入一次并保留），刷新不丢；落库失败只在当前运行内提示，重启不显示假错误；阶段时间线全入口有界保存。面板读取真实阶段，不用虚假百分比，请求接受或连接恢复不等于操作成功。连续崩溃默认最多自动重试 5 次，之后等待手动恢复。业务端口离线时新开/刷新页面仍可能无法加载，已打开页面可查询独立维护通道。设计依据见 [服务维护说明](docs/service-maintenance.md)。守护进程自动读取项目的 `.env.local`（不提交），并保留 Node 所在目录到 PATH。移动项目或升级 Node 路径后需重新执行注册命令。

服务默认仅监听 `127.0.0.1`。健康检查 `GET /health`，WebSocket `/ws`。本机无需令牌，服务校验 Host 和浏览器 Origin，拒绝其他网站跨站连接。本机进程可直接访问。工作目录不是沙箱，Agent 可以执行命令和修改文件；不要公开部署到网络。

### Tailscale 远程控制

设置左侧「默认新会话设置」下方新增「远程控制」。电脑和手机都安装 [Tailscale 官方客户端](https://tailscale.com/download)，以同一登录方式和账号登录，并保持连接。面板自动识别本机 Tailscale 登录名；未安装时提供下载入口，未登录时点击「登录 Tailscale」获取本机设备的官方授权链接，完成授权后刷新状态。登录不会自动开启远程访问；确认后手动开启并保存，在手机浏览器打开面板显示的地址。Wi-Fi 与手机流量使用同一个入口，不需要路由器端口映射。

```text
手机 Tailscale → 本机 Tailscale 地址 → 验证登录账号 → Axiom
电脑本机      → 127.0.0.1          → 原有本机访问
```

- 默认关闭；远程入口只绑定本机 Tailscale 地址，不开放 `0.0.0.0` 或普通局域网监听。
- 服务通过本机 `tailscale whois` 验证连接来源的登录名，兼容普通设备省略 `Tags` 字段的官方输出，拒绝其他用户和 tag 设备，不相信浏览器传入的邮箱或身份请求头。同一 tailnet 不代表同一用户；登录名也可能是 `name@github` 这样的标识。
- 远程控制配置只允许在电脑本机修改。关闭或更改许可会立即断开已有远程连接，不停止后台会话任务；Tailscale 身份变化使用短缓存并周期复核，不代表即时同步 Tailscale 控制台的撤权操作。
- 配置保存在数据目录 `axiom.db`（SQLite 权威）：旧版 `remote.json` 只读保留，首次启动导入后不再读写；历史双重编码值首次读取自动迁移，损坏值按禁用处理（fail closed）。远程与本机使用相同端口（默认 4319，开发模式 4320）。特殊安装位置可通过 `AXIOM_TAILSCALE_BIN` 指定 CLI。登录失败时可在官方客户端完成授权，再回到面板刷新。
- 不保存 Tailscale 密码或登录凭据。不使用 Funnel，也不需要配置 Serve；建议同时用 Tailscale 访问规则限制 Axiom 端口。
- 地址虽然是 HTTP，但设备间流量由 Tailscale 加密。浏览器将其视为非安全上下文，没有 Clipboard API；页面所有复制入口统一走 `public/clipboard.js`，剪贴板 API 缺失或被拒绝都自动回退 `execCommand`，远程也能直接复制，双路径失败才提示改用系统复制菜单。
- 电脑需要保持开机、联网并运行 Axiom。Tailscale 未安装、未登录或无法验证身份时，不允许远程访问。

回归检查：`npm test`；可选浏览器布局验收 `python tests/remote-ui.py`（需 Playwright + Chromium，覆盖 1440/390/320px，不调用真实 Tailscale）。

## 会话已完成

- 当前窗口显示所选会话的工作空间。通过侧栏切换会话或工作空间，页面内草稿分别保留；顶部不再显示应用内会话标签栏，也不提供「在新标签页打开」菜单项。
- 侧栏每个工作空间内分「置顶 / 进行中 / 已完成」三组，均为可折叠小节（`<details>`），标题右侧显示会话数徽章；没有会话的组不渲染。置顶与进行中默认展开、已完成默认折叠；手动折叠/展开按工作空间记在 `localStorage` 的 `axiom.sessionGroups`，重绘与刷新后保留。已完成展开时限高 45vh 并在组内滚动，更长列表交给会话区整体滚动。顺序固定为：置顶最前，其余与旧版一致——运行中置顶，其次是跑完但还没打开过的，最后是看过的；每段内部按最后活动时间（`updatedAt`）倒序、以相对日期逐天分隔（今天/昨天/前天/N 天前，跨月/跨年才显示具体日期，悬停分线可见精确日期），不支持拖动排序。运行中显示绿色圆点；跑完且用户之后没打开过的显示主题色圆点，打开会话即熄灭（打开时刻记在 `localStorage` 的 `axiom.sessionSeen`，只在打开过、之后又跑完时才算待查看，历史会话不会被一次性标成未读）。当前正在看的会话跑完时立即记为已读，切走后不会回头标成待查看。主代理执行中或任一子代理仍在启动/运行时，会话标题前持续显示绿色圆点，即使已标记完成也优先显示在进行中；主代理与全部子代理停止运行后才熄灭并回到相应分组。

- 隐藏只整理列表，不删除记录、不停止任务，也不切换当前对话。状态保存在当前浏览器的 localStorage，刷新保留，不跨浏览器同步；清除网站数据会重置。

## 模型收藏与供应商管理

- 输入区、默认新会话设置（全局默认与目录配置）、主/子代理和自动压缩的模型选择共用一份目录与收藏。供应商、模型、思考程度分别收藏；模型按 `provider/id` 区分，避免同名模型串用。收藏仅调整下拉顺序，不改变当前选择，不自动切换模型。
- 每个选项右侧预留五角星位置：鼠标移入或键盘聚焦显示黄色星标，已收藏常显；触屏直接显示按钮。点击星标不会选中条目或关闭菜单；再次点击取消。收藏项稳定置顶，其余保持原顺序。支持方向键、Home/End、输入查找、Enter 选择、Esc 关闭和键盘访问星标。
- 模型配置采用左侧供应商搜索导航、右侧详情与折叠高级字段，窄屏自动单列；参考 [Cherry Studio](https://github.com/CherryHQ/cherry-studio/pull/16858) 的分栏管理与 [OpenCode](https://opencode.ai/docs/models/) 的模型能力组织方式，不引入额外 UI 依赖。
- 供应商与模型分两级配置：详情页顶部有「供应商 / 模型」两个分区，连接信息与模型列表不同屏。新建供应商时模型分区先禁用（提示先保存连接），保存成功后自动选中该供应商并跳到模型分区，模板自带的示例模型作为待保存行跟着迁过去。分区选择按条目记住，重渲或回读不会把你扔回连接页。
- 供应商与模型都可复制：供应商详情的「复制为新供应商」拿当前连接开一份新草稿（id 自动加 `-copy` 避让，模型行一并克隆为待写入）；模型行的复制图标拿表单当前值（含未保存修改）新建一条待保存模型。API Key 与已存请求头值不复制，面板内明确提示重填；请求头只有名称没有值时保存直接报错，不会默默写个空值上去。复制不带内置目录覆盖（那是绑旧 id 的），也不会动原条目。
- 保存供应商连接后，可在模型分区「拉取模型列表」并搜索、勾选，再点击「添加选中的模型」；拉取本身只读，不会把全部结果自动加入配置。支持 OpenAI 兼容、Anthropic、Google 模型接口；已添加项禁选，部分添加失败可重试，未返回的模型能力不猜测。
- 思考收藏以 `provider/model:程度` 隔离，允许模型 ID 含冒号；星标只改变排序，不改变当前选择。浏览器回归：先运行 `node tests/model-selection-preview.mjs`，再运行 `python tests/model-selection-ui.py` 和 `python tests/model-settings-ui.py`（需 Python Playwright 与 Chromium，预览不使用真实凭据）。
- 「设置 → 模型与供应商」统一管理模型定义与供应商连接：自定义/覆盖供应商存 SQLite；内置/扩展供应商的模型（含未登录的）在同一页展示，可直接登录/登出（OAuth、API Key，凭据仅保存到 Axiom）、编辑名称/上下文/最大输出/推理/图片能力，并勾选思考等级（七级 off/minimal/low/medium/high/xhigh/max，写入 thinkingLevelMap）。模型管理页是定义面，七个等级全部列出；未勾「支持推理」时非 off 等级锁死，避免勾了也不生效。勾选按差异写入而不是白名单：取消写 `null`（显式禁用，浅合并下删键清不掉已落盘的条目），重新勾上回到默认（整个映射可能被清空），xhigh/max 属于 opt-in、勾上才写字面值，已落盘的自定义 API 入参在取消→勾回后原样恢复。修正了旧版把勾选当白名单写导致的“保存后等级回读不一致”。行内「有效等级」摘要实时反映当前勾选真正生效的结果。内置模型保存走逐字段覆盖（`models.model.override`），只写修改的字段，未改的能力保持内置定义，不再需要同名整条覆盖。内置模型的移除入口是隐藏，不是删除。已有供应商选择 API 协议「不设置」后，保存、刷新仍保持未设置，不自动补成 OpenAI；新建供应商仍按所选模板预填协议。该页不改变「设置 → 默认新会话设置」的模型配置位置与行为（仍在 SQLite 默认配置中，主/子代理分开设置）。旧 Pi models.json 仅导入，保存后同步 SDK 使用的 models.compat.json，不修改旧 Pi 文件。
- 供应商重命名与删除在左侧导航行内完成：悬停（或键盘聚焦）显示铅笔与删除图标，删除图标悬停变红，两者都用原生弹窗二次确认，可 Esc 取消。重命名由后端一次写盘完成（`models.provider.rename`），模型、内置覆盖与未保存草稿随新 id 迁移；重名或非法 id 在弹窗内提示，不会发出请求。
- 内置/扩展供应商与模型可从 Axiom 的选取入口隐藏：目录页与模型行上有隐藏图标，二次确认后条目从模型选择器与本页目录消失，集中在左侧「已隐藏」里可随时恢复。隐藏只写 SQLite 清单（`models.hidden.set`），不改 Pi 运行时目录，既有会话不受影响；存在同名自定义覆盖时，供应商级隐藏自动让位给覆盖条目。
- 配置保存保留未编辑的高级字段和已有凭据；密钥不回传明文，编辑时留空表示保持。支持 `$ENV_VAR` 环境变量引用，不允许从网页添加执行命令型凭据。删除只移除自定义配置，不会删除 Pi 内置模型或登录凭据。保存前检测文件版本冲突，避免覆盖外部修改。
- 保存后更新模型目录；新建会话或重新选择模型使用新配置。已经运行的会话不会强制换掉已绑定模型，避免中断当前请求。
- 设计依据：[Linear 收藏](https://linear.app/docs/favorites)的星标切换与置顶入口；[WAI-ARIA Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)明确选项不适合嵌入额外按钮，因此选择与收藏采用独立控件。沿用现有近黑表面、细边框、`#5e6ad2` 焦点色，黄色只用于收藏状态，不增加装饰色。

## 新会话与能力选择

- 「新会话」使用「设置 → 默认新会话设置」中当前目录的配置；该目录没有单独配置时回落全局默认。首次自动创建、打开空工作空间、删除最后一个会话后的补建同样按当前目录取值。初始主/子代理的 Skills、MCP、插件均不选中；已保存的明确选择（包括全部能力）保持不变。
- 默认配置可分别设置主/子代理供应商、模型，以及 Skills、MCP 服务、插件的全部或自定义选择（可全部取消）。保存仅影响之后创建的普通会话，不修改当前/已有会话的模型与能力选择，也不启动代理；唯一例外是压缩配置，按会话所属目录的最新值动态应用到已加载会话。选择即通过 WebSocket 自动保存，写入数据目录的 `axiom.db`（SQLite 权威，旧 `defaults.json` 仅首次启动一次性迁移），服务重启保留，不修改 Pi 的 settings/MCP 文件。默认能力预览实时跟随选择，状态提示区区分保存中、成功和失败；失败不覆盖旧配置。
- 设置页顶部有「全局默认 / 目录配置」下拉：全局默认是所有工作空间的兜底，目录配置按真实工作空间目录分别保存模型、思考等级、Skills/MCP/插件能力、后台压缩与重试词表。选「目录配置」可从下拉里挑已配置目录，或点「选择目录」新加一个工作空间目录再编辑；切下拉只换编辑对象，不切换或新建当前会话，也不改变当前页签的工作空间。未单独配置的目录沿用全局默认。删除目录配置只删这份配置，不删工作空间目录、也不删该目录下的已有会话，之后该目录重新回落全局默认。配置整包保存在数据目录 `axiom.db` 的 `store` 表、`defaults` 命名空间：`global` 一行，各 `workspace/<真实目录>` 各一行（含完整技能选择），刷新、重启后保留。保存后立即更新内存；能力清单在读取时按目录重新发现，无需为修改默认选择而重启服务。旧具名预设直接丢弃、不迁移。
- 默认主模型可选固定模型，或「默认主代理模型」（沿用该目录最近成功调整的主模型，尚未调整时用启动模型；各目录分别记忆、互不串用）；主/子代理均可设置思考等级，选项只列出当前选中模型真正支持的有效等级（换模型后列表跟着换；尚未选定模型时回落当前会话的等级集合），输入区、默认新会话设置与自动压缩均同一套取值，不再罗列 max 等模型并不支持的等级；主代理留空沿用默认值，子代理留空跟随主代理，运行时按模型支持调整。子代理的模型与能力可分别选择「跟随主代理」，能力跟随实际主代理选择而非全部能力。能力清单按当前工作空间读取，目录配置与目录绑定、不保存目录信任；换目录时按该目录的配置（未配置回落全局默认），只加载当前目录仍可用的已选能力；缺失项写入服务日志，不会扩大为全部能力，也不会改写全局默认配置。编辑默认配置时只提供当前目录可用项，不把其他项目或已移除的资源补成复选框；显式提交未知能力仍拒绝。
- 能力清单来自 Pi 原生包解析与 Skill 发现；仅列出本机已安装且已启用的资源，不安装新包。MCP 复用已安装 `pi-mcp-adapter` 的配置合并及 `createMcpAdapter({config})`，适配器本身不再重复显示为插件。每个代理拥有独立服务清单，未选服务不会通过该适配器暴露，stdio 服务默认使用会话工作目录。
- 选择工作空间即表示信任该目录：Windows/macOS/Linux 均默认加载项目 Skills、插件和 MCP，不需要另行勾选，也不依赖 Pi 全局信任策略。请只选择可信目录，项目插件和 MCP 可在本机执行。Axiom 不写入全局 trust/settings/MCP 文件；设置采用内存快照，保留全局和项目相对路径语义。旧协议中的 `trustProject` 字段保留兼容，但不再改变工作空间信任。
- Skills、MCP、插件能力选择与自动重试在创建时装配；尚未发送消息的空会话可在「当前会话配置」中修改，保存成功后保留会话 ID 与订阅，失败保留原配置。首次执行后不再允许重新装配，重启后也不会重新解锁；模型支持执行中调整，下一次模型请求生效。首次普通会话的子代理默认不启用可选能力、模型跟随主代理；普通会话使用保存的默认配置，自定义会话可分别选择。状态通过会话文件恢复；主代理不自动续跑，未完成子代理按持久化状态自动恢复。
- 插件加载失败会阻止创建并显示错误；启动钩子错误保留为加载提示。插件的启动和关闭事件均执行。插件命令可以没有模型回答，不会再误报失败。所有扩展仍有本机执行权限，取消勾选不是文件系统沙箱；选中的插件也可能贡献自己的额外工具。

协议新增 `capabilities.list({cwd?,trustProject?})`，返回不含凭据的 Skills/插件/MCP 目录与信任状态。`session.create` 新增 `model`、`thinking`、`subagentModel`、`capabilities`、`subagentCapabilities`、`trustProject`。能力值为 `null`（全部）或 `{skills:[id],mcp:[id],plugins:[id]}`，空数组表示不加载该类。主/子选择都在创建前校验，显式提交未知 ID 拒绝；继承默认配置与恢复历史时仅取已选 ID 和当前可用清单的交集（空集合仍为不加载），不按同名技能猜测替换路径。`config.activeTools` 返回实际工具名用于验证。

`session.defaults.get` 返回 `{model,subagentModel,thinking,subagentThinking,capabilities,subagentCapabilities}`；`session.defaults.configure` 接收上述可选字段及 `cwd?`（读取/写入对应目录的配置，省略时读写全局默认；同时用于校验该目录里的可用能力），省略字段保留原值，保存失败保留全部旧值。主模型 `null` 使用该目录的最近主模型/启动模型，子模型 `null` 跟随主代理；`thinking:null` 沿用该目录的最近/启动思考等级，`subagentThinking:null` 跟随主代理；`subagentCapabilities:"inherit"` 跟随主代理能力，`null` 仍表示全部能力；默认配置不接收 `trustProject`。`session.create` 的显式字段优先于默认值，`useDefaults:false` 完全绕过这份默认配置，网页自定义入口使用该标记；最近主模型和思考程度按目录各自继承。

## 导入 pi 会话

侧栏「导入 pi 会话…」用共享文件选择器挑选 `.jsonl`，默认从 pi 的会话目录（`service.status` 的 `importDir`）开始浏览；确认后立即成为当前对话，可继续提问。首行缺少 `session` 头或 `cwd` 无效时报错，不创建会话。

```text
pi 会话 .jsonl（~/.pi/agent/sessions/...）
        │ 选中
        ▼
复制到 ~/.axiom/workspaces/<工作空间>/<会话 ID>.jsonl ── 读回历史 ── 成为当前会话
        │
        └─ 原文件保持不动：继续对话、重命名、删除 Axiom 会话都不改动它
```

- 导入是复制而非引用：历史条目原样保留，副本头部使用新的会话 ID 和目标 `cwd`，与网页快照并存。续聊、重命名、删除均不修改原 pi 会话文件；代理创建失败时副本一并清理。
- 副本归属当前页签的工作空间，像正常会话一样续聊、保存和恢复，不再打开源会话目录；尚无当前工作空间时使用实例默认目录。只复制聊天记录，不复制项目文件；工具操作作用于目标工作空间，历史中明确写出的旧绝对路径不会自动改写。
- 标题优先用 pi 会话名，其次首条用户消息正文（去掉注入的 Skill 正文与标签），最后退回文件名。
- 历史直接读 JSONL 分支，保留原文与消息 ID，压缩记录按原折叠关系显示。能力与模型沿用「默认新会话设置」，不读取原会话在 pi 里的供应商/模型选择。
- 新增 `session.import({path, cwd?})`：`path` 是服务端文件路径（不是上传），`cwd` 是导入目标工作空间，省略时使用实例默认目录，返回与 `session.create` 相同的快照；`service.status` 返回 `importDir` 供网页定位选择器。
- 新增 `session.duplicate({sessionId})`：把已有会话复制成新身份，主历史与子任务历史 JSONL 都复制到副本自己的文件（副本绝不引用源路径，删除源不影响副本），配置沿用源会话，返回与 `session.create` 相同的快照；仅空闲且有已落盘历史的会话可复制。

## 设置窗口

设置窗口固定为可视区域高度的 80%，上下各留约 10%；切换分类不改变窗口位置或高度。内容少时留白，内容多时在窗口内部滚动，标题和关闭按钮保持可见；沿用现有暗色面板、边框与紫色选中态。

## 图片上传与放大预览

输入区支持点击图片按钮上传，或在输入框粘贴系统截图（Windows 可用 `Win + Shift + S`）；不再提供浏览器截图按钮或屏幕共享。待发送附件、消息和历史中的图片均可点击放大，也可通过 Tab 聚焦后按 Enter / 空格打开；点击关闭按钮、遮罩空白处或按 Esc 关闭预览。

```text
上传 / 粘贴 -> 光标处 [image1] + 同编号附件预览 -> Send -> 文字标记 + 消息图片
```

- 上传或粘贴时立即在光标处插入 `[image1]`、`[image2]` 占位（有选中文字时替换选区），可以继续在图片前后写说明；读取失败恢复原选区。缩略图显示同编号，点击 × 移除附件时同步删除对应标记并重排编号。手动删掉文字标记不会删除附件，删除图片请点 ×。
- 发送时保留占位，不再追加图片编号说明。模型请求会在 `[imageN]` 首次出现的位置紧接对应真实图片，保留前后文字顺序；重复引用不重复发图，未引用附件带编号放末尾，无效编号保留原文。普通发送、Steer / Follow-up 和恢复历史共用该转换；草稿、历史存储和撤回仍保留原附件顺序，多条撤回合并时同步调整编号。旧消息已保存的说明不回溯删除。
- 支持 PNG、JPEG、GIF、WebP，每条最多 4 张、每张最多 5 MiB；不支持 SVG，也不自动压缩或裁剪。大截图可先裁剪再粘贴。
- 可以只发图片，也可以搭配文字、Skill 和文件引用；附件跟随会话草稿，切换会话不会串图，发送失败保留附件。未发送草稿只存在当前页面内存，刷新页面会丢失。
- 运行中也可用 Steer / Follow-up 发送图片，队列显示附件数量，Esc 撤回时恢复图片；多条队列撤回后若累计超过 4 张，请移除多余附件后分批发送。
- 已发送图片在消息与历史中显示，随 Pi 会话记录保存。图片会发送给当前模型服务商，请避免包含密码等敏感信息；不支持图片的模型会明确拒绝，请换用视觉模型。
- `prompt` 支持可选 `images: [{type:"image", mimeType:"image/png", data:"原始 base64（不含 data: 前缀）"}]`。图片数、大小、类型、base64 与文件签名在服务端校验；仅有图片时 `text` 可为空字符串。

## 手动会话压缩

输入框下方图标组提供「手动压缩会话」，点击后选择模式并确认；与后台自动压缩共用 SDK 底层 compact()，不调用会中止主代理的 session.compact()，不生成额外状态文档或事实附录。关闭自动压缩仍可手动触发，无需达到自动阈值。

- **异步**：主会话继续运行，在安全点应用摘要，快照之后新增的消息保留。`asyncKeepRecentTokens` 默认 **5000**，是最近原始上下文的保底保留量。
- **同步**：先安全停止运行中的会话，再确认压缩；压缩期间不允许主会话继续或发送消息，完成后可继续对话。`syncKeepRecentTokens` 默认 **20000**，较大的保留量用于维持任务连续性。
- 两项均可在现有会话压缩配置中修改，适用于全局默认、工作空间默认及当前会话。数值是最近原文的 token 预算，**不是摘要长度，也不是模型输出预留**；实际边界受消息完整性影响。旧配置的 `keepRecentTokens` 继续作为异步保留量的兼容回退，同步缺省使用 20000。
- 同一会话只允许一个压缩任务；历史不足、摘要失败、校验未通过或未缩小上下文时不强行应用。可从压缩进度条打开详情并取消本次摘要。

## 后台自动压缩

在「设置 → 默认新会话设置」的全局默认或目录配置中配置后台压缩，不再提供当前会话的独立压缩设置。压缩按会话所属目录生效：修改该目录的压缩配置后，新会话直接使用；已加载的会话在保存时即时改用该目录的最新配置，不必等重启；尚未加载的会话在首次打开时按所属目录取值（未配置的目录用全局默认），其他目录的会话配置不变。单个会话因模型不兼容而应用失败不影响配置保存。默认开启；可设置 token 阈值（默认 100000）和上下文窗口占比（默认 50%），**任一先达到即触发**。留空表示不使用该阈值，开启时至少填写一个。占比使用当前主模型窗口，统计为当前上下文估算，不是会话累计消耗。近期保留量默认 5000 token，按安全消息边界保留，不拆散工具调用与结果。

可单独选择压缩模型（留空跟随主模型）和模型支持的思考等级。思考等级作为偏好：首次安装、恢复会话或换模型时，若所选等级不受支持，自动使用该压缩模型最低支持等级，实际会话配置返回适配后的值，不改写保存的默认偏好；非法等级和未知模型仍拒绝。默认 `off` 不会再阻断仅支持推理的模型启动。页面初始化若仍遇到其他会话配置错误，会保持服务连接并打开设置，允许修正配置或更新服务，不再反复断线而无法进入。摘要由 SDK 底层 compact() 直接生成，不创建额外代理会话、不加载项目工具或技能。原生提示词负责初始、滚动更新及 split-turn 摘要；customInstructions 仅追加标题和简述要求，turn-prefix 请求保持 SDK 原生行为。摘要有损，不保证语义无损。

输入框上方显示后台压缩的真实阶段：正在生成摘要、摘要就绪等待安全点、已应用、失败、跳过或取消，不显示虚构百分比。失败时显示失败阶段、原因摘要和本次重试冷却时长；摘要压平换行、限制长度并屏蔽常见凭据格式，不显示堆栈。状态按主会话隔离，切换会话和重连可恢复当前状态；服务重启不会继续显示已中断的后台任务。

条幅整行可点，打开「后台压缩」详情弹窗，结构与子代理详情一致：顶部是摘要模型、思考等级、开始时间与耗时；「触发与配置」列出触发时的上下文估算、窗口、两个阈值与近期保留量（真实用量不可用时标注为估算），应用后补上压缩前后的估算 token；「过程」是带时间的步骤流（触发、计划、实际请求、模型输出开始/结束、就绪、应用、失败、取消），失败原因单独置顶；「模型正在写的摘要」折叠展示流式输出尾部（最多 1500 字符，约每 0.5 秒推送一次，不逐 token 广播）。内存只保留最近 5 次记录，两次以上时可在弹窗里切换回看；详细请求与输出保存在会话旁的压缩尝试记录中；服务重启不会继续执行中断的请求。

详情里的「取消本次摘要」只作用于当前这一次：生成中是中断后台模型请求，摘要就绪（还没应用）是丢弃这份结果，历史记录和终态没有该按钮。取消保留原文、不计失败次数，之后 60 秒内不自动重试，冷却结束后在满足阈值的回合边界照常重试。按钮与真实状态存在竞争时以服务端返回状态为准，不会因为点晚了而报错。

```text
完整 turn 结束 -> 达到任一阈值 -> 固定快照 -> 后台生成摘要
主会话继续输出/执行工具 -------------------> 摘要待应用
下一次模型请求前 -> 校验检查点 -> 摘要 + 近期消息 + 全部新增消息
成功提交 -> 对应历史折叠为一个摘要块，展开查看摘要
```

每会话最多一个后台摘要任务；任务完成不立即修改运行中的上下文。应用时使用 Pi `prepareNextTurnWithContext` 安全入口，并保留其原生轮次刷新；用户排队输入仍由原队列投递。摘要过期、失败或取消时不删除原历史。后台压缩失败后按 30、60、120、240、300 秒逐步冷却（上限 5 分钟），冷却期间不重复请求；冷却结束后在后续回合边界且满足阈值时重试，不用定时器主动请求。成功应用摘要或修改压缩配置后清零冷却；取消和正常跳过不计失败。接近窗口上限时执行预算检查，必要时等待已有摘要；失败不请求另一套回退摘要。摘要是有损的，也可能影响模型缓存命中率。

每次后台摘要在同一次模型请求中生成增量进展标题和描述，主会话按 `01 · 标题`、`02 · 标题` 排列，描述只讲本次新增发现、进展或阻塞；历史摘要只作为背景，不重复累计描述。展开后的完整交接摘要仍累计保留有效约束和未完成工作。序号由当前会话压缩记录顺序生成，刷新后保持一致；旧记录或模型格式异常时使用默认标题，不额外请求模型。模型在完整摘要末尾依次追加 `<axiom_compact_title>标题</axiom_compact_title>`、`<axiom_compact_desc>描述</axiom_compact_desc>`，不再输出 JSON；程序在非代码区按成对标签拆出元数据，允许标签前后夹正文、两个标签顺序颠倒或带落单的闭合标签；标题超过 30 字、描述超过 200 字（按码点计，一个 emoji 记 1 字）或含 `<` 时判为不合格。缺失、超长或格式错误时只丢元数据、回退默认展示，标签原文不会留在交接摘要正文里；围栏代码里的同名标签不当协议。正常提取的展示元数据以 `progress: {title, description}` 随事件、会话快照和 Pi JSONL 压缩条目 details 保存，不进入主代理交接摘要。

每次成功压缩保存独立记录，前端只把本次覆盖的历史降为「压缩段节选」，保留近期和后台期间新增消息，不重建整个会话或清空输入。节选口径：用户输入连同图片附件原样保留，助手只保留 `<axiom_display>` 内的正式答复正文；思考、过程说明、工具调用与结果、子代理记录、内部任务通知随摘要卡收走，纯过程轮次整条不再展示。节选条目带左侧色带与「压缩段节选」底注，完整原文仍可在摘要卡展开或原文面板查看；实时折叠与刷新后快照走同一口径，刷新前后画面一致。被压缩的委托记录所对应的子代理入口收进该次摘要，展开摘要后仍能打开原有子代理详情；多次压缩在历史顶部逐层排列，关联不明的旧任务保守保留。归属依据真实委托工具结果的任务 ID，而非时间猜测。重连/重启恢复相同归属，未完成的后台摘要不会恢复；Pi JSONL 仍保留原文。

生产仅生成 SDK 原生摘要，不再运行结构化状态 patch、来源授权、facts 核验或原文摘录协议。提交前确认归档屏障、工具激活、分支与覆盖哈希，再追加 journal 并确认持久化；不确定提交锁止会话。请求前和后台触发共用预算，输出预留和误差预留独立计算；checkpoint 共用持久提交入口。

协议：`session.create`、`session.configure`、`session.defaults.configure` 支持 `compaction: {enabled,tokenThreshold,percentThreshold,model,thinking,keepRecentTokens}`，两个阈值和 model 可为 `null`。配置返回实际 compaction；快照包含 `compactions`，消息记录包含 `entryId`，被压缩折叠的记录额外带 `compacted: true`（精简版，完整原文按 `compactionId` 另取）。成功事件 `agent.compaction` 包含摘要 ID、正文、保留边界和 `compactedMessageIds`，客户端按消息 ID 折叠而非按时间猜测。进度事件 `agent.compaction.status` 与快照 `compactionStatus` 使用相同阶段数据，并附 `runId` 与最近 5 条 `runs`（阶段、触发参数、步骤时间线、流式尾部、用量、错误、结果）；老客户端只读外层 `status/message/startedAt` 仍可用。`session.compaction.cancel {sessionId, runId?}` 取消当前这一次摘要，返回 `{cancelled, reason, status}`：`runId` 对不上、任务已结束或会话未加载时只回 `cancelled: false`，不报错。关闭自动压缩时仍执行安全窗口预检，超窗明确报错，不秘密启用 SDK 压缩。

界面回归：运行 `node tests/conversation-preview.mjs` 后，在已有 Python Playwright/Chromium 的环境执行 `python tests/compaction-ui.py`，检查两层摘要、子代理详情、输入区进度条幅点开摘要进程详情（步骤时间线、流式尾部、取消按钮、历史切换）与桌面/390px/320px 布局；样例不调用模型或读取用户历史。条幅排在输入区上方，点它不算“要写入”：不触发输入区展开，否则条幅会在 mousedown 与 mouseup 之间被顶走、click 根本不触发（与“回到最新”按钮同一道防守）。

## 会话与子代理运行信息

- 发送按钮显示「发送」，不带上箭头。底部操作行上方显示运行摘要：缓存命中、上下文用量/窗口及占比、当前实际供应商 · 模型 · 等级，例如 `zai-coding-cn · glm-5.3-flash · max`，不加「思考」前缀；不再显示 OP 折叠统计。主/子模型等级选项也直接显示 `off/high/max` 等实际值，保留无障碍标签。桌面一行排列，窄屏自动换行。
- 缓存命中按最近一次模型回答的 `cacheRead / (input + cacheRead + cacheWrite)` 计算，并显示命中 token 数；没有用量或输入总量为零时显示「暂无数据」，不伪造 0%。上下文直接使用 Pi `getContextUsage()` 的当前估算，不是累计 token 消耗；压缩后尚无可靠统计时显示「待更新」。
- 主会话用柔紫色底、左侧色条和描边「子代理」徽章突出子任务卡片，显示状态、简短标题和本任务费用；点击打开独立原生浮层，不在对话中堆叠详情，也不因新任务自动弹出抢焦点。浮层以右侧会话内容区居中、宽度保留 880px 上限，位置和遮罩避开左侧配置栏与顶部会话标题；侧栏收起、窗口缩放和手机布局同步适配。
- 浮层顶部固定显示缓存、上下文、供应商/模型/等级及「回到最上」「回到最下」按钮，仅下方任务说明、系统提示词、任务账单、失败原因和消息滚动。回到最上暂停跟随，回到最下恢复跟随新输出；手动向上阅读不被刷新拉回底部。支持关闭按钮、点击会话区遮罩、Esc 和焦点返回，不会停止运行中的主/子代理。
- 子代理消息直接复用主会话的 `card/renderMessage`、`stream-renderer.js` 和 `markdown.js`，包含流式正文、思考折叠、代码块、表格、历史及最终消息，安全边界不变。系统提示词取自该子代理实际运行状态（含扩展动态修改），仅按纯文本展示；尚未创建代理时提示未加载。切换/重连时清理旧浮层，再按会话快照恢复。
- 主/子运行信息通过 `agent.runtime` 事件更新，只在消息、轮次结束及上下文压缩等边界采样，不随每个 token 重发。会话快照新增 `runtime`，子任务 `task.state` 与快照附带各自的 `runtime`，包含 `model/thinking/systemPrompt/context/usage`；子代理销毁前保留最终状态，切换或重连恢复，互不串用。`read_result` 与 `tasks.read` 仍只返回任务结果，不把展示用的系统提示词再塞入主代理上下文。

## Todo 统一任务模式（原 Goal 目标模式）

- `/goal` 与输入区「目标」按钮进入清单准备阶段，不新建会话或改变工作目录。裸 `/goal` 不请求模型；下一条消息或 `/goal <目标描述>` 用于澄清范围与验收标准，随后通过 `todo_update` 的用户确认流程建立一级目标，再开始实施。
- 旧 Goal 状态机、轮次工具、正文完成标记和独立面板已移除。执行、工具、子代理、队列和压缩共用 `src/sessions.js`，任务生命周期统一由 Todo 管理，简单问答不必建单。
- 一级目标定义交付范围与验收标准，创建、修改定义或删除须用户确认；二级步骤可由主代理在已确认范围内调整。清单最多 5000 项，查询有界分页，写操作使用 `baseVersion` 原子校验；版本冲突时按需重读。
- 二级步骤全部完成不自动完成一级目标。一级目标须逐条记录验收结果与可核对引用；工具验收使用可信工具结果，用户验收须用户确认。证据可核对不等于结果必然正确。
- 暂停在安全边界生效，不强行中断在飞工具；暂停后普通输入、子任务通知和重启不能自行恢复执行。恢复须先核对保存状态与实际产物，避免盲目重放。空闲推进有界，仅剩受阻项时不循环唤醒。
- 协议为 `todo.action`（`prepare | cancel_prepare | pause | resume`，可带 `text`）与 `todo.get`；旧 `goal.action` 不再支持。子代理不维护主清单，主代理读取结果并验收后更新。
- 输入区「添加、图片、目标」继续共用工具栏外框，各按钮独立操作。Todo 不是权限沙箱，不改变目录信任或插件权限。

### 发布复位与性能验证

发布不迁移旧任务数据。先停止服务及所有共享同库写入者，备份并核实数据库路径，再运行：

```sh
node scripts/reset-todo.mjs --database <已核实的数据库路径> --confirm-reset
```

此操作不可撤销：在事务内删除指定库的 `todo_events`、`todo_items`、`todo_lists`、遗留 `todos` 和 `goals` 表，再重建空任务结构；不清理其他表，不自动备份，不按会话筛选。输出删除前的各表行数。不要对仍在使用中的数据库执行。

`node scripts/benchmark-todo.mjs` 在临时数据库中测试 100／1000／5000 项清单，输出读写延迟与响应大小的 JSON，结束后清理临时库，不读写生产数据库。

请求用量审计新增 `usageKnown`：本地合成失败终态与旧记录默认未知，零占位计数不代表供应商确认的零用量；已有终态费用不会被迟到回调覆盖。

## 历史归档与旧引用兼容

OP 自动折叠已移除，消息不再按年龄或发送次数改写。`AXIOM_OBSERVATION_PACK` 仅产生弃用警告，不能重新启用旧策略。`src/legacy-observation.js` 仅提供旧 `obs_recall` 只读兼容，不产生对象、投影计数或 ledger；旧写入实现仅留在测试夹具。

每个持久会话在 `<journal>.history/` 维护 `raw.jsonl`（原始 message/custom_message）和 `control.jsonl`（摘要与控制节点）。SDK journal 是执行状态唯一权威；归档按 `(sourceJournalId, entryId)` 幂等追加、fsync 确认，同身份异内容拒绝。SDK 0.85.1 的持久化适配器保证首条用户消息立即落盘，写失败锁存并要求重新打开会话。归档保留 journal 的完整结构，不使用摘要序列化器；SDK 工具结果通过 `details.fullOutputPath` 声明的完整文本产物同步到 `artifacts/`，哈希校验后可用 `artifact_0` 分页读取；原临时文件消失不影响读取，归档产物缺失则拒绝屏障。内嵌图片／二进制内容保留在原始消息结构中；未声明的外部产物不伪称已保存。剩余磁盘小于 16 MiB 时阻止新增归档，不自动删除历史。

`history_search` / `history_read` 仅读取当前代理、当前来源链允许的条目，返回稳定 `hist:` 引用、哈希、来源角色与分页信息；游标签名并重新核验权限；检索快照最多缓存 128 组，重启或快照淘汰后旧游标明确失效，稳定 ref 仍可重新读取。原始 `sourceEntry` 和正文 part 可读；`summaryEvidence` 是用于核对摘要引文的派生文本，不代替原文。分页预算计算整个响应，UTF-8 字符不会被拆坏。历史材料不代表当前指令或授权。

迁移盘点：`node scripts/legacy-history-dryrun.mjs <directory>`，只读源文件，输出缺失附件、身份冲突与不可映射引用，不自动回填或删除生产数据。

## 消息执行过程

- 等待模型响应显示 `connecting...`，思考中显示 `thinking...`、完成后为 `thinking`，准备工具调用显示 `calling...`；思考只保留一条入口，右侧「查看 / 收起」。活动行采用 12px 常规字重、14px 线条 SVG 与 20px 底座。连续没有正文、没有工具调用的思考合并展示，不堆叠空白 AXIOM 卡片和重复模型用量。
- 工具行按「语义图标 → 工具原名 → 操作对象 → 状态 → 详情」排列，直接显示 `read`、`edit`、`bash`、`powershell` 等，不加中文动作前缀；仅省略已知的 `functions.` 命名空间，悬停可看完整名称，未知工具保留原名。文件、命令、搜索等各有固定 SVG，完成后不替换成小对勾；工作空间内路径显示相对路径，长摘要省略，悬停保留完整值。手机将对象移到第二行。
- 思考、工具、Skill、重试、压缩记录及子代理系统提示词隐藏默认展开三角，使用「查看 / 详情 / 收起」提示，仍保留原生 details 的 Enter / 空格操作与焦点提示。展开后标题栏随会话滚动吸顶，右侧「收起」带向上收拢图标，读到中间也能折叠；工具输出、diff 和系统提示词不再限制内部高度，不产生第二层纵向滚动。
- 所有进行中状态（连接、思考、准备/执行工具，以及子代理启动/运行中的卡片、浮层标题与输入区摘要）统一为同一枚 12px 细环：细边无光晕、1.6 秒一圈，颜色沿用所在组件的语义色。思考文字后的 `...` 动态点固定 3 字符宽，1.2 秒步进循环，点数变化不跳动布局。结束后全部停止；系统开启「减少动态效果」时动画静止但仍保留状态文字。注意：Windows 关闭系统动画或经远程桌面（RDP）会话时，浏览器会判定「减少动态效果」并冻结这些动画，属系统环境而非页面故障，在系统设置重新开启动画即恢复；页面保留该无障碍媒体查询，不另加开关。
- 工具按用途分色：读取/搜索为雾蓝，命令为青绿，编辑/写入为暖金，思考/子代理为柔紫；失败仍用柔红。颜色仅作辅助，动作与状态文字始终保留。
- 点击或键盘展开工具详情：edit 优先显示工具返回的实际红绿 diff，没有 diff 时明确标注为请求改动。默认窄屏使用统一视图、宽屏使用左右对比；支持手动切换并在浏览器记住选择，窄屏始终回退统一视图；write 显示写入内容（无法仅凭参数判断新建或覆盖）；bash/read 等显示参数和文本输出。内容以纯文本安全展示，展开后才生成详情，每节最多显示 60,000 字符，超限提示独立放在该节下方，左右对比、统一视图和手机端均可见；完整结果保留在原会话记录中。
- 主会话、子代理及历史恢复使用同一套展示；只改变显示，不删除原始消息或修改模型上下文。

## 输出渲染与性能

正文与展开的思考共用 marked + DOMPurify 安全 Markdown 渲染，支持标题、强调、列表、引用、表格与代码。正文与思考均为 14px；正文灰白、重点暖金、补充说明柔紫、行内代码青绿、链接雾蓝。思考按斜体、正常字重展示（标题、`**强调**` 和表头也不加粗，保留 Markdown 语义）；代码和复制栏保持正体，便于辨认字符。代码块显示语言与「复制」，剪贴板 API 缺失（远程 HTTP 非安全上下文）时自动回退 `execCommand`，仍失败才提示手动选择复制；宽表格和代码仅保留必要的横向滚动，可用 Tab 聚焦，不限制纵向高度。复制控件在净化后生成，不允许 Markdown 注入按钮、脚本或 inline style。

完整的 `+---+` ASCII 表格（无语言或 text/txt/plaintext/ascii 代码块，单行单元格、列数一致）自动显示为网页表格，避免中英文宽度导致边框错位；复制保留 ASCII 原文，残缺表格、普通代码和流程图不转换。无边框、靠空格对齐的表格同样转网页表格：按显示宽度（中文/全角算两格）建网格，以「每行都空的 2 格以上空白」作列界，单个空格归入单元格（如 `2026-09-12 六`）；全列都是数字/百分比的列右对齐并用等宽数字，`-----` 分隔线保留为分组上边框，单元格不折行、窄屏横向滚动。首行在数字列也是数字时（如 `ls -l` 输出）不当表头，不编造语义；少于 3 行、不足 3 列、含制表符、被识别为字符图，或对齐不一致（拆出的单元格内仍有 2 格以上空白）时一律保留原文，不猜列划分。JSON 代码块、纯文本代码块中的有效对象/数组，以及整条纯 JSON 对象/数组消息提供「格式化、压缩、去转义、转义、复制」。去转义解开一层带外层双引号的 JSON 字符串；转义把当前文本编码成 JSON 字符串；复制始终取当前操作后的内容。操作仅影响本地展示，不修改会话原文；失败保留内容并提示，格式化/压缩遇到超安全范围整数或非有限数字拒绝转换，其他数字按 JavaScript JSON 精度处理。不扫描普通段落里的 JSON 片段。

字符图统一分层处理：明确的完整 ASCII 数据表格、空格对齐表格转网页表格；ASCII 方框、目录树、箭头和 Unicode 单/双线/圆角框按结构信号识别为字符图，混合说明一并保留，不猜测连线语义；未识别内容默认原文。仅处理无语言或 text/txt/plaintext/ascii/diagram/tree 代码块（大小写不敏感），不改编程语言或 JSON。所有此类文本块提供「优化 / 原文」切换，漏识别可手动启用网格，误识别可恢复原文，表格也支持切回原文；复制始终保留源文本。按字素网格显示：中文/全角及 emoji 占两格，其他字符占一格，避免系统字体回退导致边框错位；保留并排布局、原文复制和窄屏横向滚动，不转成表格。组合字符不拆开，Tab 按当前位置推进到下一个 8 格制表位且复制保留原始 Tab；超过 20,000 字符的网格优化禁用并提示原因，以限制 DOM 数量。网格不自动修复原文本身缺少/多出的空格，也不猜测图的语义。浏览器检查：`python tests/text-diagram-ui.py`（需 Playwright Chromium）。

Git 历史单独优化为紧凑提交列表：关系列保留原始字符、哈希等宽对齐并弱化，长提交说明自动换行。支持至少 3 行、整块一致的 `git log --graph --oneline` 输出，以及首行哈希 + `├─`/`└─` 子提交列表；除上述纯文本语言外，也识别 git/gitgraph 标签。不猜测任意目录树、完整 Author/Date 日志或编程语言块；超过 20,000 字符保留原有路径。保留「优化 / 原文」切换，复制始终取完整原文，不修改历史数据。浏览器检查：`python tests/git-log-ui.py`，覆盖桌面与 320px 窄屏换行、哈希对齐及原文切换。

流式更新只处理发生变化的消息：权威原文与思考立即累计，显示层共用一个 requestAnimationFrame 调度器，绘制前合并去标签、拆分回答并刷新活动状态。当前挂载的主回复普通单段文字短缓冲后按真实时间逐字素推进，不再每批瞬间贴完；初始缓冲 150ms、基准 10 字素/秒、目标滞后约 1 秒、最高 200 字素/秒，积压超限批量对齐。Intl.Segmenter 在输入变化时对最多 24,000 UTF-16 码元全文分段，不用固定尾窗猜 emoji/旗帜边界；缺少 Segmenter 时安全整批显示。滚轮、触摸、指针、键盘和输入事件后让路 520ms，持续交互时每批待绘制内容最多延后 1 秒（主线程可运行时）；不监听程序滚动，避免贴底自我延期；flush（消息结束/切换）绕过节流立即收口，最终消息优先且清空待处理，清除会话时取消全部挂起调度。思考不触发正文 Markdown 重绘，折叠思考不解析 Markdown，展开才渲染。未打开浮层的子任务仅收集文本，不调度正文动画帧、不解析 Markdown，打开时一次显示完整结果（包括历史恢复与最终消息）；关闭再打开复用原有消息 DOM，不复制一套渲染逻辑。Markdown 按块比较，保留未变化的 DOM，仅对变化块解析、清理并替换；块键为 `type`+`raw`，引用定义另用 `lexer.links` 签名触发失效（定义不产生块，晚到的 `[id]: url` 会改变先前段落的渲染而 `type`/`raw` 不变），不再对每个 token 做 `JSON.stringify` 深序列化；仍完整词法分析以正确处理后出现的引用定义。普通文本保留同一个 Text 节点，不做逐字 Markdown 解析；第一版仅无 Markdown/HTML/链接语法的单段文字平滑，换行、代码、表格、列表等仍批量解析（活动消息至少间隔 100ms，并按上次耗时退让）。超过 24,000 UTF-16 码元统一完整安全原文展示并注明降级，不在结束时强制巨型 Markdown 解析；阈值以内复杂文档仍可能产生同步长任务，不承诺全场景帧预算。

隐藏页面停止动画，恢复直接对齐；系统 reduced-motion 动态生效；选中文字时暂停 DOM 更新（不延迟权威数据/业务终态）。消息结束或取消保留全部已收到文字并立即收口。切换快照清除游标，身份使用 item 对象加可选 generation，不跨回复借用 sessionId+agentId。挂载层可设置 `item.mounted` 并调用 `renderer.disposeMessage(item)`；默认复用节点连接状态与任务浮层 open 判断，重挂已显示消息直接对齐。高度变化只走既有 afterPaint/scrollLatest 通知，不接管虚拟窗口或滚动锚点。全文复制继续读取权威原文，不读取动画前缀；正文 aria-live=off，不逐字播报。样式、颜色与焦点规则沿用既有设计，不新增动画依赖。

测试：`node --test tests/stream-playback.test.js tests/smooth-stream.test.js tests/stream-renderer.test.js tests/markdown.test.js`；隔离实测：`python tests/smooth-stream-browser.py --out docs/perf-smooth-stream.json`（需 Python Playwright/Chromium，只启动随机 loopback 静态实例，无模型/业务连接）。实测边界与接入说明见 [流式显示交付记录](docs/smooth-stream-delivery.md)。

### 大会话渲染容量

长会话一次性完整挂载，不做消息分页：打开会话即渲染服务端下发的全部历史，没有页窗口、页游标和窗口裁剪。控制 DOM 规模靠上下文自动压缩——被压缩覆盖的历史在下发时就不包含，只保留摘要卡；点开摘要卡才按需取回该段原文（见下文「压缩摘要按需展开」）。屏幕外消息仍由浏览器 content-visibility 跳过布局与绘制。已知边界：从未压缩过的超长会话（单会话数千条且无摘要）DOM 规模无硬上限，未实现虚拟列表。

历史快照的 Markdown 渲染产物按条目缓存（LRU 2000 条 / 8MiB 原文预算，实际 DOM 内存不等于原文大小，键含会话与代理），同一会话内整份重挂（撤回重取、后台回前台收口）及切走再切回直接复用已渲染节点，切换不再整体丢弃；缓存只存派生产物，服务端原文始终是唯一权威，任何时候丢弃缓存都能重建。空态占位持有直接引用，追加消息时以 O(1) 摘除，避免历史挂载逐条扫描已增长的消息区域。超过 1MiB 的发送体在后台 Worker 里序列化，避免大命令阻塞主线程；无 Worker 环境退化为同步序列化，单条消息仍是原子发送。

浏览器验收：`python tests/render-capacity-ui.py`（需 Python Playwright/Chromium，4× CPU 节流下 500 条混合消息，覆盖整份挂载、滚动交互延迟与全展开后的 DOM 规模）。设计与实测记录见 [会话渲染容量记录](docs/session-render-phase-d.md)。

会话快照仅在地址 hash 变化时更新 History，避免首屏地址已正确时重复调用 `replaceState`；切换会话和缺失地址恢复仍同步写回。

输入框自动高度复用未变化的测量结果，避免历史重建后重复读取 `scrollHeight`；输入内容、窗口尺寸、侧栏、手机展开、折叠态切换或字体加载变化时重新测量。该优化不消除浏览器正常布局成本，实际长任务改善仍需实测。

桌面输入区默认折叠成一行输入 + 一行运行摘要（空闲约 76px）：折叠态保留运行摘要（缓存命中 / 上下文 / 模型）、右上角任务计时、右下角 Stop 与强制停止，以及上下文 chips 与待发附件；左上角 `+` / 图片 / 目标三个图标、模型与思考选择、发送按钮、会话详情入口与快捷键提示收起，把竖向空间让给会话正文。任务运行中停止按钮才出现，与运行摘要同处一行（摘要靠左、Stop 与强制停止靠右，约 90px），空间不够时摘要单行裁掉末尾而不把按钮挤到下一行；空闲时整条按钮区收掉不留空白。点击、聚焦或直接输入即展开为完整形态（约 270px），鼠标离开且键盘焦点也不在输入区内后 5 秒自动收回。折叠不动草稿（Enter 仍直接发送），也不隐藏目标/提问/队列/压缩等提示区；有待发图片、@ 补全或上下文菜单打开时不折叠，避免把正在用的按钮收进去；任务运行中照常折叠，因为停止按钮在折叠态里本来就在。宽度 ≤700px 仍用原有手机阅读/展开机制，两套不互相干扰。「回到最新消息 ↓」钉在输入区上沿，点它不算输入意图：不会展开输入区（否则 mousedown 就把按钮向上推两百多像素，mouseup 落不回原元素，click 根本不触发）。

工具详情关闭时释放已生成的详情 DOM，保留原始参数、结果与历史定位索引，重开按当前 diff 视图恢复；关闭期间新结果只更新数据，不生成详情节点。浏览器页内查找不会命中已释放的折叠详情，需先展开。

历史展示一次给全：`session.attach` 把当前会话未被压缩折叠的全部消息整份下发，前端同步挂载，没有翻页、前插预取与页替换。历史区左右两个按钮（回最早/回最新）只做本地滚动跳转，不触发任何取数。子代理记录按委派锚点整组紧跟对应委派工具，主对话保序，不会被子代理风暴挤开。屏幕外消息通过浏览器 content-visibility 跳过布局/绘制，折叠过程正文、思考、工具详情与未打开的子代理正文按需渲染。工具结果关联的子代理入口随历史挂载回到委派工具之后；委派锚点尚未入史的运行中子代理不追加到主轴末尾，入口只在输入区上方任务栏，行在入口缺席时禁用。会话阅读位置按稳定身份（messageId）恢复，切走切回、重启后回到原锚点与偏移；位置缓存保留 3 个，未保存草稿/附件不淘汰。隐藏页面暂停建 DOM：后台期间只记脏，回到前台重取一份完整历史，贴底视角自动追新、非贴底视角保留阅读位置。发送采用乐观 UI：提交即时上屏「发送中」用户卡并同步清空输入框、本次附件与技能选择，先绘制再做请求序列化，确认事件按 runId 原位升级；确定失败撤卡并在原会话编辑器仍为空时恢复本次草稿（不覆盖后续输入），结果未知时保留未确认卡、不自动恢复到输入框以避免误重发；快照整份重建在飞时提交不被阻塞。未采用 HTML 本地文件缓存，避免原文与派生 UI 双份状态过期。

`session.attach` 返回整份历史及 seq/instanceId，另带 messageIndexes/messageCount（折叠前的历史下标与总长，供目标轮次锚点与重试卡定位）。`session.compaction.messages` 按 compactionId 取回某次压缩折叠的原文段（含该段内的子代理记录、工具状态与重试记录），未加载的会话走只读 JSONL 投影、不创建 SDK 实例。服务端下发按委派锚点顺序投影：live 会话的到达序数组不动，仅下发时重排（孤儿任务记录前置头部）；恢复会话同样按锚点归位。撤回真正截断历史时广播 `session.history.reset`，各端整份重取（增量事件表达不了「消息消失」）。消息带 messageId（entryId 优先，否则 UUID），活动流另带 liveMessageIds，结束事件带最终身份；prompt 回执带 runId，事件信封同样携带，供前端乐观卡对账。浏览器查找和选区复制仅覆盖已挂载内容，折叠工具与未展开的压缩段须先展开；原文对照提供已加载内容逐条源码复制，不把 DOM 选区偏移当源码偏移。

边界：SDK 与 Sessions 的权威历史仍全量驻留，单次下发量由压缩折叠控制而不是分页；从未压缩的超长会话仍可能一次下发很大一帧（收发上限 32 MiB），未实现硬上限虚拟列表；活动任务、未保存输入、单条巨大消息不是硬字节有界，尚不宣称整个链路内存有界。当前证据与复现见 [本轮性能采集](docs/perf-history-session/README.md)。

自动滚动请求合并，只在贴底时执行，内容增高由内容观察器兜底补底，用户滚动意图（滚轮、触摸、键盘、拖动）才暂停跟随；切换会话清理待绘制任务；删除重复任务恢复、单连接多订阅容器和重命名时的整份历史复制。静态资源启动时读取并生成 ETag，浏览器刷新时重新校验，未变化返回 304，不重复传输正文；生产下更新或新增静态文件需快速重启服务载入。开发服务（`AXIOM_DEV=1`，即 `npm run dev`）按文件 mtime 惰性重读已注册的静态资源并重算 ETag，改完刷新页面即可，不必重启；新增文件仍需重启注册路由。`public/stream-renderer.js` 独立负责渲染调度，`markdown.js` 负责安全块渲染。

视觉回归：先运行 `node tests/conversation-preview.mjs`，再用已有 Python Playwright + Chromium 环境执行 `python tests/conversation-ui.py [截图输出目录]`。测试使用静态样例，不读取用户数据、不调用模型；覆盖 1440/390/320px 配色、工具原名、活动行字号/字重/图标比例、行高与手机点击区域、Skill 键盘展开和模块强调、真实转圈/思考动态点固定宽/减少动态效果、长内容吸顶收起、无内部纵向滚动与子代理定位。

运行 `node tests/benchmark.js` 可复现 CPU/DOM 微基准。浏览器同机 3 个约 4KB 输出区 × 60 次更新，三次中位数从 391ms 降至 148ms（约 -62%）。这不是模型生成速度或真实端到端延迟指标。新增折叠任务场景：3 个任务 × 60 次更新，展开时 60 帧 / 180 次 Markdown 解析，折叠时 0 帧 / 0 次解析；完整内容保留，展开后按需呈现。

- 选中后复用原上下文标签与发送逻辑，文件或文件夹标签也可单独发送；只发送路径引用，不预读文件、不递归扫描目录、不增加依赖。

添加菜单采用 176px 宽的三行单行布局，说明收进悬停提示；加号为 28px 无边框细线 SVG 按钮，触屏扩大触控区域。输入区按「任务正文 → 模型选择/发送按钮 → 会话信息」排列，不再用 CSS order 重排。

输入框上沿「＋」菜单提供 Skill、工作空间文件、工作空间文件夹三个入口，使用统一线条 SVG 图标。搜索列表按名称或说明模糊匹配技能。文件/文件夹按层级浏览，过滤 `.git`、`node_modules` 与符号链接，服务端 realpath 校验禁止浏览工作空间外目录。选择后显示可移除标签，不改变原模型选择与运行信息布局。Skill 只显示在上方标签，输入框仅显示任务正文，发送时自动附加 `/skill:名称 `；手动输入有效 Skill 命令并键入空格后也转为标签，每次显式加载一个；文件/文件夹以路径引用随消息发送，由代理按需读取，不上传或递归灌入整目录。标签随页面内草稿切换保留，发送成功清空，失败保留。

会话里的原生 `<skill>` 消息块显示为默认折叠的 `SKILL` 描边标识和技能名，用雾蓝左侧色条、浅底色和边框与普通工具行区分；点击展开路径和经过 Markdown 安全渲染的正文，skill 块放在对应用户消息前面，与用户气泡平级，不嵌套；纯 skill 消息不显示空气泡，历史恢复也适用。该标识表示技能正文进入消息，不表示模型已完成执行。

### 统一文件 / 文件夹选择器

「打开工作空间」、「导入 pi 会话」和「＋ → 文件 / 文件夹」共用 `public/file-picker.js` 原生网页弹窗，与现有主题保持一致，不再启动 PowerShell。支持地址输入、面包屑、上一级、刷新、常用位置、按名称模糊搜索（递归当前目录的全部子目录，命中行右侧显示所在相对目录）和确认/取消；目录单击进入，文件选中后确认或双击添加。支持 Tab、上下箭头和 Esc，窄屏自动收拢位置栏。代码、配置、文档、图片、音视频、压缩包、PDF、字体和项目目录使用本地分类 SVG 图标，不加载远程图标或字体。

```text
打开工作空间 ─┐                    ┌─ 主机目录（绝对路径）
选择文件 ─────┼─ 共享选择器 ────────┤
选择文件夹 ───┘                    └─ 当前工作空间（限制范围）
                         点进目录 → 只读取该层 → 每页 200 项
```

- 无搜索词时只读取当前层名称和类型，不扫描子目录、不读取文件内容/大小/修改时间，按目录优先排序后服务端分页，按需「加载更多」。搜索词非空时改为客户端零改动的服务端搜索：BFS 逐层递归当前目录（跳过 `.git`、`node_modules`、符号链接），只匹配名称、不回读文件，忽略大小写且字符按顺序出现即命中（`apjs` 命中 `app.js`），按匹配质量（完全相等 → 前缀 → 子串 → 子序列）排序后一次返回最多 60 条、不再分页；递归目录数封顶 400、单目录不可读只跳过，避免超大工作空间卡住请求。实测 Axiom 工作空间每次搜索 3–40ms。单层目录仍需 `readdir` 后排序，极端大目录若成为瓶颈再改为流式目录游标，不提前搭建索引服务。
- Windows、macOS、Linux 共用 Node 文件系统实现；主机模式提供用户主目录、文件系统根目录及 Windows 可用盘符，地址栏可输入 UNC 路径。浏览的是 **Axiom 服务所在机器**，不是另一台浏览器设备。系统权限错误在弹窗中提示并可重试。
- 工作空间引用保留相对路径和 `realpath` 边界校验，过滤 `.git`、`node_modules` 与符号链接；打开工作空间允许浏览本机目录但不预先加载其中的项目能力。选定后仍沿用已有会话切换/创建与信任流程；取消不切换。过期响应、会话切换和关闭弹窗不会覆盖新选择。
- 图片上传仍使用浏览器原生文件上传和粘贴：这是上传附件，不是引用服务端路径，不能混用两者。
- 新增 `files.browse({sessionId?,path?,directoriesOnly?,offset?,query?})`，返回 `path/parent/entries/nextOffset/breadcrumbs/locations`；省略 sessionId 为主机模式。补全接口 `workspace.browse({sessionId,path?,query?})` 复用同一实现：`query` 非空时递归搜索当前 `path` 子树（默认工作空间根）、一次返回全部命中。沿用本地 WS Host/Origin 校验，不接受任意系统命令。`workspace.reveal({sessionId})` 使用 Explorer / open / xdg-open 打开系统文件管理器，Linux 需安装 xdg-open 并有桌面环境。

调研参考：[VS Code Lists And Trees](https://github.com/microsoft/vscode/wiki/Lists-And-Trees)、[Seti 文件图标主题](https://github.com/jesseweed/seti-ui)、[原生 JS FileExplorer](https://github.com/cubiclesoft/js-fileexplorer)。借鉴目录懒加载、文件分类和导航布局，不引入完整文件管理器或复制其图标资产；图标为本地自绘 SVG。[showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker) 浏览器支持有限，也不能提供服务端工作目录路径，因此不作为跨平台实现基础。

普通发送、插话和追加均复用 Pi 原生 Skill 命令展开，在发送/入队时读取 Skill 正文，不另建文件读取接口，不修改会话能力配置。选择表示「本次发送要加载」，不代表模型已经使用；已进入上下文的 Skill 不会因取消下一次选择而被删除。会话配置新增 `skills: [{name, description}]`，取自主代理实际资源加载器。

## 队列与执行中交互

- 执行中显示 `Steer` / `Follow-up`：Steer 在下一个可介入节点补充指令，不立即中断运行中的工具；Follow-up 等当前这一轮结束后发送，不影响当前执行，也不保证上一轮成功。Enter 使用设置中的默认类型，初始为 Steer；配置页直接展示两者说明，下拉框复用模型选择样式。
- 输入框上方显示 Pi 原生队列和类型。点击队列或单按 Esc，使用 Pi `clearQueue()` 一次撤回全部队列并追加到现有草稿，不覆盖草稿；重新发送时可选类型。这里与 Pi 原生一致，不提供逐条删除。
- 双按 Esc（300ms 内）或「停止」取消执行。右上角已连接时显示 `Idle` / `Running`，断线为灰色。
- 300ms 内三按 Esc：把这一轮已发出的输入收回输入框（含图片，编号重新对齐草稿附件）。只在模型还没产出内容时成立（被中断或失败的半截回答会一并丢弃）；一旦出现过回答、工具调用或工具结果，只停止并保留原消息；队列里的消息仍按单按 Esc 撤回，被拒绝的撤回不会吞掉队列。撤回按分支回退实现，之后的历史前缀逐字节不变，供应商前缀缓存继续命中。
- 撤回已在 Pi 分支生效后，即使 SQLite 暂时拒绝保存，网页历史仍同步、输入仍交还草稿；保存错误会显示，整组记录清理保留到下次保存或关闭重试，不把“已撤回”冒充“已落库”。
- `prompt` 可带 `queueType: "steer" | "followUp"`；`session.configure` 可保存默认 `queueType`；`queue.withdraw` 可带 `recall: true` 并返回 `{steering,followUp,recalled}`（`recalled` 为 `{entryId,text,images}` 或 `null`）；`session.queue` 同步队列，attach 快照包含 `queue`。
- 输入框上方「+」行最右端显示任务计时器，口径就是侧栏绿点：绿点亮起开始计时，熄灭后定格，重新执行继续累加而不清零。不足 1 分钟显示 `45s`，之后 `3m 05s`、`1h 02m 03s`；运行中绿点脉动、文字提亮，停止后变为静态灰点，数字用等宽数字位（`tabular-nums`）避免每秒跳动，减少动态效果只停动画、不停计时。计时按会话落盘：`sessions.list` 与 `session.state`/`task.state` 事件附带 `elapsedMs`（已结算累计毫秒）与 `runningSince`（本段起点，空闲为 `null`），服务重启保留已结算累计值，未结算的运行段不补算。

## 协议

每个命令必须有请求 `id`；响应为 `{type:'response', id, ok, data?, error?}`。

```javascript
const ws = new WebSocket('ws://127.0.0.1:4319/ws', ['axiom']);
ws.onmessage = ({ data }) => console.log(JSON.parse(data));
ws.onopen = () => ws.send(JSON.stringify({id:'1', type:'session.create'}));
// 从响应 data.sessionId 取得会话 ID 后发送：
// {id:'2', type:'prompt', sessionId, text:'并行检查两个模块，读取结果并总结'}
// {id:'3', type:'session.attach', sessionId}  // 重连，返回快照并订阅
// {id:'4', type:'tasks.read', sessionId, taskId:'...', resultId:'通知中的 UUID'}
// {id:'5', type:'cancel', sessionId}          // 取消主 Agent 与当前子任务
// {id:'6', type:'session.close', sessionId}   // 释放会话与结果
```

`session.create` 自动订阅；断开连接不取消任务。重新 attach 返回状态、历史消息、当前流式消息、工具状态、任务结果与序号。快照后按事件 seq 接续，不要重复追加快照之前的内容。服务不保存每个增量的回放日志。

事件包含 `sessionId`、`seq`；Agent 事件包含 `agentId`，子任务另有 `taskId`、`parentAgentId`。类型为 `session.state`、`agent.message.start/end`、`agent.delta`、`agent.runtime`、`tool.state`、`task.state`、`session.billing`、`error`。`agent.delta.data` 的 `type/contentIndex/delta` 对应内容块增量；thinking 是否可见取决于模型。`tool.state.data.partialResult` 为累计结果，替换展示而非追加。`agent.message.end` 的完整消息为最终事实。

主 Agent idle 不代表所有子任务完成，使用 task.state 判断子任务。任务 ID 只在其所属会话中有效。本机客户端能访问所有会话。

## 交互式提问

答题卡使用紧凑题签和选项行；同组问题按当前宽度预留最高内容区，切题时题签位置稳定。卡片不设独立滚动条，超长内容通过输入区域滚动查看；手机收起输入框时待答问题仍可见。自定义回答随换行自动增高，不受聊天框 240px 上限影响；切题保留已撑开的题面高度，调整窗口宽度后重测并保留输入焦点与选区。题签用编号/完成勾区分进度，方向键使用 SVG 键帽提示；主色沿用 Linear 紫色（#5e6ad2），完成状态使用成功绿（#27a644）。浏览器回归：`python tests/question-layout-ui.py`。

主代理内置 `question` 工具：需要用户澄清或决策时调用，等待网页答案后作为工具结果继续原任务；不另发聊天消息、不增加专用系统提示词。子代理不注册此工具。

参数为 `questions: [{ header, question, description, options: [{ label, description? }], multiple? }]`。`header` 是选项卡短标题，问题 `description` 必填，用于说明背景和选择影响；选项说明可选，`multiple` 默认 false。每次 1–10 题，每题 1–20 个不重名选项，页面自动提供自定义回答。工具输出为 `{ answers: string[][] }`，按题序返回选中标签或自定义文字。

页面显示多题选项卡，左右切题、上下移动选项焦点、空格选择、Enter 下一题（最后一题答完后提交）；Tab 正常切换控件，自定义输入内保留方向键编辑。问题首次出现聚焦选项，不默认作答；切题保留草稿，所有问题答完后统一提交。单题隐藏选项卡。取消等待中的提问后，底部显示「重新提问」：点击直接重新执行原问题，不让模型重新生成题目；回答后作为工具结果继续原任务。普通请求中断仍显示「重试」。

待回答状态属于会话，断线不取消，重新连接或刷新通过快照恢复；重复提交只生效一次。停止任务、删除会话或关闭服务会解除等待。等待对象仅在内存中，不支持跨服务重启续答；已返回答案随正常工具结果进入 Pi 历史。

## 委派工具

- `delegate({context:'委派原因、当前进展、已知信息与共同约束',tasks:[{task:'研究问题 A、范围与交付要求'},{task:'分析问题 B、范围与证据要求'}]})`：异步启动研究与分析子代理，成功后立即返回 `{taskIds:[...]}`，不返回结果。委派前明确待解决的问题、结果用途和交付要求，并检查任务说明是否足以让未参与当前对话的子代理独立理解并执行；`context` 为批内共享背景，`tasks[].task` 放任务专属信息，不重复共享背景，子代理不继承主会话历史。每个任务只设一个几轮内可完成、可独立验证的目标，较大工作拆开（轮次预算见「会话标题与子代理轮次预算」）。收到完成通知中的 `taskId` 和 `resultId` 后，再择时调用 `read_result` 读取一次，不轮询。
- `read_result({taskId:'...',resultId:'...'})`：仅在收到子任务完成通知后，用同一条通知中的 `taskId` 和 `resultId` 读取结果；通知到达前调用会失败。此工具只获取结果，不查询任务进度，不得轮询。移除 `wait` 和批量 ID 参数，不提供轮询/等待入口；错配、跨会话或未完成均拒绝。重复读取保留结果，失败与取消也有可读结果。任务结果按模型原文落库与回读，`<title>` 等记忆标签不在落库时剥离，剥离只发生在网页展示层。
- `append({taskId:'...',text:'补充指令',mode:'steer'})`：向 `delegate` 启动的运行中子任务发送补充指令，默认 `steer`（在下一安全点调整当前工作的方向或要求），可选 `followUp`（排队等待当前工作完成后执行）。`text` 应说明要修改的要求或新增的工作，并补充理解指令所需的新信息，不重复子任务已有背景。回执只表示接收，不表示已执行；启动中、停止/总结期间排队。终态有持久化历史且清理已确认时，允许新追问启动新执行；旧执行结果仍凭旧通知读取。
- `cancel_task({taskId:'...',mode:'summary',reason:'停止理由'})`：停止当前会话内指定子任务，不取消主代理或其他子任务。默认停止工作后禁工具总结，`mode:'immediate'` 跳过模型总结但仍交付系统事实报告；回执不返回完整结果，结果通过完成通知与 `read_result` 获取。未知或跨会话 ID 拒绝，已结束任务保持原结果。取消保留历史，不回滚副作用；网页子任务详情使用同一机制，不改变 Goal 的安全暂停规则。

子任务结束后生成独立 `resultId`，先把结果和待通知状态落盘，再主动触达主代理。通知只带 taskId/resultId/status，不塞完整结果或子代理系统提示词。当前主代理还在运行时通过内部消息在下一可介入节点送达；空闲时直接唤醒。待送达的内部通知不显示在 Steer / Follow-up 用户队列中，点击撤回或单按 Esc 只取回用户输入（含图片），不会移除通知或把通知文本写入输入框。主代理收到通知再调用 read_result，不轮询。停止会话会暂停自动唤醒，下一条用户消息恢复；服务关闭不再唤醒。重启会补发未确认送达的通知（崩溃窗口可能重复，同一 resultId 可重复读取），不会重跑已完成子任务；有持久化历史的未完成子任务会续跑。旧任务缺少凭证时在加载时补发凭证。通知状态表示通知轮已处理完，不保证模型一定读取了结果。

输入框「＋」上方显示当前会话进行中的子代理摘要：启动中/运行中/收尾中/停止中/总结中每个一行，转圈图标与单行省略文本；点击或用 Enter / 空格激活后跳到会话内对应子代理卡片并聚焦，暂停自动跟随，不直接弹出详情。可继续点击卡片查看详情，或点「回到最新消息」恢复跟随。任务结束自动移除，无任务时隐藏，切换会话不混入其他会话任务。

无固定并发上限、工具层只读限制或结果截断；子任务受上述独立时间预算约束，自动退避也不延长硬截止。子 Agent 没有递归委派工具。并行修改同一文件可能冲突，应让主 Agent 分配不同文件，或使用不同工作目录/worktree。取消不回滚已发生的文件修改。主代理与子代理遇到模型限流、可恢复网络异常或意外中断时自动避让续跑，最多重试 45 次；间隔为 `2、2、5、5、10、10、30、60、120、240、480、960……秒`，480 秒之后翻倍，16 分钟封顶（全部耗尽纯等待约 9.3 小时）。Stop 会立即取消等待；凭证、权限、计费等永久错误不重试。可在会话配置中自定义错误词表（子串匹配、大小写不敏感）：白名单命中即强制重试（可越过内建黑名单，如供应商把瞬时故障报成 quota 文案），黑名单命中即不重试且优先于白名单与内建判定；词表由新建会话保存，主/子代理共用，重启恢复继续使用该会话原词表，修改默认设置不追溯改写旧会话。词表输入框回车添加一条，Backspace（输入为空时）或 × 删除，重复词不区分大小写；只打字未回车就离开输入框时也会补记该词，「默认新会话设置」里每次增删即自动保存；关闭再打开或刷新页面后，已保存的词会直接显示为标签，重复输入不会新增或隐藏已有标签。重试保留已完成工具结果，不重新发送原始任务；正常结束不凭空判断“任务未完成”，仅对明确的可恢复失败重试。重试详情仅显示次数、错误和预计继续时间，不收纳正文、思考或工具调用；成功后折叠，可手动展开。子代理重试直接按已落入 SQLite 的任务 ID（agentId）绑定，实时、刷新及重启后都固定放在该子任务说明后；不依赖子代理消息是否恢复或混合消息下标，旧记录有任务 ID 即可归位。主代理新记录保存首次重试的消息边界与关联消息 ID。历史迁移优先使用 JSONL 条目写入时间，不将排队消息的编写时间误当消费时间；可靠位置落盘后复用。撤回同步处理被移除区间的重试与其余边界；压缩区间内的重试收进对应摘要，主/子代理分别展示。无法可靠还原原位置的主代理历史记录、尚缺任务元数据的子代理记录放入顶部「历史重试记录（原位置无法确认）」折叠区（任务元数据到达后自动移回任务说明后），不再伪装成回答结束后的事件。终态清除当前等待字段，成功清除当前错误，尝试历史仍保留；记录随会话保存；主代理重启不自动继续，未完成子代理按持久化状态续跑。

若输出被截断（`length`）且正文为空、没有工具调用，Axiom 会保留已完成工具结果，从下一次请求中移除末尾截断回复，附加一句通用内部提示自动恢复一次；提示不冒充用户消息、不改原始日志，恢复结束后移除。恢复再失败即停止，不进入普通错误的多次重试；用户停止后不自动恢复。主代理和子代理共用此规则。

自动重试不覆盖的异常停止（手动 Stop、终态错误、重试用尽）在会话流末尾给出「上一次请求未正常结束。↻ 重试」入口：语义是续跑，删掉末尾失败的助手消息后接着上次中断的位置继续，不重发你的输入，已完成工具结果保留在上下文；续跑再遇可恢复失败仍走上面的自动退避。仅在主代理末尾消息确有异常证据（失败、被中止、被截断，或停在工具轮/半截轮次）、会话空闲且连接正常时出现，正常结束、空会话、运行中不显示；子代理独立在任务详情显示重试入口；点击后转入运行即自动收起。服务端在启动前同步校验可续性，不可续时直接回错，不产生空转运行。

实现参考 [OpenAI Node SDK](https://github.com/openai/openai-node#retries)、[Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript#retries) 及已安装 Pi SDK 的错误分类/安全继续机制。禁用底层重复重试，由 Axiom 统一计数；采用上述指定时间表，不额外加入随机抖动。SDK 消息边界未保留原始 HTTP Retry-After 响应头，因此这里不宣称支持按该响应头调整等待。

任务状态只归 tasks 管理，工具不保存另一份状态；传输层不直接调用 Pi SDK。采用原生 JavaScript ES modules 和 Node 测试工具，不增加编译步骤或工作流框架。

模型配置、收藏、内置模型隐藏清单与凭据的读改写使用同一权威数据库连接进行原文比较后原子写入（CAS）；其他进程已修改时明确拒绝，不覆盖、不自动重放凭据回调。数据库中某一行不是合法 JSON 或顶层结构非法时，读路径按未配置处理并在配置页给出告警（启动与页面都打得开，用户有自愈入口），写路径明确拒绝——不知道原值是什么就写新值等于静默丢弃用户数据。派生模型文件仍有跨进程陈旧窗口，不能把权威库防丢更新等同于各进程 SDK 实时同步。

## 会话操作与断线恢复

- 左侧每条会话框内右侧提供中性色铅笔重命名、垃圾桶删除图标；无需切换会话即可操作。长标题使用省略号，图标保留固定空间，悬停可查看完整标题。删除确认默认聚焦取消，危险按钮及悬停均为红色；弹窗复用暗色边框与背景。
- WS 初次连接失败或断开后按 1、2、4、8、15 秒间隔自动重试，成功后重置；保留草稿并恢复会话快照。连接正常时不轮询，手动重试不创建并发连接。

内部子任务完成通知用于唤醒主代理，送达后以独立通知条展示，不伪装成用户消息；待送达时不显示在可撤回队列中。任务卡片与结果读取保持不变。

卸载入口通过显式传递服务操作避免模块循环等待；若旧版出现 `unsettled top-level await`，请使用上文手动卸载步骤；旧包名安装必须先完成「从旧包名迁移」，不要直接覆盖安装。

## SQLite 配置与管理存储

Axiom 使用数据目录中的 `axiom.db`（Node 内置 SQLite，WAL 模式），保存会话管理状态、任务与通知、全局默认与各目录配置、模型与明文凭据、收藏、内置模型隐藏清单、远程访问配置和守护维护记录。不需要安装数据库服务或手动编辑 Pi 配置。Pi JSONL 保留模型会话原文与重启恢复；数据库不重复保存主会话完整消息。

动态数据拆为 `sessions`（元数据）、`session_events`（压缩/重试）、`tasks`（单任务）三表；`store` 只保存小配置、凭据与迁移标记。改标题只更新会话元数据，通知确认仅修改单任务标志，不逐 token 写库。旧库首次打开时幂等清理已废弃的 `summaries` 表、`main_turn` / `memory_turn` / `progress` 列与 `summary_trigger` / `progress_delivery` 事件行，按实际表结构自检，不靠迁移标记，新库不执行任何清理。同一次开库还会给老库里没有身份的事件行补一个稳定 key（早期版本的事件行允许不带 id，读出来没有身份，重写会多出删不掉的重复行、撤回又删不中），补完读、写、删三条链路才认得同一行；已有身份的行不动，新库零行受影响。

迁移读取旧 `store.sessions` 与更早的会话 JSON，成功后新表是唯一动态数据来源，不双写、不支持旧版运行。首次实际导入前自动生成一致性备份 `axiom.db.pre-store-migration.db`（先写唯一临时文件，完整成功才发布；失败不导入、不标记）；逐会话事务与完成标记确保重跑不覆盖已迁移数据，重启不再读取已迁移的大 JSON；坏文件/坏行保留并警告，修复后可以重试。JSONL 缺失时会话仍在列表中，打开时报错，不创建空历史覆盖。具有持久化历史的运行中子任务重启后从原上下文继续，不重新发送已落盘的任务输入；已完成或用户主动取消的不自动运行。旧迁移源保留用于人工备份；删除会话仍按既有删除流程清理其关联文件。

模型配置页直接保存到数据库（唯一权威，models.compat.json 只是可重建的派生镜像，不双写）；一次导入门闩按来源独立：每个来源只看自己的迁移标记，models.json 与 auth.json 互不牵连。模型权威一经存在（页面配置或既往导入）且该来源没有遗留告警，就补打迁移标记退出导入来源——此后旧文件不再被读取，清空权威也不会复活导入，陈旧导入告警同时清除；仍有告警的来源保持窗口开着，坏文件/坏结构只去重告警、不打完成标记，修好后可重导（importModels/importAuth 都不覆盖已存在的权威行，重试只补缺失条目，UI 新值不会被旧源覆盖）；收藏来源结构非法同样记录告警，不静默跳过。收藏读取如实反映库内条目，每组 200 条上限只拦新增，超限的旧数据仍可被逐条取消，不在读取时静默截断。若入库成功但派生文件或 SDK 应用失败，页面保留新指纹并显示“已保存，但尚未应用”，通过“重试应用”重读并应用当前数据库配置，不重放保存或删除。`models.compat.json` 是为 Pi SDK 自动生成的派生文件，可重建，勿手改。API Key 明文存储，页面和普通接口遮挡密钥；备份应保护数据库、WAL 与派生文件，建议停止服务后连同 JSONL 一起备份。POSIX 在打开数据库前收紧主库与已有 WAL/SHM 权限至 `600`，新建侧文件继承主库权限；不改共享父目录。Windows 的 chmod 不替代 ACL，请将数据目录放在仅授权用户可访问的位置（自定义目录尤其要核对继承权限）。Pi 插件/技能资源与订阅登录入口继续沿用 SDK 能力，并非所有 Pi 文件都已移除。

### 独立前端开发服务器（Vite）

两个终端分别运行 `npm run dev`（隔离后端，4320）和 `npm run dev:web`（前端，**http://127.0.0.1:5173**）。前端脚本不启动、不停止、不重启后端；不要混用 localhost 与 127.0.0.1，代理严格校验开发页面 Host/Origin。Vite 固定为开发依赖 **8.3.0**，Node 要求与项目 engines 相容；`npm start` 和正式静态路径不依赖 Vite，不需要生产构建。

```text
浏览器 -> 5173 Vite -> /ws、/health、/service/stop -> 4320 隔离后端
           |
           +-> Vite 自带开发 WS（仅 CSS 热替换，不承载业务事件）
```

**当前交付是 CSS 热替换，不是无损 JS HMR。** CSS 保存后不刷新页面，草稿与阅读位置原地保留；普通 JS/HTML 的整页自动刷新统一暂停，终端会提示。手动刷新仍会丢失内存草稿/附件/阅读位置，请先复制或保存；尚未实现刷新持久化，因此没有启用自动刷新，不能把这一阶段称为完整热加载目标已完成。新增文件仍需登记生产 server.js 静态路由。后端源码修改走原有安全重启流程。

安全边界：Vite 仅绑定 loopback，HTTP/业务 WS 在代理改写头之前拒绝非同源 Origin；生产鉴权/Host/Origin/CSP不变。仅开发维护服务允许固定5173 Origin（token仍必需）；开发CSP仅为CSS注入允许 inline style，并允许loopback维护端口，不允许 inline script/unsafe-eval。Vite仍是开发工具，不应向局域网或公网暴露。

验证：`node --test tests/dev-vite.test.js tests/dev-assets.test.js`；`python tests/dev-vite-ui.py`（串行运行，会临时追加并 finally 恢复本 worktree 的 CSS/JS）。后者验证真实 CSS 更新、草稿与页面身份保留、JS刷新暂停、隔离后端健康身份不变。
### 实时通信基础层

```text
app.js 权威归并/视图 <- public/transport.js（唯一业务连接）
                            | 原生 WebSocket，逻辑订阅不隔离物理带宽
sessions.js 事件 -> server.js -> src/transport.js（统一发送保护）
```

- 请求回执统一超时（默认 120 秒）、取消本地等待与清理；断线中的副作用请求标记结果未知，不自动重放。
- `subscribe(type, {sessionId, agentId}, listener)` 返回退订函数；异步监听者提交前使用 `context.commit`，退订或销毁后不再提交。权威同步归并失败不推进 seq，停止归并并重新恢复。
- attach/create/import 回执到达即合上事件闸门，渲染成功后提交快照并按到达顺序补放；实例变化清除旧水位。没有额外优先级发送队列，同会话正文与完成事件不逆序。
- 收发默认上限 32 MiB，快照事件队列最多 10000 条，等待请求最多 256 个；广播与删除通知共用保护，慢客户端单独断开。超大单帧关闭码 1009 停止自动恢复；连续恢复失败最多自动重试 5 次（1/2/4/8/15 秒），之后需手动连接，长时间维护后亦然。
- 当前全量快照超过 32 MiB 会进入受限状态，手动重试不会缩小快照；缓解手段是上下文自动压缩（折叠段不下发），不是分页。未宣称大历史/真实高负载验收通过。05 负责历史挂载与滚动，06 只消费权威归并正文，不自行建立连接。
- 专项回归：`node --test tests/realtime-transport.test.js tests/snapshot*.test.js`，使用假连接与受控快照，不调用模型。

压缩摘要按需展开：摘要卡默认折叠且不加载段内原文，点开才用 `session.compaction.messages` 取一次（结果缓存，失败可重新展开重试；切换会话后迟到的响应丢弃）。取回的原文按时间序插回「原文对照」面板，段内子代理记录补进对应任务弹窗已有内容之前，段内重试卡按锚点归位到摘要卡内；实时压缩刚折叠的段落原文还在页上，展开无需再取。主消息锚点保持时间顺序，避免后续实时重试定位错位。

从独立 JSONL 恢复历史时，子代理消息按委派结果中的任务 ID 放回对应执行段，不再集中追加到主回答之后，避免最近一页全是子代理而看不到主会话回答。无委派关联的旧子历史保留在前部，不猜测归属；主子消息仍可连续上滚查看，原始 JSONL 不改写。

### 摘要 JSON 兼容与诊断

任务状态摘要接受裸 JSON，或唯一完整的 JSON/无语言 Markdown 代码块；不从解释文本抽取 JSON，不补全截断内容。结构、逐字引用与约束授权校验仍严格执行。格式错误提供格式分类与字符数，非法结构归类为 SUMMARY_SCHEMA_INVALID。

有持久会话文件时，压缩终态旁写 `<session.jsonl>.compaction-diagnostics.json`，保存本进程最近至多 5 次终态的阶段、时间、错误代码和输出长度，不保存提示词、摘要正文、引文或供应商错误原文；重启后可直接读取文件排查，但 UI 不自动恢复它，后续终态会用当前进程记录覆盖。诊断写入失败不影响压缩。

开发排障：页面一直显示「连接中」时，检查浏览器静态模块请求是否 404；新增 public JS/CSS 必须登记 src/server.js 路由并重启服务。任务清单资源为 /todo.js 与 /todo.css。

复用快照只减少读取，不免除清单维护：用户提出新的多步骤工作（例如排查转修复）时，应先新增对应事项，再执行并更新进度。
