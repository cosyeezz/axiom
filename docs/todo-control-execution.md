# Todo 长会话控制：执行基准

## 用户确认的边界

- 主 agent 通过工具创建、读取和维护清单；子 agent 不注册 Todo 工具、不接收 Todo 上下文、不维护主清单。
- SQLite 是唯一权威存储。UI、工具返回和请求概览均是投影，不使用压缩摘要重建任务真相。
- 最多两级，支持大清单、执行中拆分、待办编辑/重排、状态更新、不再需要的事项删除。删除保留审计但不阻塞完成。
- 输入框上方展示清单，可折叠为一行 SVG 图标加数字；展开偏好在浏览器全局持久化，不按会话区分。
- 原生压缩只负责上下文缩减，停止生成与注入任务状态文档。历史状态可查看，不转换成可自动执行的 Todo。
- 用户补充：直接调用SDK原生compact并传customInstructions参数，仅增加折叠标题/简述要求；不自建摘要协议、不生成facts/引文核验、不做失败回退。展示字段缺失只使用默认UI文案，不重试摘要。异步仍使用不abort主agent的底层compact；保留冻结输入、窗口检查、取消和原文持久化提交安全。

## 数据与工具

- 主 agent 使用 todo_read 与 todo_update。修改为版本校验下的批量原子操作；稳定 ID，不用位置序号标识事项。
- 事项状态：pending / running / done / blocked。最大两级；父项由子项汇总，整体检查需显式列为子项。
- 支持 add / edit / status / move / delete / reopen；完成事项不静默改写成另一件事。
- 主 agent 固定执行约定指明读取入口；每请求注入轻量概览而非全部大清单。
- 子任务结果经正常通知返回，由主 agent 检查并更新事项，不由子任务自证主任务完成。

## 自动推进

- 自动推进状态与事项状态分离：enabled / paused / completed。
- 仅主会话空闲、无活动子任务（含starting/wrapping/stopping/summarizing）、无待通知结果、无排队输入、无待回答问题、无压缩/关闭/配置操作时督促可执行未完成事项。
- 用户停止优先，普通输入不得自动解除暂停；明确恢复才重新启用。重启暂停，要求核对实际产物。
- 只剩blocked事项时不循环唤醒；连续失败/无进展需有界暂停。状态编辑本身不是产物完成证据。
- 复用既有安全调度接线，不允许Goal和Todo两套推进器同时驱动同一会话。

## 验证与交付

- SQLite恢复、隔离、版本冲突、原子性、父子汇总、删除/重排/重新打开。
- 仅主工具可见；主请求概览与读取入口、子请求不泄漏Todo。
- 空闲推进、停止冻结、重启暂停、问题与子任务多阶段守卫、防重复/空转。
- 原生压缩无stateDoc依赖，失败仍保留原文；旧记录可读。
- UI桌面/窄屏、SVG数字折叠、全局偏好恢复及实时更新。
- 同步README/devlog，完整验证后按仓库约定提交、推送、合并master；保留用户已有改动，不重启服务。
