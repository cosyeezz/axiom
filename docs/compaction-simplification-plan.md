# 压缩简化与过程展示：定稿方案

> 状态：本轮已实现统一生成层回退、内联摘录核验、精确回读及可观察展示；真实供应商两轮持久应用／重开和桌面／窄屏浏览器验收通过。测试结果及真实验收边界见文末。
>
> 本文替代此前“独立 facts 数组＋所有内容引用编号”的讨论稿。下一阶段按本文验证接线与实施，不整体合并旧实验。

## 1. 定稿结论

**Pi 原生摘要规则与流程 + 模型自选重要内容的内联原文摘录 + 程序核验并替换原消息 ID + 按 ID 精确回读 + 可观察的一次原生回退。**

- 不再使用八类 JSON 任务状态作为压缩成功前提，不新增状态迁移或授权协议。
- 不注入输入消息编号，不要求逐消息总结、逐句引用或全覆盖引用。
- 不输出独立 facts 数组。内联摘录承担原来证据数组的逐字校验职责。
- 摘要生成无工具，主会话需要细节时才调用原文读取工具。
- 沿用原生摘要格式、内容取舍、连续更新规则，不叠加第二套摘要组织指令。
- 会话界面不做分页拉取。读取与展示可以分离，但不以分页解决切换性能。
- 实际请求可查、完整正文生成可见、引用处理可核对、应用结果明确、回退分尝试保留。

此前审查文档中的优化不再照单实施：只有支持本定稿的项目才继续，补救被弃用复杂协议的项目不再作为前置工作。

## 2. 原文、摘要与展示的职责

### 完整原文

Pi JSONL 仍是执行与恢复的权威记录。复用已有 `.history/` 归档及其增量同步，不另建第二个执行权威。

- 原始消息按持久 ID 保存，压缩不删除、不重编号。
- 原始消息与生成摘要分开；不把生成摘要当作用户原文证据。
- 工具关联、角色、分支和附件引用保持完整。
- 文本匹配使用确定性的原文文本投影，不跨消息拼接证据，不对图片等非文本内容虚构文字。
- 分支与访问权限参与来源范围限制；不是扫所有会话文件，命中任意一处就算有效。

### 摘要上下文

沿用原生“上一份摘要＋本轮待压缩内容”的累计摘要机制，不每次重发全部历史。近期原文保留与合法切点尽量复用原生能力。

### 界面数据

列表已有元数据层；冷切换仍存在完整 JSONL 解析及时间线转换。未来可维护可重建的 Axiom 展示投影，减少重复工作，但不替代 Pi 写入、不引入会话分页；性能改造另行测量和实施，不阻塞压缩简化。

## 3. 原生基座边界：已核实与待验证

已核实 SDK 0.85.1：

- 原生已有固定摘要章节与连续更新提示，附加指令追加在原生指令之后。
- 原生序列化没有消息 ID；本方案不再需要给输入注入 ID。
- **原生序列化对每条工具结果保留前 2,000 字符。** 本方案不为引用功能改动这项原生行为；它不是旧 OP 折叠。不得宣称原生摘要实际看到了全部工具输出。
- Axiom 自己增加的头尾分配、任务状态和额外截断不作为新方案基础。不保留“让无工具摘要模型自行调用 history_read 补读”的无效指令。
- 摘录只能来自模型实际看到的内容；程序可以使用完整原文核验，但这不代表模型看过未发送部分。
- 原生手动压缩能接收附加指令；自动压缩和 split-turn 前缀摘要不能假定自动继承该指令。需验证受支持的最小适配方式。
- 原生底层调用可获得流式返回，但常规压缩事件只有开始／结束等信息。观察层可以从实际调用处获取请求和正文，不应重写摘要算法。

实施门槛：验证首次、连续及 split-turn 的附加指令、提交前摘录校验、取消与原生回退接线。不能因为简单手动路径可用就宣称全部入口覆盖；也不能为补这个缺口回到八类状态协议。

## 4. 最小附加提示

保留原生提示，仅追加：

> 保持原有摘要格式与规则。对你认为需要保留原始依据的重要内容，在对应句后附短的、连续的逐字原文，格式为 `[原文：“…”]`。不要为了引用而增加摘要内容，不要求逐句引用。保留旧摘要中的相关内容时，沿用其已有来源标识。

补充边界由协议／校验说明承担，不再长篇重述摘要规则：

- 新摘录不得用省略号拼接不同片段，不改写引文；标记只在正常正文位置解析，不把代码示例中的标记当成引用。
- 普通内容可以没有标记；没有摘录不自动判定失败，但也不能显示“全部事实已核验”。
- 旧内容仍相关时保留已有来源，改写不应丢掉来源；删除无关内容时可一并删除引用。
- 一句确需多个来源时允许多个消息 ID，不要求为所有讨论过程累积引用。
- 新增结论不能只挂旧 ID 冒充新证据。程序不能仅靠 ID 存在判断语义正确，不增加新的复杂状态机来假装解决此问题。

## 5. 摘录核验与消息 ID 替换

示例：

```text
模型原始输出：
用户禁止会话分页拉取。[原文：“不做分页拉取会话”]

程序处理后：
用户禁止会话分页拉取。[原始消息ID]
```

处理规则：

1. 确认本轮原文覆盖已可靠归档。
2. 在当前允许引用的原始消息中逐字匹配每段内联摘录；不依赖模型计算行号或字节范围。
3. 单一命中：替换为真实持久消息 ID，内部记录匹配位置。
4. 多条消息命中：不任意选第一条；保留可访问的候选消息 ID 并在处理结果中说明歧义。角色信息不得丢失，不能把助手复述自动当作用户决策证据。候选过多等无法清晰处理的情况应明确报校验失败，不无限膨胀引用。
5. 无命中、摘录标记损坏、虚构旧 ID：增强候选失败，不删除坏证据、模糊修复或转成普通编号放行。
6. 旧 ID 仅允许来自已接受摘要的有效引用，检查其仍可访问；不要求重新生成摘录。
7. 保存模型原始输出、匹配结果和替换后的最终摘要。来源和摘要可靠保存后才标记为已应用。

消息 ID 始终直达原文，不形成“新摘要→旧摘要→原文”的链。实际标记语法须与普通 Markdown 链接／方括号区分；选择一个明确格式并提供解析测试，不以任意方括号内容猜测 ID。

**能力边界：**匹配证明摘录存在，不证明摘要对摘录的解释正确；没有引用的摘要内容不做这项核验。模型可能遗漏重要事项，必须通过质量验收关注，不能将引用成功率等同于摘要质量。

## 6. 原文读取工具：精确定位，不提供跨消息搜索

复用 `history_read` 的底层归档读取能力，面向主会话收敛为消息 ID 与关键词。新协议不暴露跨历史 `history_search`；旧记录与其他使用者如何兼容需迁移验证，不能声称当前工具已下线。

单项语义：

```json
{"messageId":"原始消息ID","keyword":"分页"}
```

同一工具可以小批量读取：

```json
{"sources":[{"messageId":"idA","keyword":"分页"},{"messageId":"idB","keyword":"展示"}]}
```

最终参数 schema 可统一为一项或多项列表，不强求两种冗余入口。建议默认批量最多 3 条，作为待测试的实现常量，不是新增产品流程。

- 当前会话范围＋消息 ID 精确定位；不存在或无权访问，单项明确报错，不搜索其他消息替代。
- 关键词采用字面文本匹配，不使用额外模型或正则检索。
- 消息约 2,000 字符以内：完整返回。
- 超长消息且命中：以首次命中为中心返回前后合计约 2,000 字符，可适度对齐换行；报告命中次数，不拼接远隔片段冒充连续原文。
- 未命中：返回头尾各约 1,000 字符，明确标注中间省略。
- 2k 指字符量，不是 tokens，不是前后各 2k；实现明确 Unicode 截取规则，不切坏字符。
- 返回角色、消息 ID、原文长度、返回范围、命中情况及是否完整。批量结果分消息呈现。
- 不提供全局搜索或工具分页游标；需要时主会话换更具体的关键词或少量分次调用。

已接受的取舍：没有消息 ID 的内容不能通过本工具直接召回；重复关键词的后续命中可能暂不能准确取出。不为覆盖所有长文本场景继续扩大接口。

## 7. 有界原生回退

```text
确认原文归档 → 原生基座生成增强摘要 → 摘录核验与 ID 替换 → 应用
                                      │失败
                                      ↓
                             最多一次未增强原生压缩
                             成功应用 / 失败停止
```

- 原生回退不附摘录要求或任务状态协议，不重复进入增强钩子，不复用失败候选。
- 用户取消、归档不完整、分支失效、无合法切点、提交失败或提交不确定不能通过回退绕过。
- 原生也失败就保留原文并报告，不无限重试。
- 回退标记“未进行原文摘录核验”，不以总成功率掩盖增强频繁失败。
- 生成错误具体是否可回退、限流是否应等待等按有限错误分类处理，不重新建设大型恢复状态机。
- 自动、手动异步、手动同步已统一为生成层最多一次回退，复用同一冻结切点和提交屏障；不调用会中止主代理的 session.compact。

## 8. 过程可观察性：每次操作包含独立尝试

### 请求区

展示模型、增强／原生回退模式、输入覆盖范围，以及**实际发出的模型上下文**：系统提示、原生摘要指令、附加指令、上一份摘要和本轮输入。

- 采集实际请求，不能以模板重建或完整档案冒充实际发送内容。
- 阅读视图可分区，但必须保留实际组合顺序与完整原始请求文本；不能靠不可靠文本拆分伪造“真实请求”。
- SDK 原生截断在此如实可见。
- 不采集凭据或鉴权头；用户会话正文可能含敏感信息，受会话访问权限保护。脱敏时标注这是脱敏展示，不声称逐字完整请求。
- 大段历史默认折叠、按需载入，不随每次流式事件重复广播。该按需查看不等于会话时间线分页。

### 生成区

- 显示完整累积的模型正文，不能只保留末尾 1,500 字符。
- 无正文时显示“已发送／等待正文／用时”，不使用假进度条。
- 节流传输和渲染，不丢前文；不显示或伪造隐藏内部推理。
- 若 SDK 对一次压缩有多个实际请求（如 split-turn），按子请求分别显示，不能交错拼接成一段流。

### 结果区

- 模型原始摘要（含内联摘录）。
- 摘录处理明细：命中、未命中、多处命中与消息 ID 映射；无摘录明确显示 0 项，而不是“事实全部通过”。
- 最终应用摘要（已替换消息 ID）。
- 可靠保存／应用状态与失败阶段、原生提供的压缩统计。

### 回退记录与持久化

尝试 1 的请求、输出和错误不被尝试 2 覆盖。刷新后能够查看已完成尝试的请求记录、原始结果与最终结果。

详细记录属于受保护的会话产物，不混入通用错误诊断日志，不自动提交仓库。不重复保存每次流式快照；优先引用不可变请求产物并在完成时保存结果。记录保留／删除遵循会话生命周期，不能留下无限增长的孤立敏感文件。

## 9. 展示定稿：Markdown 预览与原文对照

不能继续把全部提示、输入和输出堆进一个文本框。复用现有压缩面板及安全 Markdown 能力，避免新增平行日志控制台。

### 信息布局

- 顶部：阶段、用时、模型、当前尝试、成功／失败状态。
- 请求：系统指令、摘要指令、历史输入分区；长内容折叠。
- 生成：完整正文流。
- 结果：模型原始输出、引用处理、最终应用摘要分区或切换查看。
- 增强尝试与原生回退有清楚的独立标题和时间，不混成一次成功。

### 阅读与原文模式

- 提示词、生成结果、最终摘要支持 **Markdown 预览／原始文本** 切换，并提供复制原文。
- 阅读模式保留标题、列表、引用、表格、代码块的层次；不得修改提示词内容、重排实际指令或自动润色摘要。
- 非 Markdown 的角色边界、XML 类标签、消息分隔符用明确文本／代码容器保留，不允许渲染后消失。完整原文模式始终可查。
- 复制基于源文本而非 DOM 文本。脱敏展示的复制亦为脱敏内容，并明确提示。
- 未完成的 Markdown 流式块使用安全稳定的渲染策略；完整源文本持续保留，完成后重新渲染。
- 模型／用户内容一律不可信：安全渲染，禁止脚本、事件属性及任意 HTML 执行；不自动请求远端图片等外部资源；代码与链接安全处理。

### 可读性与交互

- 正文使用常规阅读字体，不把整份提示词显示成等宽代码；代码块才用等宽，带语言标识与复制反馈。
- 代码和表格在自身容器横向滚动，不撑破面板；长 ID／路径可换行或有可展开的完整值。
- 默认只在用户位于底部时跟随流式输出；用户向上查看即暂停跟随，提供“回到底部”。切换原文／预览尽量保持各自阅读位置。
- 稳定滚动条占位，容器滚动不拖动背景；减少动态效果偏好下关闭滚动动画。
- 折叠、切换和复制支持键盘及可见焦点；状态不只靠颜色表达，窄屏不用难以阅读的强制双列。

### 项目设计约束

遵循 `.pi/skills/design/styles/linear.app.md`，复用项目 `public/style.css` 现有双主题 token，不硬编码一套暗色主题：

- 表面层级与 1px 边框表达分区，不新增阴影、渐变或大面积强调色。
- 薰衣草强调色仅用于必要交互强调与焦点，不用作大块背景。
- 正文沿用项目阅读字号，代码沿用现有 `.code-block`，表格沿用滚动容器。
- 深浅主题、错误状态、空态、复制反馈和折叠态一起验收。

## 10. 最小实施顺序与验收

1. 在隔离历史副本验证纯原生生成、应用、重开，建立基线。
2. 验证原生附加指令及提交前处理接线，覆盖首次、连续、split-turn；不修改 SDK 私有内部状态硬套设计。
3. 接入内联摘录核验、消息 ID 替换与精确读取。
4. 接入只观察的请求／流包装，确保请求次数、取消、重试和计费不被观察层改变。
5. 实现安全 Markdown 与原文对照，最后验证有界原生回退。

验收必须区分代码测试、模拟服务与真实供应商结果：

- [ ] 原始消息、工具配对和附件可恢复，重复同步幂等。
- [ ] 摘录成功／不命中／多处命中／损坏标记处理正确；无摘录不假报核验成功。
- [ ] 多轮压缩后旧 ID 仍直达原文，相关引用保留、无关内容允许遗弃。
- [ ] 读取权限、短消息、长消息命中／未命中、多来源批量、Unicode边界均覆盖。
- [ ] 真实提示内容与实际请求一致，脱敏明确，没有泄露鉴权信息。
- [ ] 正文超 1,500 字符仍完整；多请求不混流，刷新可查看已完成记录。
- [ ] 原始摘要与最终摘要均保留；回退不覆盖失败尝试。
- [ ] Markdown安全、原文复制、代码块、长表格、窄屏及滚动不跳动通过验收。
- [ ] 取消／归档故障／提交不确定不回退，原生失败不循环。
- [ ] 完整历史副本至少两轮实际应用及重开成功。
- [ ] 同一历史对比纯原生与增强：重要要求／未完成事项不遗漏，不变流水账，不因证据而过度冗长，后续任务能正确继续。

真实请求次数与费用有界；不以单次生成或引用核验通过宣称恢复可用。经验证后按项目约定同步、提交、合并、推送，不擅自重启活动会话服务。
