## 1. 目标与背景

目标：Electron 是正式桌面版唯一后端生命周期管理者，使用随包固定的独立 Node 直接启动业务 worker。页面、可选能力或单个会话失败不得被误报为整个后端断线。

当前仓库 `desktop/pake.json` 与 `.github/workflows/desktop.yml` 是 Pake 壳；用户提及的 Electron 仓库和分支尚未定位。先确认它的主进程、打包资源、退出语义和更新器，禁止另建第二套桌面端。

当前 `scripts/service.mjs` 是 supervisor，管理 `src/main.js` worker；worker 已有 `service.ready` IPC，`/health` 已有实例信息；慢启动、退出与恢复已有部分实现。现有相对 `AXIOM_HOME` 处理和安全停止逻辑应复用，不从零重写。

## 2. 范围与非目标

本组负责：单实例归属、启动/就绪/退出、有限崩溃重试、可选业务失败隔离、开发后端安全重启。

不负责：包下载、版本选择、签名、安装目录替换（01）；WebSocket 消息路由（03）；页面分区（04）。不新增修复按钮，不把 npm install、npm ls、逐依赖 import 校验放进用户启动链。不默认使用 Electron 内置 Node，不叠加完整旧 supervisor。

旧 CLI 模式可以保留原 supervisor，但它与桌面模式不能共同管理同一实例或并发写同一用户数据。

## 3. 最小运行链

```text
Electron 单实例与数据目录归属确认
  -> 随包 Node 启动 main.js worker
  -> 必需数据库与基础 HTTP/WS 可用
  -> 经专用 IPC 回传 ready
  -> 打开业务页面
  -> 模型目录、会话历史、远程能力按需加载
```

- 在创建子进程前，以调用方原始 cwd 解析 `AXIOM_HOME`，传绝对路径；安装资源路径也显式传入。不能通过简单 chdir 改变数据位置。
- 就绪必须验证本次启动令牌、instanceId、bundleVersion、地址与子进程身份，不能仅看某端口返回 HTTP 200。
- 必需的数据库无法安全打开时不能谎报 ready；Electron 外壳仍能显示脱敏错误和手动更新入口。
- 不因模型不支持、坏会话、远程配置失败关闭基础连接；打开该能力时局部报告。
- 保留 Node 版本硬门槛与信任边界校验，删除的是重复预检，不是必要错误处理。

## 4. 拟议契约（非已有 API）

| 接口 | 输入/输出与保证 |
|---|---|
| `startBackend({bundleRoot,bundleVersion,dataRoot})` | 使用绝对路径，返回与本次启动绑定的 ready；并发调用共用启动结果 |
| `getBackendState()` | starting/ready/busy/stopping/stopped/failed 和脱敏原因；不通过猜端口判断归属 |
| `requestStop({reason,mode})` | reason=quit/update/dev；mode=wait 或用户已确认的 cancel；返回真实 stopped，不将超时当成功 |
| ready IPC | 启动令牌、instanceId、bundleVersion、地址、协议版本；仅接受受管子进程消息 |
| stopped IPC/exit | 保存完成并确认相关受管进程退出；缺失确认不得让01替换目录 |

01 只请求安全停止和读取就绪事实；02 不选择新版本或替换文件。兼容01的 `{stopped,exitCode}` / `{ready,instanceId,bundleVersion}` 返回。

## 5. 状态机与失败安全

```text
stopped -> starting -> ready <-> busy
               |         |        |
             failed      +--- stopping -> stopped
```

- Electron 单实例机制之外，还需按数据根目录核对旧服务所有权；不同端口不等于可以同时写同一数据。遇到未知进程不杀、不接管，给明确诊断。
- 复用旧 supervisor 的退避与重试上限思路，只留一个重启负责人。持续失败进入 failed，不无限重启；不能凭进程退出自动重复用户任务。
- 普通关窗与显式退出须按现有Electron产品约定确认；文档不预设关窗必停或必留。
- 有任务时提供等待完成或明确取消后退出；取消后必须等 SDK 保存与后端退出确认。超时停留在错误状态，不能悄悄强杀后宣称保存成功。
- 系统关机不保证有足够清理时间：依赖既有持续持久化并报告中断，不承诺绝不丢内存增量。
- 渲染器崩溃不结束后端任务；主进程异常退出的孤儿回收策略在目标平台验证，重开时先核对归属，不能启动第二写入者。
- 不用全局 uncaughtException 吞掉不可恢复错误继续写库。

## 6. 开发后端重启

与04前端开发服务分离。监听后端源文件，合并连续保存；空闲时走同一个安全停止流程后重启。忙时记录待重启，不自动取消任务。监听生成物和数据目录应排除，避免循环重启。可以使用标准库监听，但需覆盖目标平台事件差异。

前端刷新不重启后端；生产包不包含开发监听入口。

## 7. 文件归属与独立开发

本组新增生命周期模块，建议 `desktop/backend-lifecycle.*`，具体路径等待Electron仓库定位；先做纯模块与假子进程测试。不要为未知Electron项目创建正式壳。

`src/main.js`、`scripts/service.mjs`、共享协议和Electron主入口由集成负责人统一接线。本组提交接线清单，不与01同时改 service.mjs。可以抽取已存在的纯退避/路径逻辑，不保留双层正式管理。

## 8. 实施步骤

1. 定位Electron并记录平台/打包/退出约定；核对所有启动和重启调用方。
2. 用假子进程实现 start/ready/stop 状态机及实例令牌校验。
3. 复用绝对数据路径与保存退出逻辑，明确旧CLI迁移门禁。
4. 集成worker IPC，移除桌面路径旧守护/独立npm更新职责。
5. 按需能力局部失败与开发重启接入。
6. 在隔离数据目录完成跨平台故障测试，再联调01成品安装包。
