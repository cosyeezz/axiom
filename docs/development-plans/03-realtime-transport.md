# 03 实时通信与事件分发：独立开发任务书

日期：2026-09-15。待实施方案；本轮未修改产品代码、未执行实现测试。

## 1. 目标与现状

保留浏览器原生 WebSocket 与 Node `ws`，统一连接管理、事件订阅、回执和错误边界；限制积压，避免正文事件触发无关分区更新。不迁移Socket.IO、不按区域开连接、不引入独立网关。

入口：`public/app.js` 的 ws.onmessage/pending/acceptEventSeq/snapshotQueue，`src/server.js` 的 WebSocketServer/attach/broadcast/send，`src/sessions.js` 的 emit/snapshot/listeners，`src/protocol.js` 的命令校验。

当前代码已有每会话seq、快照水位、快照期间事件缓冲、退避重连和慢客户端发送缓冲保护。不能把这些当全新功能重写；实施前核对所有send与listener调用方，统一覆盖广播及删除事件等旁路。

## 2. 边界与核心不变量

```text
权威业务状态 -> 会话有序事件 -> 发送边界 -> 一条WS
                                         -> 客户端接收/归并
                                         -> 定向订阅通知
                                         -> 各区自行调度绘制
```

- 连接由通信层唯一持有，分区不能close或自行重连。
- channel是应用路由标签，不是独立TCP队列、线程或可抢占带宽。
- 权威数据归并与UI通知分开；一个UI监听者失败不影响其他监听者或连接。权威归并失败则停止推进该会话水位并请求受控同步，不能吞错后继续假装完整。
- 保留每会话seq作用域；agentId不另建排序水位。后端重启后的epoch/实例变化须使旧水位失效并重新快照，不能跨实例直接比较seq。
- 06消费归并后的正文，不订阅原始delta做第二份reducer。05负责历史快照一致性，03不自造另一套恢复协议。

## 3. 拟议最小接口（非已有 API）

```js
subscribe(type, { sessionId, agentId }, listener); // 返回unsubscribe
request(command, { signal });                    // 匹配单次回执
getConnectionState();
```

字段沿用现有type/sessionId/agentId，不为逻辑频道批量改消息信封。消息身份messageId尚需05与集成负责人统一，03不把seq当消息ID，也不假定每条消息有runId。

- request内部创建连接内唯一id，pending有超时与数量上限；取消本地等待不代表服务端业务取消。
- 断线后拒绝未完成请求并标明结果可能未知；禁止自动重放prompt、取消、保存配置等副作用操作。
- 迟到/重复回执不二次resolve。每个正常已接收请求按现有协议回复一次；不能宣称跨崩溃网络恰好执行一次。
- 异常回调要可见报告、脱敏，不空catch；异步监听拒绝也须隔离。
- 退订后旧异步结果通过订阅generation失效，不能覆盖新会话。
- 第一版不新增event.ack、stream.suspend、stream.resync。只有测得必要且05恢复契约完备时另行扩展。

## 4. 优先级：保序比抢占重要

| 级别 | 内容 | 调度约束 |
|---|---|---|
| P0 | 控制请求、独立回执、连接状态 | 优先安排尚未send的独立消息 |
| P1 | 实时正文、工具事件、会话运行与终态 | 同一会话严格按seq，不让完成越过正文 |
| P2 | 配置目录、历史分页等后台读取 | 按需、有界，避免大包，不能永久饿死 |

调度比较的是**不同独立流的队首**，不能将同会话事件按等级拆散后重排。即使某终态逻辑很重要，也要等它之前的正文被应用。已交给socket的消息不可抢占；巨型历史需05分页或独立内容接口解决，不靠channel解决。

先统一发送边界并测量，再决定是否需要队列调度；没有积压时直接发送，不引入无条件复杂队列。

## 5. 有界缓冲与慢消费者

同时记录待发送字节/条数、最老等待时间、socket bufferedAmount、客户端待归并量。阈值集中为少量可测试参数，初值以当前机制和隔离测量为依据，文档不凭空承诺延迟上界。

- 所有发送路径走相同保护，包括广播；单客户端慢不得阻塞所有客户端。
- 连续同身份、同字段文本可以无损合并，但第一版优先保持原事件不变，只合并前端绘制通知。若传输批处理，保留内部原seq；协议两端同时验证后启用。
- 不把所有toolcall_*当字符串拼接；部分事件是结构化补丁。不能跨正文/工具/终态边界合并。
- 完整状态快照可在语义证明后留最新值；正文、工具结果、请求回执不可静默丢弃。
- 超过安全发送上限时沿用单慢连接断开与权威快照恢复，不继续无限缓存。断开不取消服务端任务。
- 连续因恢复大快照再次超限时，暂停自动重试并明确显示连接受限状态，保留草稿/外壳操作；等待05有界恢复或用户明确重试。不能紧密循环重连制造新负载，也不让一次重试反复下载全部历史。
- bufferedAmount只证明本地缓冲，不能证明前端已应用。严格在途窗口/消费确认属后续按测量需要实施，不先造协议。

## 6. 最小重连与快照契约

```text
断线 -> pending变为失败/结果未知，草稿保留
     -> 有上限退避并避免并发连接
     -> 验证新实例与协议
     -> 只恢复当前必要订阅及快照水位
     -> 按序应用水位后的排队事件
```

不重跑所有配置初始化。配置按版本变化/缺失按需同步，不让配置目录读取阻塞对话恢复。实例改变必须重设对应epoch和水位。

05的分页首屏必须包含一致的snapshotId、实例/epoch与seq水位（命名由集成确定），首屏建立后才应用后续事件；历史页不能推进实时水位，过期页不能写入新视图。当前全量快照兼容路径可暂保留，但不得声称其已解决大历史积压。

## 7. 文件归属与独立开发

建议新模块：`public/transport.js` 管客户端连接/回执/订阅，服务端纯发送边界按现有复用情况放 `src/transport.js`。不要求为了对称创建两套框架。

`public/app.js`、`src/server.js`、`src/protocol.js`、`src/sessions.js`共享入口由集成负责人接线；本组提交调用点清单和契约测试。04只消费订阅，05提供快照适配器，06无直接通信依赖。

## 8. 实施顺序

1. 枚举所有send、listener、重连、pending调用方，记录当前队列与报文基线。
2. 用FakeWebSocket抽出客户端连接和pending，保持现有信封兼容。
3. 定向订阅与异常隔离；明确权威归并失败不推进水位。
4. 统一服务端发送保护，补齐广播旁路，测试慢单连接。
5. 与05接入有界恢复；与04接入分区订阅；仅在测量有益时启用保序优先调度。

## 9. 独立测试与验收

拟新增 `tests/realtime-transport.test.js`，执行 `node --test tests/realtime-transport.test.js`；文件尚未实现，本轮未测试。

使用假socket、假时钟、受控ready/close/send错误及内存快照源，无模型调用、无真实用户目录：

- 同事件两个订阅者，一个同步/异步失败不影响另一个；退订不会收到迟到更新。
- request超时/断线清理pending，副作用调用不重发，重复回执不重复完成。
- 正文seq=10、终态seq=11即使终态标高优先也不能逆序；跨会话可以调度队首。
- 重启epoch后接受新快照；旧会话异步页/回执不污染当前视图。
- 慢socket及广播都触发同一上限；快socket继续工作；连续恢复超限不会无限重连。
- 有界缓冲后最终正文与权威快照一致；若无法恢复必须明确失败，不宣称无损。
- 配置慢请求不阻断可用对话订阅；正文不通知模型区域。

真实验收串行降低网络/CPU处理能力，记录队列峰值、等待年龄、内存趋势、重连次数、停止响应和正文一致性。不要仅用平均吞吐宣称不卡顿。

## 10. 交付与非目标

交付模块、可运行测试、接线清单、序列/实例契约、慢消费者测量记录、README/devlog。

不加每会话socket、预留空频道、无依据固定连接数限制、永久事件重放库。保留输入校验、鉴权、Origin/Host限制、XSS与敏感信息脱敏；性能优化不能绕过它们。
