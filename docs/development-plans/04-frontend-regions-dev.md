# 04 前端分区与开发热加载：独立开发任务书

日期：2026-09-15。待实施，未改产品代码或执行实现测试。UI实施前读取项目design skill与对应规范，沿用现有token、布局和无障碍约定，不另造设计系统。

## 1. 目标和已知问题

页面固定分区，只更新真正变化的区域，不为分区更换React/Vue或引入通用状态框架。

代码入口：`public/app.js` 的 controls/options/refill/applyEvent/snapshot，`public/model-picker.js` 的 sync/syncAll/rerender，`public/index.html` 和 `public/style.css`。

已核对：controls横跨多类控件，末尾调用modelPicker.syncAll；model-picker.sync在菜单打开时触发重建，菜单渲染使用replaceChildren。正文不是每个token整页刷新，但无关状态同步可能连带重建打开的模型菜单。实施前grep全部调用者，避免只修某一事件分支。

## 2. 固定六区

| 区域 | 唯一负责 | 订阅变化 |
|---|---|---|
| 连接状态 | 连接提示、启动/断线可见反馈 | 连接状态 |
| 会话导航 | 工作空间、列表、标题、未读 | 会话元数据变化 |
| 对话展示 | 消息挂载、工具记录、阅读位置 | 当前会话归并数据 |
| 输入操作 | 草稿、附件、发送/停止 | 草稿、运行状态、权限/连接变化 |
| 模型配置 | 供应商、模型、思考等级 | 模型目录、选中配置、收藏 |
| 设置与详情 | 设置页、按需详情与子任务面板 | 面板打开及对应数据 |

分区是DOM与更新边界，不强制每区新建相同模板类。后台会话数据更新不意味着挂载后台DOM。设置中的模型选择器与输入区选择器可复用同一组件，但各自订阅范围明确。

## 3. 拟议接口与不变量（非已有）

各区提供必要的 `update(change)` 和 `dispose()` 或复用已有组件方法；不要求统一继承层。通过03的 `subscribe(type,filter,listener)` 获得定向通知，dispose取消订阅和局部监听。

- 全局连接、当前会话、配置和消息仍有唯一权威来源。局部只拥有展开/焦点/滚动/草稿展示等视图状态，不复制第二份消息reducer。
- 数据没变时update不操作DOM；仅按钮状态变化只改属性；只改变选择时不重建目录。
- 所有异步请求带当前会话/面板generation，切换后迟到结果不能覆盖新视图。
- UI回调抛错局部报告，不关闭WS。权威消息归并失败由03处理，不能用safeRegion吞掉后继续推进seq。
- 分区仍共享主线程，不宣称线程隔离；长历史与流式绘制分别由05/06治理。

## 4. 首个可见里程碑：稳定模型菜单

不等整页拆分即可先交付：

1. 给options/选中值/收藏/disabled建立明确变化判定，避免比较每帧新造的大对象。
2. 菜单关闭时只更新必要摘要；打开时若目录无变化保留菜单项节点。
3. 仅选中值或disabled变化就局部修改状态；目录确变才重建必要选项。
4. 必须重建时按稳定模型键恢复焦点和滚动，选项被删除时选择合理焦点并明确配置错误，不静默换模型。
5. 再逐项移除无关controls联动，保留兼容调用只到迁移完毕，不能让兼容层继续同步所有区。

验收：运行中打开模型菜单并滚动到中间，节点身份、焦点和scrollTop不变；收藏/删除/切换模型真实变化仍正确响应，键盘与读屏语义保持。

## 5. 开发热加载

优先评估成熟独立开发服务器Vite：仅devDependency，不进入正式Electron后端启动依赖，不新建业务WS的dev.reload协议或自造监听广播服务。

第一阶段目标：CSS热替换、HTML/普通JS自动刷新；原生JS模块若无显式热替换/清理边界，允许整页刷新，不能称无损HMR。后续确有需要才为局部模块实现accept/dispose，必须防重复订阅。

- Vite另用开发端口，将业务HTTP/WS代理至隔离开发后端；登录/Origin/Host/CSP不得为开发方便关闭生产校验。
- 清楚记录浏览器业务WS与Vite开发WS职责不同；前者仍由03唯一管理，后者仅开发环境存在。
- 开发刷新不得重启后端。刷新前保存草稿、当前会话和阅读锚点；不能保证保存成功时不得无提示丢输入，可暂停自动页面刷新。
- 后端改动按02的忙时延期安全重启，不承诺后端无损热替换。
- 保持生产静态资源路径可用；是否需要构建产物由最小验证决定，不为开发服务强迫生产改打包架构。
- 验证导入路径、静态白名单、代理、CSP及离线生产启动；成熟工具版本/Node要求在实施时锁定，不凭文档假定兼容。

## 6. 文件归属与独立开发

本组独占模型选择器及必要区域模块；`app.js`、`server.js`、`protocol.js`、全局HTML/CSS和package/开发脚本由集成负责人接线。区域模块可用假订阅源与最小DOM独立验证，无需03已上线。

05拥有消息窗口和缓存；06拥有活动消息显示游标。04不改这两者内部算法，仅提供容器和生命周期入口。03已有信封保持兼容。

## 7. 实施步骤

1. 枚举controls调用方与DOM id归属，建立事件→区域矩阵。
2. 先交付模型菜单无变化不重建及回归测试。
3. 分离输入与连接状态，再导航、设置；逐步缩小兼容controls。
4. 将对话挂载接05，绘制接06；验证父/子代理详情与原文对照。
5. 独立验证Vite开发入口，再由集成负责人接入dev脚本。
6. 检查隐藏详情、自动滚动与重复Markdown是否真热点；有证据再优化，不重复实现已有惰性详情。

## 8. 测试替身与验收

拟新增 `tests/frontend-regions.test.js`，运行 `node --test tests/frontend-regions.test.js`；未实现、未运行。复用现有测试工具，使用假订阅源、可控延迟配置请求和最小DOM；真实焦点/滚动用仓库已有浏览器测试能力，不以源代码字符串断言代替交互验收。

必测：模型节点稳定；输入草稿不重建历史；一分区失败其他区仍响应；切换后旧请求被忽略；多次mount/dispose不重复监听；后台正文不通知模型区；读屏/键盘/IME不退化。

开发验收：改CSS不丢草稿，JS整页刷新有明确语义且后端PID不变；生产包不存在开发监听与依赖；WS代理鉴权正确；连续保存不累积订阅。
