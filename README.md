# Axiom

Axiom 是独立开发、独立发布的项目，唯一代码仓库为 [`cosyeezz/axiom`](https://github.com/cosyeezz/axiom)。

多智能体协作的可靠基础。独立 Node.js 服务，通过 Pi SDK 运行主 Agent，以 `delegate` 并行启动子 Agent、以 `read_result` 读取结果，通过 WebSocket 输出实时事件。

Stop 按钮右侧的方块使用现有危险提示红色，文字与按钮边框保持不变。

会话运行中保持吸底：正文流式输出、工具记录、图片解码、折叠展开等任何内容增高都贴到最新，用户主动上滚（滚轮、触摸、键盘、拖动滚动条）才暂停跟随，滚回底部或点「回到最新消息 ↓」自动恢复；上方「回到最早消息 ↑」跳到开头并暂停跟随。跟随状态只由“是否贴底”和“用户意图”决定，布局重排、程序跳转与内容增高引发的滚动事件不会误判成用户离开底部；两个按钮上下分开，沿用现有按钮样式。浏览器回归：先运行 `node tests/conversation-preview.mjs`，再执行 `python tests/autoscroll-ui.py`。

执行过程按正文分段：连续思考与工具调用共用一行 `Working`，模型名和用量统计不分组，回答前的 thinking 并入紧邻的前段工具组，不重复堆叠 Completed；出现后续用户消息或模型正文后，前段变为 `Completed` 并自动收起。工具返回不会触发最新执行段完成或折叠；子任务卡片等分隔出的旧段若已无待执行记录，则显示 Completed，不再跟随最新段一起 Working。执行过程的 Working 还受 Agent 实际状态约束：中断、结束、断线或恢复空闲快照后不再转圈；有失败/停止记录时显示 Stopped，否则显示 Completed。状态变化不会强制折叠用户正在查看的记录。子代理详情内的执行、思考和工具标题随正文滚动，不吸顶叠层遮字；Working 行沿用面板背景，不出现突兀黑条（主会话吸顶行为不变）。主动中断后不会自动重放命令，发送“继续完成任务”可让 Agent 根据历史接着处理。消息底部以 `供应商 · 模型 · 思考级别    113,494↑  1,234↓` 展示元信息；思考级别只在消息有记录时显示，箭头分别代表输入/输出 tokens，窄屏整体换行。

## 子代理位置与恢复

- 子代理入口按 `delegate` 返回的任务 ID 绑定委派工具，显示在对应执行段之后，而不是最终回答末尾；刷新、迟到状态和同批多任务保持同一顺序。压缩后的入口仍归入对应摘要。
- 子代理过程使用独立 Pi JSONL 落盘，并与原 task ID 关联；重启后恢复历史，重启前尚未完成的任务自动继续，已完成或用户主动取消的任务不自动执行。
- 子代理详情提供「↻ 重试」，仅在服务端确认可续跑时显示；沿用原任务与上下文，不重新委派。重复点击被阻止，断线时不可操作。
- 本次不迁移旧任务过程；没有历史文件的旧任务不能恢复完整执行过程。

## 会话标题与子代理轮次预算

- Axiom 自有提示词集中在 `src/prompts.js`，按主代理、子代理、压缩代理组织，注入时机仍由各模块控制；用户全局/项目规则及 Pi、插件提示词保持原加载链路。主代理正式答复应独立、完整、清晰易懂，并用独占行的 `<axiom_answer>...</axiom_answer>` 标记；子代理和压缩代理不加载该交流格式，不强制 ASCII 图，也未新增 Mermaid 渲染。
- 主会话 UI 从原始消息提取回答正文，标签不展示；同一用户轮已有明确回答时，先前进度和工具记录可折叠查看。流式开标签到达即可展示正文，代码围栏/行内代码不解析；标记只认缩进不超过 3 空格的独占行，缩进 4 空格或 Tab 的同名行按代码原样保留。漏标、重复/嵌套标签回退原文，回退时先删掉正文里落单的裸标记行（丢协议不丢内容）；未闭合答复保留已输出内容。历史压缩逻辑和原始消息存储不变。用户输入按纯文本显示，保留换行、空白，长文本自动折行，不执行输入中的 HTML。
- 首次输入随正常模型请求附带一次标题要求；首个合法标题不超过 10 个字，直接更新会话名，不覆盖手动改名。未生成标签或格式不合规则保留临时标题，不额外调用模型、不重试标题请求。标题标签可跨行，正文换行折叠为空格；网页正文隐藏 `<title>` 标签，并继续过滤旧会话历史里的 `<axiom_summary>` / `<summary>` / `<progress>`（含落单的闭合标签与流式残片），不让它们漏进展示；代码围栏（``` 与 ~~~）、缩进代码块与行内代码内的同名标签是讨论内容，原样保留不剥离、不提取。`<title>` 只在回复首个非空非代码行内提取和剥离，正文中间讨论用的行内 `<title>` 不当自报标题。同名的正经 HTML 不被吞：`<details><summary>` 折叠块标题保留，带属性的 `<progress value=… max=…>` 等元素保留。落单的开启标签只删标签本身，不再把后面的正文一起截掉；只有流式未完成时才裁掉尾部残片。
- 不做增量摘要：没有摘要提醒、摘要记录对话框，也没有子代理进度回报。上下文靠 Pi 原生 turn 上下文与本文档「上下文自动压缩」一节的后台压缩维持，主代理只在任务完成通知后主动 `read_result` 取回结果，避免忙碌时被插入的子任务信息打断注意力。
- `delegate` 的每个任务必须带 `context` 字段：交代背景、已确认的事实、约束和验收标准，子代理不继承主会话历史。工具说明与系统提示词同时约束任务粒度（一个任务一件可独立交付的事，不要把整条流水线塞进一个任务）。
- 子代理有软轮次预算：默认 20 轮，最后 2 轮为收尾窗口。开工时系统提示词告知预算规模，累计 turn 达到 `maxTurns - wrapUpWindow` 后每轮在请求末尾追加 `[轮次预算] …` 收尾指令，要求交付已确认事实、未查清部分和建议的下一步拆分。上限是软的：只注入提示，不 abort（abort 会让 `result()` 抛错，连带丢掉此前所有轮次的产出）。轮次只在子代理进程内计数，不落盘；主代理没有预算。
- 在「设置 → 默认新会话设置 → 子代理轮次预算」配置轮次上限（3-200）与收尾窗口（1-10），默认 20/2，保存到 SQLite；新建任务立即生效，已运行的子代理保持原预算。预算随会话创建定死并写入会话 selection：重开旧会话仍用它创建时的预算，改全局值只影响此后新建的会话。库中记录含未知键（旧版本/未来字段）时只取已知键校验，不因此丢掉用户设过的合法值。非法值在建会话时直接报错，早于任何模型请求。
- 标题与任务状态按变更增量落盘：记忆钩子用 `save(change)` 描述本轮变更（标题、压缩/重试事件、单任务、事件删除），无变更不落盘，不再每个事件全会话重写；任务事件附 `saved` 完整单条快照（含 parentContext/resultId/notified/runtime/createdAt/updatedAt）供单任务保存，广播前剥离，前端只收安全视图。运行开始那一笔状态落盘顺带写入当前标题与 `updatedAt`：这两个值在运行开始前就已确定（首条输入推导的临时标题、本轮开始时间），长任务跑到一半进程被杀时不退回「新会话」和旧时间，侧栏排序仍按真实活动时间。模型自报的标题另有一笔即时落盘，与 `titleRequested` 同事务，不必等整轮结束。

## 项目技能与全局技能

技能、MCP 与插件配置显示 `[当前项目]` / `[全局]` 来源，悬停可查看完整路径。自定义默认配置中的全局技能跨工作空间共用，项目技能选择按真实工作空间目录分别保存（保存在 Axiom SQLite 的默认配置中，不写入 Pi 全局设置或项目文件）。通过目录链接打开同一项目也使用同一份选择。

旧版默认配置中的 `projectSkills`（`.pi/skills`、`.agents/skills` 项目路径）保留并迁移到各自所属目录的配置；不会按同名技能替换。配置只影响新建会话（目录配置只影响该目录），已有会话请新建后验证。“全部能力”仍按当前工作空间发现全部资源。

## 本地开发与安装版分离

- 源码目录运行 `npm run dev`：默认 `http://localhost:4320`，右上角显示 `DEV`，点击连接状态可进入「设置 → 服务与更新」，界面不展示源码位置；会话和日志放在 `~/.axiom-dev`，不影响日常数据。
- npm 全局安装版运行 `axiom`：默认 `http://localhost:4319`，不显示 DEV，继续使用 `~/.axiom`。
- 开发入口默认以当前源码为工作空间，不读取 `.env.local` 中的旧工作空间值；可在启动前显式设置 `AXIOM_PORT`、`AXIOM_CWD`、`AXIOM_HOME` 覆盖默认值。`AXIOM_HOME` 给相对路径时会先按启动时的当前目录解析成绝对路径，再传给守护进程与 worker（worker 以项目根为工作目录启动，不解析就会各自算出不同的数据目录、打开两个库）。
- 开发服务（`npm run dev`）下修改前端静态文件无需重启，刷新页面即可；修改后端 `src/` 仍需重启服务载入。开发测试通过后推送 master，Mac 安装版通过「检查更新」安装最新 master 并重启；不要直接修改全局安装目录，也不要把开发服务注册成日常自启动。

## 启动

需要 Node.js 22.13+（22.x）或 24+；安装和服务入口在加载内置 SQLite 前检查版本，旧版本提示升级，无需额外安装 SQLite 或修改全局安装命令。安装程序检查 Pi CLI，未安装时自动全局安装最新版 `@earendil-works/pi-coding-agent@latest`，已有 Pi 不强制升级。无需预先配置模型或凭据：没有可用模型时仍启动网页，并引导进入「设置 → 模型与供应商」；添加供应商、模型及 API Key 后即可新建对话，无需重启。订阅登录可直接在「设置 → 模型与供应商」内完成（授权链接/设备码，凭据仅保存到 Axiom SQLite），无需回到终端 Pi `/login`。首次使用时，主 Agent 和子 Agent 的 Skills、插件、MCP 默认选择全部为空，无需安装这些可选资源；需要时在默认新会话配置中手动启用。已有保存配置和 Pi 配置不被清空，提示词模板及目录上下文维持原有规则；基础编码工具为 read/bash/edit/write，主 Agent 额外获得 delegate/read_result/append 三个协作工具。可选能力清单来自终端持久配置，未选择 MCP 时不加载适配器入口，不继承另一终端进程的临时参数、会话状态或已执行的模式命令。纯 TUI 组件和终端快捷键不适用于网页；当前无插件交互 UI 桥，需要审批的 MCP 调用按适配器规则拒绝，不自动批准。

### 一键安装（macOS / Windows）

本仓库即 npm 包，两种路线任选；缺 Node 时安装脚本会经 Homebrew / winget 自动安装，随后装依赖、注册登录自启、在后台启动服务，并在就绪后打开浏览器。交互终端逐项确认（默认注册登录自启、打开浏览器）；脚本调用可用 `--no-autostart` / `--no-browser` 关闭。自定义端口写项目根 `.env.local`（`AXIOM_PORT=…`），安装、自启、服务读取同一来源。

注意 `npm install -g` 只装代码，不会启动任何进程、也不会注册自启，装完必须再运行 `axiom-setup`。若跳过它直接运行 `axiom`，首次会在交互终端补问一次注册登录自启与是否打开页面（问过即记下，删掉 `~/.axiom` 才会再问）。

npm 路线（推荐）：

```sh
npm install -g github:cosyeezz/axiom
axiom-setup
```

git 路线（macOS 终端）：

```sh
git clone --depth 1 git@github.com:cosyeezz/axiom.git ~/axiom; sh ~/axiom/install.sh
```

Windows（PowerShell）：

```powershell
git clone --depth 1 git@github.com:cosyeezz/axiom.git "$env:USERPROFILE\axiom"; & "$env:USERPROFILE\axiom\install.ps1"
```

Windows 也可直接双击 `install.cmd`。更新版本：网页「设置 → 服务与更新 → 检查更新」（按 GitHub master 提交比对，先检查、确认目标提交后才安装；DEV 不提供安装版更新），或重跑安装命令。卸载自启：`npm run autostart:disable`。

命令行帮助：`axiom help`（也支持 `axiom --help`、`axiom -h`），列出后台启动、前台运行、停止、卸载命令及数据保留说明；查看帮助不会启动服务。

停止后台服务：终端运行 `axiom stop`（默认 4319；`AXIOM_PORT` 可指定其他端口）。有运行任务时拒绝停止；空闲时保存会话，退出服务及守护进程，命令等待退出确认，超时不强杀。只停止当前运行实例，不取消登录自启。新版 worker 启动失败并处于重试等待时，可通过守护进程的本地通道停止；worker 仍活跃时不绕过任务检查。旧版本没有停止接口，需要首次完整重启升级后才可使用。

服务停止后重新拉起（守护进程 + 服务进程）：终端运行 `axiom`，**默认在后台启动**并立即返回——进程脱离终端，关闭终端窗口或断开 SSH 都不会停服；已在运行时不重复启动，只提示访问地址与日志路径。首次在交互终端运行会补问一次登录自启与打开页面，之后不再询问。要在前台运行（日志直接打在终端、`Ctrl+C` 停止，排查问题用）加 `--foreground`：`axiom --foreground`。

首次没有可用模型时，网页保持连接并打开「设置 → 模型与供应商」，不会反复新建失败会话。保存供应商、模型及凭据后，点击「＋ 新会话」开始；无需重启。已有会话引用和页面内草稿会保留。

### 卸载 npm 安装版

统一卸载（Windows / macOS / Linux）：

```sh
axiom uninstall
```

命令核对当前 npm 全局安装位置，安全停止服务、取消自启，再移除当前包 `@cosyeezz/axiom`。忙碌、停止超时或取消自启失败均中止卸载；服务未运行可直接继续。保留 `~/.axiom` 和 `~/.pi`，不卸载共享 Pi。

旧版不支持该命令时，使用以下手动步骤（任一步失败应停止，不要继续删除包）。包名以本机实际安装为准：打开 `npm root -g` 下的包目录，读取其 `package.json` 的 `name` 作为下文 `<包名>`；它不是安装来源 `github:cosyeezz/axiom`。

Windows PowerShell：

```powershell
$npmRoot = npm root -g
node "$npmRoot/<包名>/scripts/autostart.mjs" disable
axiom stop
npm uninstall -g <包名>
```

macOS / Linux：

```sh
node "$(npm root -g)/<包名>/scripts/autostart.mjs" disable
axiom stop
npm uninstall -g <包名>
```

若提示任务运行中，先停止任务再重试；服务本来就未运行时可跳过停止。取消自启须在卸载包之前执行。卸载保留 `~/.axiom` 会话数据及 `~/.pi` 配置，不卸载共用的 Pi；不需要的数据请确认备份后自行删除。

### 从旧包名迁移（一次性）

本项目独立发布，npm 包更名为 `@cosyeezz/axiom`，macOS 登录自启 Label 同步改为 `com.cosyeezz.axiom`。更名不支持原地自动迁移：旧版本不要用「检查更新」过渡，它会按新包名另装一份，旧包与旧自启仍在，容易同时运行两个服务。手动迁移一次：

1. 结束运行任务后安全停止旧服务：`axiom stop`（更早版本无停止接口时，退出旧守护进程并确认 4319 端口空闲）。
2. 取消旧自启：`node "$(npm root -g)/<旧包名>/scripts/autostart.mjs" disable`（PowerShell 用 `$npmRoot` 写法同上节）。`<旧包名>` 从旧安装目录 `package.json` 的 `name` 读取，不要凭记忆输入；macOS 上该步骤同时移除旧 Label 的 LaunchAgent。
3. 卸载旧包：`npm uninstall -g <旧包名>`。
4. 安装新包并初始化：`npm install -g github:cosyeezz/axiom`，再运行 `axiom-setup`（可重新注册登录自启，macOS Label 为 `com.cosyeezz.axiom`）。

`~/.axiom` 会话数据与 `~/.pi` 配置跨更名保留，无需搬移。迁移期间及之后都不要同时运行新旧两个服务：两者默认占用同一端口并读写同一数据目录，同时启动会端口冲突或互相干扰；先确认旧服务已完全停止，再启动新服务。

### 独立桌面壳（Pake / macOS + Windows）

```text
Axiom（npm 安装、独立更新） <-- http://127.0.0.1:4319 -- Pake 桌面窗口
```

桌面壳只打开本地正式服务，不内置 Node.js、Pi、网页副本或后端，不启动/停止服务。Axiom 更新后刷新窗口即可，通常无需重打壳；关闭窗口不停止后台任务。壳的版本在 `desktop/pake.json` 独立维护，不跟随 npm 包版本。

使用：先按上文 `npm install -g github:cosyeezz/axiom` 安装本体，再运行 `axiom-setup --no-browser`（可注册登录自启），最后安装并打开桌面壳。服务未启动时窗口无法加载，先运行 `axiom`，再重新打开窗口。桌面窗口与浏览器的 localStorage 不共享，但会话仍由同一本地服务保存。

下载已构建安装包：[Desktop v0.1.0](https://github.com/cosyeezz/axiom/releases/tag/desktop-v0.1.0)（含 Windows MSI、macOS Universal DMG 与 SHA256 校验文件）。安装桌面壳不需要 Rust。

打包（无需在自己电脑安装 Rust）：在本仓库 GitHub **Actions → Build Axiom Desktop → Run workflow** 手动运行。成功后从该次运行的 Artifacts 下载并解压：

- `Axiom-Windows-x64`：`Axiom.msi`，Windows x64，运行需要 WebView2。
- `Axiom-macOS-universal`：`Axiom.dmg`，同时支持 Apple Silicon 与 Intel，打开后拖入 Applications。

目前产物未配置代码签名/公证，系统可能提示未知发布者或拦截；仅安装可信来源的产物，不建议关闭系统安全机制。macOS 若拦截可信下载，可在「系统设置 → 隐私与安全性」批准打开。Actions 产物保存 30 天，正式包另行发布到 Release，不自动更新壳。

### 自动启动与服务控制

跨平台当前用户登录后自动启动（无需管理员；默认不是登录前的系统服务）：

| 平台 | 系统原生方式 |
|---|---|
| Windows | 当前用户启动文件夹，隐藏窗口 |
| macOS | `~/Library/LaunchAgents`，LaunchAgent |
| Linux | `~/.config/systemd/user`，systemd 用户服务（需可用的用户服务管理器） |

以下命令仅注册/取消注册，不启动或停止当前进程，下次登录生效。Linux 如需未登录即运行，可由用户另行配置 `loginctl enable-linger`；脚本不会自行提升权限。

```powershell
npm run autostart:enable
# 取消自动启动
npm run autostart:disable
```

右上角显示连接状态、DEV 和版本，点击状态进入「设置 → 服务与更新」，不展示源码位置。维护操作使用统一暗色确认弹窗，默认聚焦取消、支持 Esc；仅确认后发送请求。面板提供：

| 操作 | 行为 |
|---|---|
| 重启服务 | 保存会话、停止服务并重新启动，不安装依赖 |
| 修复依赖并重启 | 在暂存目录安装锁定依赖并验证 SDK → 保存并停止 → 备份、切换依赖 → 按需构建 → 启动并核验 |
| 检查更新 / 安装更新 | 先检查 GitHub master 完整 SHA，用户确认后安装固定提交；暂存新包与私有依赖、校验提交和 SDK，再停止切换，新实例就绪后才记录提交和清理备份；DEV 隐藏更新 |

检查更新由用户点击触发，不是后台定时更新；提交必须推送到公开仓库 `cosyeezz/axiom` 的 `master`。更新固定本次检查得到的 SHA，安装期间若又有新提交，下次检查会继续发现。安装前后均通过 `npm root -g` 核对目标包与当前服务的真实目录；不一致则报错，不写提交记录，安装前发现不一致时不会执行安装。网络/安装失败不记录新提交，安装失败会尝试重启服务并向页面报告错误。首次升级此更新机制后，需要完整重启守护进程一次（而非仅网页快速重启），使新的安装逻辑生效。

Axiom 使用原生 JavaScript，目前没有编译脚本，因此重建时不会假装执行编译。安装可能访问网络并执行依赖安装脚本；失败信息会记录到日志并反馈到菜单。准备失败不触碰在用依赖；发现残留 `.node_modules-backup` 时在停止服务前拒绝重建，保留运行中的服务和备份，请先检查备份来源、不要直接删除或覆盖。切换前保留旧依赖，构建或启动失败恢复备份；维护失败后的兜底实例若也退出，会恢复有上限的崩溃重试，不再静默离线；构建脚本自身修改的产物不自动回滚。启动核验默认 60 秒，超时后先确认新进程优雅退出再回滚，不强杀或并行拉起第二个进程。重启不拉取 Git 更新、不改变锁文件，也不删除会话历史。运行中的会话会阻止重启，请先停止任务；页面保留草稿并自动重连。页面与服务断开且业务进程退出时，「设置 → 服务与更新」提供「尝试恢复服务」按钮，经守护进程独立维护通道拉起；自动重试与限流由守护进程负责，维护端点也不可达时页面提示终端运行 `npm start`。

`npm start` 使用独立守护进程。直接 `node src/main.js` 仍可使用聊天，但不能从网页重启。首次从旧的直接启动迁移时，先停止旧进程，避免端口冲突。自动启动和安装输出日志位于 `~/.axiom/service.log`（POSIX 下权限收紧至 `600`，与数据库同口径；写入前按白名单脱敏——维护 token、安装目录、用户目录都换成占位符，凭证与本机路径绝不明文落盘，方便直接贴到 issue）。维护结果按安装根与端口隔离保存在数据目录 `axiom.db`（旧版 `service-state-<标识>.json` 只读导入一次并保留），刷新不丢；落库失败只在当前运行内提示，重启不显示假错误；阶段时间线全入口有界保存。面板读取真实阶段，不用虚假百分比，请求接受或连接恢复不等于操作成功。连续崩溃默认最多自动重试 5 次，之后等待手动恢复。业务端口离线时新开/刷新页面仍可能无法加载，已打开页面可查询独立维护通道。设计依据见 [服务维护说明](docs/service-maintenance.md)。守护进程自动读取项目的 `.env.local`（不提交），并保留 Node 所在目录到 PATH。移动项目或升级 Node 路径后需重新执行注册命令。

服务默认仅监听 `127.0.0.1`。健康检查 `GET /health`，WebSocket `/ws`。本机无需令牌，服务校验 Host 和浏览器 Origin，拒绝其他网站跨站连接。本机进程可直接访问。工作目录不是沙箱，Agent 可以执行命令和修改文件；不要公开部署到网络。

### Tailscale 远程控制

设置左侧「默认新会话设置」下方新增「远程控制」。电脑和手机都安装 [Tailscale 官方客户端](https://tailscale.com/download)，以同一登录方式和账号登录，并保持连接。面板自动识别本机 Tailscale 登录名；未安装时提供下载入口，未登录时点击「登录 Tailscale」获取本机设备的官方授权链接，完成授权后刷新状态。登录不会自动开启远程访问；确认后手动开启并保存，在手机浏览器打开面板显示的地址。Wi-Fi 与手机流量使用同一个入口，不需要路由器端口映射。

```text
手机 Tailscale → 本机 Tailscale 地址 → 验证登录账号 → Axiom
电脑本机      → 127.0.0.1          → 原有本机访问
```

- 默认关闭；远程入口只绑定本机 Tailscale 地址，不开放 `0.0.0.0` 或普通局域网监听。
- 服务通过本机 `tailscale whois` 验证连接来源的登录名，兼容普通设备省略 `Tags` 字段的官方输出，拒绝其他用户和 tag 设备，不相信浏览器传入的邮箱或身份请求头。同一 tailnet 不代表同一用户；登录名也可能是 `name@github` 这样的标识。
- 远程控制配置只允许在电脑本机修改。关闭或更改许可会立即断开已有远程连接，不停止后台会话任务；Tailscale 身份变化使用短缓存并周期复核，不代表即时同步 Tailscale 控制台的撤权操作。
- 配置保存在数据目录 `axiom.db`（SQLite 权威）：旧版 `remote.json` 只读保留，首次启动导入后不再读写；历史双重编码值首次读取自动迁移，损坏值按禁用处理（fail closed）。远程与本机使用相同端口（默认 4319，开发模式 4320）。特殊安装位置可通过 `AXIOM_TAILSCALE_BIN` 指定 CLI。登录失败时可在官方客户端完成授权，再回到面板刷新。
- 不保存 Tailscale 密码或登录凭据。不使用 Funnel，也不需要配置 Serve；建议同时用 Tailscale 访问规则限制 Axiom 端口。
- 地址虽然是 HTTP，但设备间流量由 Tailscale 加密。浏览器仍将其视为非安全上下文，自动复制等剪贴板能力可能受限，可使用系统复制菜单。
- 电脑需要保持开机、联网并运行 Axiom。Tailscale 未安装、未登录或无法验证身份时，不允许远程访问。

回归检查：`npm test`；可选浏览器布局验收 `python tests/remote-ui.py`（需 Playwright + Chromium，覆盖 1440/390/320px，不调用真实 Tailscale）。

## 会话已完成

- 每个浏览器页签只显示一个工作空间。打开其他目录时另开页签，原页签的会话和草稿不变；浏览器拦截时可点击提示中的链接打开。
- 侧栏将执行中、待查看与已读统一放在「进行中」，顺序固定为：运行中置顶，其次是跑完但还没打开过的，最后是看过的；每段内部按最后活动时间（`updatedAt`）倒序、以本地日期逐天分隔，不支持拖动排序。运行中显示绿色圆点；跑完且用户之后没打开过的显示主题色圆点，打开会话即熄灭（打开时刻记在 `localStorage` 的 `axiom.sessionSeen`，只在打开过、之后又跑完时才算待查看，历史会话不会被一次性标成未读）。当前正在看的会话跑完时立即记为已读，切走后不会回头标成待查看。「已完成」默认折叠，固定在侧栏底部、设置上方；手动展开状态在列表刷新和搜索时保留，刷新页面后恢复折叠，两组内容各自滚动。主代理执行中或任一子代理仍在启动/运行时，会话标题前持续显示绿色圆点，即使已标记完成也优先显示在进行中；主代理与全部子代理停止运行后才熄灭并回到相应分组。
- 会话行只保留标题与「⋯」入口，点击后在三点右侧显示独立浮动菜单，可标记已完成/移回进行中、新页签打开、复制、重命名、删除。「复制 ›」点击后向右展开「复制所在目录 / 复制文件名 / 复制完整路径」，均针对会话的 `.jsonl` 源文件（不是工作空间目录），目录保留末尾分隔符；完整路径可在另一实例导入框粘贴。窄屏自动向内避让，不挤动下方标题；Esc 逐级关闭并恢复焦点，点击外部关闭。只有明确标记完成才进入已完成，标记不会停止任务。搜索仅筛选当前工作空间；已完成的匹配项需展开查看。复制与完成标记不依赖连接；会话尚未落盘时提示先发首条消息。
- 创建时间写入 SQLite 会话表，后续消息与重命名不改变排序；旧记录缺少创建时间时，以已有最后更新时间作为固定兼容值，无法还原真实创建日期。
- 侧栏浏览器验收：启动 `node tests/conversation-preview.mjs`，再运行 `python tests/session-sidebar-ui.py`（需安装 Playwright）。默认端口 4321；端口占用时给预览设置 `PREVIEW_PORT`，给测试设置对应的 `AXIOM_PREVIEW_URL`。
- 隐藏只整理列表，不删除记录、不停止任务，也不切换当前对话。状态保存在当前浏览器的 localStorage，刷新保留，不跨浏览器同步；清除网站数据会重置。

## 模型收藏与供应商管理

- 输入区、默认新会话设置（全局默认与目录配置）、主/子代理和自动压缩的模型选择共用一份目录与收藏。供应商、模型、思考程度分别收藏；模型按 `provider/id` 区分，避免同名模型串用。收藏仅调整下拉顺序，不改变当前选择，不自动切换模型。
- 每个选项右侧预留五角星位置：鼠标移入或键盘聚焦显示黄色星标，已收藏常显；触屏直接显示按钮。点击星标不会选中条目或关闭菜单；再次点击取消。收藏项稳定置顶，其余保持原顺序。支持方向键、Home/End、输入查找、Enter 选择、Esc 关闭和键盘访问星标。
- 模型配置采用左侧供应商搜索导航、右侧详情与折叠高级字段，窄屏自动单列；参考 [Cherry Studio](https://github.com/CherryHQ/cherry-studio/pull/16858) 的分栏管理与 [OpenCode](https://opencode.ai/docs/models/) 的模型能力组织方式，不引入额外 UI 依赖。
- 保存供应商连接后，可「拉取模型列表」并搜索、勾选，再点击「添加选中的模型」；拉取本身只读，不会把全部结果自动加入配置。支持 OpenAI 兼容、Anthropic、Google 模型接口；已添加项禁选，部分添加失败可重试，未返回的模型能力不猜测。
- 思考收藏以 `provider/model:程度` 隔离，允许模型 ID 含冒号；星标只改变排序，不改变当前选择。浏览器回归：先运行 `node tests/model-selection-preview.mjs`，再运行 `python tests/model-selection-ui.py` 和 `python tests/model-settings-ui.py`（需 Python Playwright 与 Chromium，预览不使用真实凭据）。
- 「设置 → 模型与供应商」统一管理模型定义与供应商连接：自定义/覆盖供应商存 SQLite；内置/扩展供应商的模型（含未登录的）在同一页展示，可直接登录/登出（OAuth、API Key，凭据仅保存到 Axiom）、编辑名称/上下文/最大输出/推理/图片能力，并勾选思考等级（七级 off/minimal/low/medium/high/xhigh/max，写入 thinkingLevelMap，勾选非 off 自动标记支持推理）。内置模型保存走逐字段覆盖（`models.model.override`），只写修改的字段，未改的能力保持内置定义，不再需要同名整条覆盖。内置模型的移除入口是隐藏，不是删除。已有供应商选择 API 协议「不设置」后，保存、刷新仍保持未设置，不自动补成 OpenAI；新建供应商仍按所选模板预填协议。该页不改变「设置 → 默认新会话设置」的模型配置位置与行为（仍在 SQLite 默认配置中，主/子代理分开设置）。旧 Pi models.json 仅导入，保存后同步 SDK 使用的 models.compat.json，不修改旧 Pi 文件。
- 供应商重命名与删除在左侧导航行内完成：悬停（或键盘聚焦）显示铅笔与删除图标，删除图标悬停变红，两者都用原生弹窗二次确认，可 Esc 取消。重命名由后端一次写盘完成（`models.provider.rename`），模型、内置覆盖与未保存草稿随新 id 迁移；重名或非法 id 在弹窗内提示，不会发出请求。
- 内置/扩展供应商与模型可从 Axiom 的选取入口隐藏：目录页与模型行上有隐藏图标，二次确认后条目从模型选择器与本页目录消失，集中在左侧「已隐藏」里可随时恢复。隐藏只写 SQLite 清单（`models.hidden.set`），不改 Pi 运行时目录，既有会话不受影响；存在同名自定义覆盖时，供应商级隐藏自动让位给覆盖条目。
- 配置保存保留未编辑的高级字段和已有凭据；密钥不回传明文，编辑时留空表示保持。支持 `$ENV_VAR` 环境变量引用，不允许从网页添加执行命令型凭据。删除只移除自定义配置，不会删除 Pi 内置模型或登录凭据。保存前检测文件版本冲突，避免覆盖外部修改。
- 保存后更新模型目录；新建会话或重新选择模型使用新配置。已经运行的会话不会强制换掉已绑定模型，避免中断当前请求。
- 设计依据：[Linear 收藏](https://linear.app/docs/favorites)的星标切换与置顶入口；[WAI-ARIA Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)明确选项不适合嵌入额外按钮，因此选择与收藏采用独立控件。沿用现有近黑表面、细边框、`#5e6ad2` 焦点色，黄色只用于收藏状态，不增加装饰色。

## 新会话与能力选择

- 「新会话」使用「设置 → 默认新会话设置」中当前目录的配置；该目录没有单独配置时回落全局默认。首次自动创建、打开空工作空间、删除最后一个会话后的补建同样按当前目录取值。初始主/子代理的 Skills、MCP、插件均不选中；已保存的明确选择（包括全部能力）保持不变。
- 默认配置可分别设置主/子代理供应商、模型，以及 Skills、MCP 服务、插件的全部或自定义选择（可全部取消）。保存仅影响之后创建的普通会话，不修改当前/已有会话的模型与能力选择，也不启动代理；唯一例外是压缩配置，按会话所属目录的最新值动态应用到已加载会话。选择即通过 WebSocket 自动保存，写入数据目录的 `axiom.db`（SQLite 权威，旧 `defaults.json` 仅首次启动一次性迁移），服务重启保留，不修改 Pi 的 settings/MCP 文件。默认能力预览实时跟随选择，状态提示区区分保存中、成功和失败；失败不覆盖旧配置。
- 设置页顶部有「全局默认 / 目录配置」下拉：全局默认是所有工作空间的兜底，目录配置按真实工作空间目录分别保存模型、思考等级、Skills/MCP/插件能力、后台压缩与重试词表。选「目录配置」可从下拉里挑已配置目录，或点「选择目录」新加一个工作空间目录再编辑；切下拉只换编辑对象，不切换或新建当前会话，也不改变当前页签的工作空间。未单独配置的目录沿用全局默认。删除目录配置只删这份配置，不删工作空间目录、也不删该目录下的已有会话，之后该目录重新回落全局默认。配置整包保存在数据目录 `axiom.db` 的 `store` 表、`defaults` 命名空间：`global` 一行，各 `workspace/<真实目录>` 各一行（含完整技能选择），刷新、重启后保留。保存后立即更新内存；能力清单在读取时按目录重新发现，无需为修改默认选择而重启服务。旧具名预设直接丢弃、不迁移。
- 默认主模型可选固定模型，或「默认主代理模型」（沿用该目录最近成功调整的主模型，尚未调整时用启动模型；各目录分别记忆、互不串用）；主/子代理均可设置思考等级，选项来自模型支持的等级；主代理留空沿用默认值，子代理留空跟随主代理，运行时按模型支持调整。子代理的模型与能力可分别选择「跟随主代理」，能力跟随实际主代理选择而非全部能力。能力清单按当前工作空间读取，目录配置与目录绑定、不保存目录信任；换目录时按该目录的配置（未配置回落全局默认），只加载当前目录仍可用的已选能力；缺失项写入服务日志，不会扩大为全部能力，也不会改写全局默认配置。编辑默认配置时只提供当前目录可用项，不把其他项目或已移除的资源补成复选框；显式提交未知能力仍拒绝。
- 能力清单来自 Pi 原生包解析与 Skill 发现；仅列出本机已安装且已启用的资源，不安装新包。MCP 复用已安装 `pi-mcp-adapter` 的配置合并及 `createMcpAdapter({config})`，适配器本身不再重复显示为插件。每个代理拥有独立服务清单，未选服务不会通过该适配器暴露，stdio 服务默认使用会话工作目录。
- 选择工作空间即表示信任该目录：Windows/macOS/Linux 均默认加载项目 Skills、插件和 MCP，不需要另行勾选，也不依赖 Pi 全局信任策略。请只选择可信目录，项目插件和 MCP 可在本机执行。Axiom 不写入全局 trust/settings/MCP 文件；设置采用内存快照，保留全局和项目相对路径语义。旧协议中的 `trustProject` 字段保留兼容，但不再改变工作空间信任。
- 能力在创建时确定，设置弹窗显示主/子代理的能力摘要；模型支持执行中调整，下一次模型请求生效。首次普通会话的子代理默认不启用可选能力、模型跟随主代理；普通会话使用保存的默认配置，自定义会话可分别选择。状态通过会话文件恢复；主代理不自动续跑，未完成子代理按持久化状态自动恢复。
- 插件加载失败会阻止创建并显示错误；启动钩子错误保留为加载提示。插件的启动和关闭事件均执行。插件命令可以没有模型回答，不会再误报失败。所有扩展仍有本机执行权限，取消勾选不是文件系统沙箱；选中的插件也可能贡献自己的额外工具。

协议新增 `capabilities.list({cwd?,trustProject?})`，返回不含凭据的 Skills/插件/MCP 目录与信任状态。`session.create` 新增 `model`、`thinking`、`subagentModel`、`capabilities`、`subagentCapabilities`、`trustProject`。能力值为 `null`（全部）或 `{skills:[id],mcp:[id],plugins:[id]}`，空数组表示不加载该类。主/子选择都在创建前校验，显式提交未知 ID 拒绝；继承默认配置与恢复历史时仅取已选 ID 和当前可用清单的交集（空集合仍为不加载），不按同名技能猜测替换路径。`config.activeTools` 返回实际工具名用于验证。

`session.defaults.get` 返回 `{model,subagentModel,thinking,subagentThinking,capabilities,subagentCapabilities}`；`session.defaults.configure` 接收上述可选字段及 `cwd?`（读取/写入对应目录的配置，省略时读写全局默认；同时用于校验该目录里的可用能力），省略字段保留原值，保存失败保留全部旧值。主模型 `null` 使用该目录的最近主模型/启动模型，子模型 `null` 跟随主代理；`thinking:null` 沿用该目录的最近/启动思考等级，`subagentThinking:null` 跟随主代理；`subagentCapabilities:"inherit"` 跟随主代理能力，`null` 仍表示全部能力；默认配置不接收 `trustProject`。`session.create` 的显式字段优先于默认值，`useDefaults:false` 完全绕过这份默认配置，网页自定义入口使用该标记；最近主模型和思考程度按目录各自继承。

## 导入 pi 会话

侧栏「导入 pi 会话…」用共享文件选择器挑选 `.jsonl`，默认从 pi 的会话目录（`service.status` 的 `importDir`）开始浏览；确认后立即成为当前对话，可继续提问。首行缺少 `session` 头或 `cwd` 无效时报错，不创建会话。

```text
pi 会话 .jsonl（~/.pi/agent/sessions/...）
        │ 选中
        ▼
复制到 ~/.axiom/workspaces/<工作空间>/<会话 ID>.jsonl ── 读回历史 ── 成为当前会话
        │
        └─ 原文件保持不动：继续对话、重命名、删除 Axiom 会话都不改动它
```

- 导入是复制而非引用：历史条目原样保留，副本头部使用新的会话 ID 和目标 `cwd`，与网页快照并存。续聊、重命名、删除均不修改原 pi 会话文件；代理创建失败时副本一并清理。
- 副本归属当前页签的工作空间，像正常会话一样续聊、保存和恢复，不再打开源会话目录；尚无当前工作空间时使用实例默认目录。只复制聊天记录，不复制项目文件；工具操作作用于目标工作空间，历史中明确写出的旧绝对路径不会自动改写。
- 标题优先用 pi 会话名，其次首条用户消息正文（去掉注入的 Skill 正文与标签），最后退回文件名。
- 历史直接读 JSONL 分支，保留原文与消息 ID，压缩记录按原折叠关系显示。能力与模型沿用「默认新会话设置」，不读取原会话在 pi 里的供应商/模型选择。
- 新增 `session.import({path, cwd?})`：`path` 是服务端文件路径（不是上传），`cwd` 是导入目标工作空间，省略时使用实例默认目录，返回与 `session.create` 相同的快照；`service.status` 返回 `importDir` 供网页定位选择器。

## 设置窗口

设置窗口固定为可视区域高度的 80%，上下各留约 10%；切换分类不改变窗口位置或高度。内容少时留白，内容多时在窗口内部滚动，标题和关闭按钮保持可见；沿用现有暗色面板、边框与紫色选中态。

## 图片上传与放大预览

输入区支持点击图片按钮上传，或在输入框粘贴系统截图（Windows 可用 `Win + Shift + S`）；不再提供浏览器截图按钮或屏幕共享。待发送附件、消息和历史中的图片均可点击放大，也可通过 Tab 聚焦后按 Enter / 空格打开；点击关闭按钮、遮罩空白处或按 Esc 关闭预览。

```text
上传 / 粘贴 -> 光标处 [image1] + 同编号附件预览 -> Send -> 文字标记 + 消息图片
```

- 上传或粘贴时立即在光标处插入 `[image1]`、`[image2]` 占位（有选中文字时替换选区），可以继续在图片前后写说明；读取失败恢复原选区。缩略图显示同编号，点击 × 移除附件时同步删除对应标记并重排编号。手动删掉文字标记不会删除附件，删除图片请点 ×。
- 发送时保留占位，不再追加图片编号说明。模型请求会在 `[imageN]` 首次出现的位置紧接对应真实图片，保留前后文字顺序；重复引用不重复发图，未引用附件带编号放末尾，无效编号保留原文。普通发送、Steer / Follow-up 和恢复历史共用该转换；草稿、历史存储和撤回仍保留原附件顺序，多条撤回合并时同步调整编号。旧消息已保存的说明不回溯删除。
- 支持 PNG、JPEG、GIF、WebP，每条最多 4 张、每张最多 5 MiB；不支持 SVG，也不自动压缩或裁剪。大截图可先裁剪再粘贴。
- 可以只发图片，也可以搭配文字、Skill 和文件引用；附件跟随会话草稿，切换会话不会串图，发送失败保留附件。未发送草稿只存在当前页面内存，刷新页面会丢失。
- 运行中也可用 Steer / Follow-up 发送图片，队列显示附件数量，Esc 撤回时恢复图片；多条队列撤回后若累计超过 4 张，请移除多余附件后分批发送。
- 已发送图片在消息与历史中显示，随 Pi 会话记录保存。图片会发送给当前模型服务商，请避免包含密码等敏感信息；不支持图片的模型会明确拒绝，请换用视觉模型。
- `prompt` 支持可选 `images: [{type:"image", mimeType:"image/png", data:"原始 base64（不含 data: 前缀）"}]`。图片数、大小、类型、base64 与文件签名在服务端校验；仅有图片时 `text` 可为空字符串。

## 后台自动压缩

在「设置 → 默认新会话设置」的全局默认或目录配置中配置后台压缩，不再提供当前会话的独立压缩设置。压缩按会话所属目录生效：修改该目录的压缩配置后，新会话直接使用；已加载的会话在保存时即时改用该目录的最新配置，不必等重启；尚未加载的会话在首次打开时按所属目录取值（未配置的目录用全局默认），其他目录的会话配置不变。单个会话因模型不兼容而应用失败不影响配置保存。默认开启；可设置 token 阈值（默认 100000）和上下文窗口占比（默认 50%），**任一先达到即触发**。留空表示不使用该阈值，开启时至少填写一个。占比使用当前主模型窗口，统计为当前上下文估算，不是会话累计消耗。近期保留量默认 5000 token，按安全消息边界保留，不拆散工具调用与结果。

可单独选择压缩模型（留空跟随主模型）和模型支持的思考等级。摘要由独立内存 Pi 会话生成，不出现在子任务列表；固定禁用全部工具、MCP、插件、Skills 和项目上下文，只接收摘要指令、上次摘要和历史快照，不执行历史中的指令。仍使用滚动更新摘要，不永久追加旧摘要；提示词明确要求保留未再次提及但仍有效的目标、用户约束、关键决策、未完成事项及准确路径/数值/验收条件，仅在有明确变更时替换旧要求，并输出完整交接摘要。这能降低遗漏风险，不保证语义无损。

输入框上方显示后台压缩的真实阶段：正在生成摘要、摘要就绪等待安全点、已应用、失败、跳过或取消，不显示虚构百分比。状态按主会话隔离，切换会话和重连可恢复当前状态；服务重启不会继续显示已中断的后台任务。

```text
完整 turn 结束 -> 达到任一阈值 -> 固定快照 -> 后台生成摘要
主会话继续输出/执行工具 -------------------> 摘要待应用
下一次模型请求前 -> 校验检查点 -> 摘要 + 近期消息 + 全部新增消息
成功提交 -> 对应历史折叠为一个摘要块，展开查看摘要
```

每会话最多一个后台摘要任务；任务完成不立即修改运行中的上下文。应用时使用 Pi `prepareNextTurnWithContext` 安全入口，并保留其原生轮次刷新；用户排队输入仍由原队列投递。摘要过期、失败或取消时不删除原历史。接近模型窗口硬上限仍以 Pi 原生压缩兜底，必要时会等待，并非任何情况下都零延迟。摘要是有损的，也可能影响模型缓存命中率。

每次后台摘要在同一次模型请求中生成增量进展标题和描述，主会话按 `01 · 标题`、`02 · 标题` 排列，描述只讲本次新增发现、进展或阻塞；历史摘要只作为背景，不重复累计描述。展开后的完整交接摘要仍累计保留有效约束和未完成工作。序号由当前会话压缩记录顺序生成，刷新后保持一致；旧记录、原生兜底或模型格式异常时使用默认标题，不额外请求模型。模型在完整摘要末尾依次追加 `<axiom_compact_title>标题</axiom_compact_title>` 和 `<axiom_compact_desc>描述</axiom_compact_desc>`，不再输出 JSON；程序在非代码区按成对标签拆出元数据，允许标签前后夹正文、两个标签顺序颠倒或带落单的闭合标签；标题超过 30 字、描述超过 200 字（按码点计，一个 emoji 记 1 字）或含 `<` 时判为不合格。缺失、超长或格式错误时只丢元数据、回退默认展示，标签原文不会留在交接摘要正文里；围栏代码里的同名标签不当协议。正常提取的展示元数据以 `progress: {title, description}` 随事件、会话快照和 Pi JSONL 压缩条目 details 保存，不进入主代理交接摘要。

每次成功压缩保存独立记录，前端只隐藏本次覆盖的历史，保留近期和后台期间新增消息，不重建整个会话或清空输入。被压缩的委托记录所对应的子代理入口收进该次摘要，展开摘要后仍能打开原有子代理详情；多次压缩在历史顶部逐层排列，关联不明的旧任务保守保留。归属依据真实委托工具结果的任务 ID，而非时间猜测。重连/重启恢复相同归属，未完成的后台摘要不会恢复；Pi JSONL 仍保留原文。

协议：`session.create`、`session.configure`、`session.defaults.configure` 支持 `compaction: {enabled,tokenThreshold,percentThreshold,model,thinking,keepRecentTokens}`，两个阈值和 model 可为 `null`。配置返回实际 compaction；快照包含 `compactions`，消息记录包含 `entryId`。成功事件 `agent.compaction` 包含摘要 ID、正文、保留边界和 `compactedMessageIds`，客户端按消息 ID 折叠而非按时间猜测。进度事件 `agent.compaction.status` 与快照 `compactionStatus` 使用相同阶段数据。未启用此功能时仍保留 Pi 原生窗口保护。

界面回归：运行 `node tests/conversation-preview.mjs` 后，在已有 Python Playwright/Chromium 的环境执行 `python tests/compaction-ui.py`，检查两层摘要、子代理详情、输入区进度与桌面/390px/320px 布局；样例不调用模型或读取用户历史。

## 会话与子代理运行信息

- 发送按钮显示 `Send`，不带上箭头。底部操作行上方显示运行摘要：缓存命中、上下文用量/窗口及占比、当前实际供应商 · 模型 · 等级，例如 `zai-coding-cn · glm-5.3-flash · max`，不加「思考」前缀。主/子模型等级选项也直接显示 `off/high/max` 等实际值，保留无障碍标签。桌面一行排列，窄屏自动换行。
- 缓存命中按最近一次模型回答的 `cacheRead / (input + cacheRead + cacheWrite)` 计算，并显示命中 token 数；没有用量或输入总量为零时显示「暂无数据」，不伪造 0%。上下文直接使用 Pi `getContextUsage()` 的当前估算，不是累计 token 消耗；压缩后尚无可靠统计时显示「待更新」。
- 主会话用柔紫色底、左侧色条和描边 `SUBAGENT` 标识突出子任务卡片，显示状态和简短标题；点击打开独立原生浮层，不在对话中堆叠详情，也不因新任务自动弹出抢焦点。浮层以右侧会话内容区居中、宽度保留 880px 上限，位置和遮罩避开左侧配置栏与顶部会话标题；侧栏收起、窗口缩放和手机布局同步适配。
- 浮层顶部固定显示缓存、上下文、供应商/模型/等级及「回到最上」「回到最下」按钮，仅下方任务说明、系统提示词、失败原因和消息滚动。回到最上暂停跟随，回到最下恢复跟随新输出；手动向上阅读不被刷新拉回底部。支持关闭按钮、点击会话区遮罩、Esc 和焦点返回，不会停止运行中的主/子代理。
- 子代理消息直接复用主会话的 `card/renderMessage`、`stream-renderer.js` 和 `markdown.js`，包含流式正文、思考折叠、代码块、表格、历史及最终消息，安全边界不变。系统提示词取自该子代理实际运行状态（含扩展动态修改），仅按纯文本展示；尚未创建代理时提示未加载。切换/重连时清理旧浮层，再按会话快照恢复。
- 主/子运行信息通过 `agent.runtime` 事件更新，只在消息、轮次结束及上下文压缩等边界采样，不随每个 token 重发。会话快照新增 `runtime`，子任务 `task.state` 与快照附带各自的 `runtime`，包含 `model/thinking/systemPrompt/context/usage`；子代理销毁前保留最终状态，切换或重连恢复，互不串用。`read_result` 与 `tasks.read` 仍只返回任务结果，不把展示用的系统提示词再塞入主代理上下文。

## Goal 目标模式

- 输入 `/` 或 `/go` 可看到 `/goal` 命令提示。单独发送 `/goal` 只开启任务状态，不请求模型；下一条消息作为目标。也可直接发送 `/goal <目标描述>`，两种方式都先规划、确认后执行。
- 在输入框发送 `/goal <目标描述>` 即把当前会话原地切进目标模式（不新建会话、不改工作目录），也可点输入区按钮进入。普通会话不注入目标上下文、不暴露 Goal 工具、不触发目标续跑。
- 进入后先澄清目标并通过 `goal_plan` 提交轮次计划，提示模型不得开始实施，等用户确认或调整。目标状态与计划写入 SQLite；此阶段不是工具权限沙箱。
- 执行按轮推进：每轮结束模型必须把 `<axiom_round_finished>` 单独写在一行，Axiom 才结算并落盘该轮，然后开始下一轮；目标全部达成时把 `<axiom_goal_finished>` 单独写在一行，并附验收证据。标记只有在正文中独占一行、缩进不超过 3 空格才生效，夹在句子里的同名文字、缩进 4 空格或 Tab 的行、代码围栏与行内代码里的标记都不触发结算（未闭合的围栏按 CommonMark 视为代码延伸到结尾）。展示与落库的轮次小结里不留标记原文（含模型多写的闭合形式），小结取剥掉记忆标签与答复标记后的正文首行；网页正文同样不显示标记原文，流式打到一半的残片（如 `<axiom_rou`）先隐藏，代码围栏、缩进或行内代码里讲解的标记原样保留（用户手写的同名文本也不当作协议）。解析与剥离只有一份实现 `public/goal-markers.js`，`src/goal.js` 与网页端都复用它，规则不会两边漂移。
- 完成带证据门：`<axiom_goal_finished>` 只是声明，Axiom 同时要求目标具备可核对的验收证据（命令输出、测试结果、文件内容等）；`goal_evidence` 必须引用当前轮真实工具结果 ID（不是正文自报）；缺证据则留在当前轮核验，不标成功。轮次证据与整体验收证据都要求引用当前轮的工具结果，跨轮的旧证据不算已齐（末轮需重新给出整体验收证据）。证据是「能自己拿去核对」的材料，不等于正确性证明。
- 轮次、目标与状态按会话写入 SQLite，刷新、断线、服务重启后可恢复已确认目标与已完成轮次；恢复后不自动继续跑，等用户点继续，避免无人看管时自行推进。
- 「暂停」在工具批次安全边界生效：不 abort 在飞工具，并等待在飞子任务收尾；无需完成标记也能暂停。「继续」从保存的当前进度接着执行；「调整 Goal」修改总体目标并重新规划；「重启 Goal」重新开始目标，不删除原产物或历史。暂停后通知、重试与重启恢复不能自行唤醒循环。
- `goal_progress` 保存已完成、待办、检查、阻塞、下一步和产物位置，计划面板可展开查看；每次模型请求重新注入当前状态。轮次切换通过原生 checkpoint 替换工作上下文，不删除历史消息。自动续跑最多 64 段，预算耗尽或 `goal_block` 报告阻塞时持久暂停。
- 架构上 `src/goal.js` 是外层包装（outer wrapper），只负责计划/确认/轮次状态机、标记解析（复用前后端共享的 `public/goal-markers.js`）、进度持久化与对外事件；发送、工具、子代理、队列、压缩仍全部走 `src/sessions.js` 这一套共享会话引擎，没有第二条执行链路。前端 `public/goal.js` / `public/goal.css` 只加目标状态条与按钮，消息渲染继续复用 `app.js`。
- 「退出目标模式」在空闲或暂停后返回普通对话，保留消息与实际产物；执行中请先暂停，等待工具和子任务安全收尾后退出。退出后不因旧子任务通知自动唤醒。
- 输入区「添加、图片、目标」使用同一个工具栏外框，按钮统一尺寸并保留独立操作。
- 协议：新增 `goal.action`，`action` 取 `enter | confirm | adjust | pause | resume | restart | exit`，可带 `text`（进入目标或调整计划时的说明）。
- 边界与不承诺：目标模式不是沙箱，不改变工具权限、目录信任与插件执行范围。不承诺「绝对无漏洞」或产出必然正确；验收证据只表示模型给了可核对材料，是否真的达标仍由用户判断。模型可能漏标、误标或提前宣告完成，上下文压缩仍可能丢细节，长目标建议拆小并及时调整或暂停。

## 消息执行过程

- 等待模型响应显示 `connecting...`，思考中显示 `thinking...`、完成后为 `thinking`，准备工具调用显示 `calling...`；思考只保留一条入口，右侧「查看 / 收起」。活动行采用 12px 常规字重、14px 线条 SVG 与 20px 底座。连续没有正文、没有工具调用的思考合并展示，不堆叠空白 AXIOM 卡片和重复模型用量。
- 工具行按「语义图标 → 工具原名 → 操作对象 → 状态 → 详情」排列，直接显示 `read`、`edit`、`bash`、`powershell` 等，不加中文动作前缀；仅省略已知的 `functions.` 命名空间，悬停可看完整名称，未知工具保留原名。文件、命令、搜索等各有固定 SVG，完成后不替换成小对勾；工作空间内路径显示相对路径，长摘要省略，悬停保留完整值。手机将对象移到第二行。
- 思考、工具、Skill、重试、压缩记录及子代理系统提示词隐藏默认展开三角，使用「查看 / 详情 / 收起」提示，仍保留原生 details 的 Enter / 空格操作与焦点提示。展开后标题栏随会话滚动吸顶，右侧「收起」带向上收拢图标，读到中间也能折叠；工具输出、diff 和系统提示词不再限制内部高度，不产生第二层纵向滚动。
- 所有进行中状态（连接、思考、准备/执行工具，以及子代理启动/运行中的卡片、浮层标题与输入区摘要）统一为同一枚 12px 细环：细边无光晕、1.6 秒一圈，颜色沿用所在组件的语义色。思考文字后的 `...` 动态点固定 3 字符宽，1.2 秒步进循环，点数变化不跳动布局。结束后全部停止；系统开启「减少动态效果」时动画静止但仍保留状态文字。注意：Windows 关闭系统动画或经远程桌面（RDP）会话时，浏览器会判定「减少动态效果」并冻结这些动画，属系统环境而非页面故障，在系统设置重新开启动画即恢复；页面保留该无障碍媒体查询，不另加开关。
- 工具按用途分色：读取/搜索为雾蓝，命令为青绿，编辑/写入为暖金，思考/子代理为柔紫；失败仍用柔红。颜色仅作辅助，动作与状态文字始终保留。
- 点击或键盘展开工具详情：edit 优先显示工具返回的实际红绿 diff，没有 diff 时明确标注为请求改动。默认窄屏使用统一视图、宽屏使用左右对比；支持手动切换并在浏览器记住选择，窄屏始终回退统一视图；write 显示写入内容（无法仅凭参数判断新建或覆盖）；bash/read 等显示参数和文本输出。内容以纯文本安全展示，展开后才生成详情，每节最多显示 60,000 字符，超限提示独立放在该节下方，左右对比、统一视图和手机端均可见；完整结果保留在原会话记录中。
- 主会话、子代理及历史恢复使用同一套展示；只改变显示，不删除原始消息或修改模型上下文。

## 输出渲染与性能

正文与展开的思考共用 marked + DOMPurify 安全 Markdown 渲染，支持标题、强调、列表、引用、表格与代码。正文与思考均为 14px；正文灰白、重点暖金、补充说明柔紫、行内代码青绿、链接雾蓝。思考按斜体、正常字重展示（标题、`**强调**` 和表头也不加粗，保留 Markdown 语义）；代码和复制栏保持正体，便于辨认字符。代码块显示语言与「复制」，失败会提示手动选择复制；宽表格和代码仅保留必要的横向滚动，可用 Tab 聚焦，不限制纵向高度。复制控件在净化后生成，不允许 Markdown 注入按钮、脚本或 inline style。

完整的 `+---+` ASCII 表格（无语言或 text/txt/plaintext/ascii 代码块，单行单元格、列数一致）自动显示为网页表格，避免中英文宽度导致边框错位；复制保留 ASCII 原文，残缺表格、普通代码和流程图不转换。无边框、靠空格对齐的表格同样转网页表格：按显示宽度（中文/全角算两格）建网格，以「每行都空的 2 格以上空白」作列界，单个空格归入单元格（如 `2026-09-12 六`）；全列都是数字/百分比的列右对齐并用等宽数字，`-----` 分隔线保留为分组上边框，单元格不折行、窄屏横向滚动。首行在数字列也是数字时（如 `ls -l` 输出）不当表头，不编造语义；少于 3 行、不足 3 列、含制表符、被识别为字符图，或对齐不一致（拆出的单元格内仍有 2 格以上空白）时一律保留原文，不猜列划分。JSON 代码块、纯文本代码块中的有效对象/数组，以及整条纯 JSON 对象/数组消息提供「格式化、压缩、去转义、转义、复制」。去转义解开一层带外层双引号的 JSON 字符串；转义把当前文本编码成 JSON 字符串；复制始终取当前操作后的内容。操作仅影响本地展示，不修改会话原文；失败保留内容并提示，格式化/压缩遇到超安全范围整数或非有限数字拒绝转换，其他数字按 JavaScript JSON 精度处理。不扫描普通段落里的 JSON 片段。

字符图统一分层处理：明确的完整 ASCII 数据表格、空格对齐表格转网页表格；ASCII 方框、目录树、箭头和 Unicode 单/双线/圆角框按结构信号识别为字符图，混合说明一并保留，不猜测连线语义；未识别内容默认原文。仅处理无语言或 text/txt/plaintext/ascii/diagram/tree 代码块（大小写不敏感），不改编程语言或 JSON。所有此类文本块提供「优化 / 原文」切换，漏识别可手动启用网格，误识别可恢复原文，表格也支持切回原文；复制始终保留源文本。按字素网格显示：中文/全角及 emoji 占两格，其他字符占一格，避免系统字体回退导致边框错位；保留并排布局、原文复制和窄屏横向滚动，不转成表格。组合字符不拆开，Tab 按当前位置推进到下一个 8 格制表位且复制保留原始 Tab；超过 20,000 字符的网格优化禁用并提示原因，以限制 DOM 数量。网格不自动修复原文本身缺少/多出的空格，也不猜测图的语义。浏览器检查：`python tests/text-diagram-ui.py`（需 Playwright Chromium）。

流式更新只处理发生变化的消息，每帧合并一次；思考不触发正文 Markdown 重绘，折叠思考不解析 Markdown，展开才渲染。未打开浮层的子任务仅收集文本，不调度正文动画帧、不解析 Markdown，打开时一次显示完整结果（包括历史恢复与最终消息）；关闭再打开复用原有消息 DOM，不复制一套渲染逻辑。Markdown 按块比较，保留未变化的 DOM，仅对变化块解析、清理并替换；仍完整词法分析以正确处理后出现的引用定义。超长单个段落/代码块仍需重算该块，不保证恒定开销。

自动滚动请求合并，只在贴底时执行，内容增高由内容观察器兜底补底，用户滚动意图（滚轮、触摸、键盘、拖动）才暂停跟随；切换会话清理待绘制任务；删除重复任务恢复、单连接多订阅容器和重命名时的整份历史复制。静态资源启动时读取并生成 ETag，浏览器刷新时重新校验，未变化返回 304，不重复传输正文；生产下更新或新增静态文件需快速重启服务载入。开发服务（`AXIOM_DEV=1`，即 `npm run dev`）按文件 mtime 惰性重读已注册的静态资源并重算 ETag，改完刷新页面即可，不必重启；新增文件仍需重启注册路由。`public/stream-renderer.js` 独立负责渲染调度，`markdown.js` 负责安全块渲染。

视觉回归：先运行 `node tests/conversation-preview.mjs`，再用已有 Python Playwright + Chromium 环境执行 `python tests/conversation-ui.py [截图输出目录]`。测试使用静态样例，不读取用户数据、不调用模型；覆盖 1440/390/320px 配色、工具原名、活动行字号/字重/图标比例、行高与手机点击区域、Skill 键盘展开和模块强调、真实转圈/思考动态点固定宽/减少动态效果、长内容吸顶收起、无内部纵向滚动与子代理定位。

运行 `node tests/benchmark.js` 可复现 CPU/DOM 微基准。浏览器同机 3 个约 4KB 输出区 × 60 次更新，三次中位数从 391ms 降至 148ms（约 -62%）。这不是模型生成速度或真实端到端延迟指标。新增折叠任务场景：3 个任务 × 60 次更新，展开时 60 帧 / 180 次 Markdown 解析，折叠时 0 帧 / 0 次解析；完整内容保留，展开后按需呈现。

## 布局

手机端（宽度 ≤700px）默认纯阅读：收起顶部标题、输入框、模型栏、操作按钮、附件/队列/进度与回到最早/最新入口，只保留会话正文及底部一行「缓存百分比 · 上下文百分比 · 供应商/模型/思考程度」和「展开」按钮。长状态在本行横向滑动，不换行；未知百分比显示 —，读屏保留说明。展开后恢复输入、模型选择和辅助操作（包括停止任务），收起不清除草稿或附件；错误提示不隐藏。桌面端保持原布局。展开的输入框使用 14px 小字、默认一行 44px，输入后自动增高，上限为 120px 或屏高的 20%；底部最多占会话区一半，内容多时内部滚动。操作指引不常驻；手机详情标题不吸顶，跳转按钮进入正常布局，不再悬浮遮字。沿用 Linear 的 surface/line/muted token、8/12px 间距，不引入依赖。浏览器回归：启动 `PREVIEW_PORT=4338 node tests/conversation-preview.mjs` 后运行 `python tests/mobile-reading-ui.py`（环境变量写法按 Shell 调整）；覆盖 320/390px、横屏与短视口，并对比桌面计算样式和坐标。短视口模拟不等于真实手机软键盘验收。

桌面会话消息区和底部输入区左右各留白 5%，不再限制为 880px 宽；桌面、侧栏收起及手机端均按可用会话区域宽度自适应，手机输入区改用 12px 留白。工具/思考行桌面最小高度 36px，手机点击区域至少 44px；消息间隔 24px、角色标题到正文 8px，正文仍保留 14px 与 1.8 行高。通过减少外围空白提高密度，不压缩正文行距；子任务详情浮层尺寸不变。

左侧仅展示本页签工作空间的会话，按进行中、已完成分组，已完成默认折叠并固定在设置上方，组内按最后活动时间倒序并按天分隔；支持标题搜索、展开操作菜单后重命名和删除。侧栏可收起；手机端覆盖主区而非挤压内容，点击遮罩或 Esc 关闭，打开时主区不可交互。主区只滚动消息，输入区常驻底部；运行时显示插话、追加与停止按钮，空白输入与断线时禁用发送。切换会话保留页面内草稿、输入框高度和滚动位置，每个浏览器标签页独立记住当前会话 ID，刷新和断线重连不会跟随其他标签页切换；旧版浏览器记录仅在首次进入时作为兼容回退。每条会话的「在新标签页打开」按钮可将不同工作空间并排工作，链接中的 `#session=…` 定位对应会话。页面内断线保留可阅读的消息与可编辑草稿，点击「重新连接」后恢复；刷新页面仍不保存草稿。子任务通过卡片打开详情浮层；历史恢复时按首条子任务消息的位置放回卡片，不再全部堆到用户请求之前。空会话显示简短欢迎内容。

会话的 Pi 原生 JSONL 存于 `~/.axiom/workspaces/<规范目录路径的 SHA-256>/`，保存模型上下文和分支；标题、配置、摘要与任务分别保存在 `~/.axiom/axiom.db` 的独立表中，不再整份重写会话 JSON（旧每会话 JSON 首次启动只读导入）。左侧只显示当前工作空间，打开其他工作空间另开页签，不移动已有会话目录、不取消后台任务；页面可见时每 5 秒刷新后台会话状态（不订阅后台正文）；其他标签页删除会话会立即通知当前页面、禁止向旧会话发送，并在原目录新建会话恢复草稿和附件（不自动发送）；断线期间删除则在重连时恢复，恢复失败保留输入并提示重试。完成标记通过浏览器 storage 事件同步，支持 Web Locks 的浏览器串行保存，避免同时操作覆盖；重命名与删除采用统一暗色原生弹窗，删除会停止任务并删除本地记录。启动只加载会话元数据，首次打开再恢复历史；仅有待通知任务的会话会串行提前恢复，不自动重新执行未完成的任务。Goal 处于暂停/等待确认等阻塞态的会话即使有待通知结果也不在启动时拉起（那时投递必被拒），待通知标记原样保留，等用户恢复 Goal 再投递。新建会话的 JSONL 由 Pi 在第一条消息时惰性创建，因此只有真实存在的文件才写入库（未落盘时路径留空，列表菜单提示「发送首条消息后生成」），不会留下库里有路径、磁盘无文件、重启后打不开的空会话记录。已落盘的路径此后只增不抹：JSONL 被外部清理工具删除时库里仍保留原路径，打开会明确报「历史文件缺失」而不是当成全新会话静默重建（「从未生成」与「生成后丢失」是两种状态，不合并）。历史技能/插件/MCP 已卸载、移动或因信任设置不可用时，跳过失效选择并记录具体 ID；成功恢复的会话保存收窄后的选择。单个会话目录不存在、历史文件缺失或代理加载失败时，打开会话会明确报错，待通知恢复失败则记录到服务日志（通常为 `~/.axiom/service.log`）；列表与原始数据保留，不拖垮其他会话。修复后重新打开即可重试。启动时若列表里的会话无法恢复（历史文件缺失等），会跳过它继续加载其余会话，不因单条会话导致页面连不上；跳过的会话仍留在列表里，点开会明确报错。

## 输入框加载 Skill

- 输入框开头键入 `/` 可按名称或说明模糊补全当前会话 Skill（名称按顺序字符命中即可，兼容 `/skill:名称`）；在正文空白后键入 `@` 可补全工作空间文件和文件夹，名称模糊匹配（`apjs` 命中 `app.js`）并在**整个工作空间内递归搜索**，命中按「完全相等 → 前缀 → 子串 → 子序列」排序，每条显示相对路径，最多 60 条。
- `@src/` 按目录浏览（只在 `src` 子树内搜索）、继续输入筛选名称；含空格路径可用 `@"my folder/`。上下箭头选候选，Enter / Tab 添加标签，Esc 关闭而不撤回队列；文件夹可直接添加，或用右箭头 /「进入 ›」继续浏览。鼠标点击同样可选。
- 选中后复用原上下文标签与发送逻辑，文件或文件夹标签也可单独发送；只发送路径引用，不预读文件、不递归扫描目录、不增加依赖。

添加菜单采用 176px 宽的三行单行布局，说明收进悬停提示；加号为 28px 无边框细线 SVG 按钮，触屏扩大触控区域。输入区按「任务正文 → 模型选择/发送按钮 → 会话信息」排列，不再用 CSS order 重排。

输入框上沿「＋」菜单提供 Skill、工作空间文件、工作空间文件夹三个入口，使用统一线条 SVG 图标。搜索列表按名称或说明模糊匹配技能。文件/文件夹按层级浏览，过滤 `.git`、`node_modules` 与符号链接，服务端 realpath 校验禁止浏览工作空间外目录。选择后显示可移除标签，不改变原模型选择与运行信息布局。Skill 只显示在上方标签，输入框仅显示任务正文，发送时自动附加 `/skill:名称 `；手动输入有效 Skill 命令并键入空格后也转为标签，每次显式加载一个；文件/文件夹以路径引用随消息发送，由代理按需读取，不上传或递归灌入整目录。标签随页面内草稿切换保留，发送成功清空，失败保留。

会话里的原生 `<skill>` 消息块显示为默认折叠的 `SKILL` 描边标识和技能名，用雾蓝左侧色条、浅底色和边框与普通工具行区分；点击展开路径和经过 Markdown 安全渲染的正文，skill 块放在对应用户消息前面，与用户气泡平级，不嵌套；纯 skill 消息不显示空气泡，历史恢复也适用。该标识表示技能正文进入消息，不表示模型已完成执行。

### 统一文件 / 文件夹选择器

「打开工作空间」、「导入 pi 会话」和「＋ → 文件 / 文件夹」共用 `public/file-picker.js` 原生网页弹窗，与现有主题保持一致，不再启动 PowerShell。支持地址输入、面包屑、上一级、刷新、常用位置、按名称模糊搜索（递归当前目录的全部子目录，命中行右侧显示所在相对目录）和确认/取消；目录单击进入，文件选中后确认或双击添加。支持 Tab、上下箭头和 Esc，窄屏自动收拢位置栏。代码、配置、文档、图片、音视频、压缩包、PDF、字体和项目目录使用本地分类 SVG 图标，不加载远程图标或字体。

```text
打开工作空间 ─┐                    ┌─ 主机目录（绝对路径）
选择文件 ─────┼─ 共享选择器 ────────┤
选择文件夹 ───┘                    └─ 当前工作空间（限制范围）
                         点进目录 → 只读取该层 → 每页 200 项
```

- 无搜索词时只读取当前层名称和类型，不扫描子目录、不读取文件内容/大小/修改时间，按目录优先排序后服务端分页，按需「加载更多」。搜索词非空时改为客户端零改动的服务端搜索：BFS 逐层递归当前目录（跳过 `.git`、`node_modules`、符号链接），只匹配名称、不回读文件，忽略大小写且字符按顺序出现即命中（`apjs` 命中 `app.js`），按匹配质量（完全相等 → 前缀 → 子串 → 子序列）排序后一次返回最多 60 条、不再分页；递归目录数封顶 400、单目录不可读只跳过，避免超大工作空间卡住请求。实测 Axiom 工作空间每次搜索 3–40ms。单层目录仍需 `readdir` 后排序，极端大目录若成为瓶颈再改为流式目录游标，不提前搭建索引服务。
- Windows、macOS、Linux 共用 Node 文件系统实现；主机模式提供用户主目录、文件系统根目录及 Windows 可用盘符，地址栏可输入 UNC 路径。浏览的是 **Axiom 服务所在机器**，不是另一台浏览器设备。系统权限错误在弹窗中提示并可重试。
- 工作空间引用保留相对路径和 `realpath` 边界校验，过滤 `.git`、`node_modules` 与符号链接；打开工作空间允许浏览本机目录但不预先加载其中的项目能力。选定后仍沿用已有会话切换/创建与信任流程；取消不切换。过期响应、会话切换和关闭弹窗不会覆盖新选择。
- 图片上传仍使用浏览器原生文件上传和粘贴：这是上传附件，不是引用服务端路径，不能混用两者。
- 新增 `files.browse({sessionId?,path?,directoriesOnly?,offset?,query?})`，返回 `path/parent/entries/nextOffset/breadcrumbs/locations`；省略 sessionId 为主机模式。补全接口 `workspace.browse({sessionId,path?,query?})` 复用同一实现：`query` 非空时递归搜索当前 `path` 子树（默认工作空间根）、一次返回全部命中。沿用本地 WS Host/Origin 校验，不接受任意系统命令。`workspace.reveal({sessionId})` 使用 Explorer / open / xdg-open 打开系统文件管理器，Linux 需安装 xdg-open 并有桌面环境。

调研参考：[VS Code Lists And Trees](https://github.com/microsoft/vscode/wiki/Lists-And-Trees)、[Seti 文件图标主题](https://github.com/jesseweed/seti-ui)、[原生 JS FileExplorer](https://github.com/cubiclesoft/js-fileexplorer)。借鉴目录懒加载、文件分类和导航布局，不引入完整文件管理器或复制其图标资产；图标为本地自绘 SVG。[showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker) 浏览器支持有限，也不能提供服务端工作目录路径，因此不作为跨平台实现基础。

普通发送、插话和追加均复用 Pi 原生 Skill 命令展开，在发送/入队时读取 Skill 正文，不另建文件读取接口，不修改会话能力配置。选择表示「本次发送要加载」，不代表模型已经使用；已进入上下文的 Skill 不会因取消下一次选择而被删除。会话配置新增 `skills: [{name, description}]`，取自主代理实际资源加载器。

## 队列与执行中交互

- 执行中显示 `Steer` / `Follow-up`：Steer 在下一个可介入节点补充指令，不立即中断运行中的工具；Follow-up 等当前这一轮结束后发送，不影响当前执行，也不保证上一轮成功。Enter 使用设置中的默认类型，初始为 Steer；配置页直接展示两者说明，下拉框复用模型选择样式。
- 输入框上方显示 Pi 原生队列和类型。点击队列或单按 Esc，使用 Pi `clearQueue()` 一次撤回全部队列并追加到现有草稿，不覆盖草稿；重新发送时可选类型。这里与 Pi 原生一致，不提供逐条删除。
- 双按 Esc（300ms 内）或「停止」取消执行。右上角已连接时显示 `Idle` / `Running`，断线为灰色。
- 300ms 内三按 Esc：把这一轮已发出的输入收回输入框（含图片，编号重新对齐草稿附件）。只在模型还没产出内容时成立（被中断或失败的半截回答会一并丢弃）；一旦出现过回答、工具调用或工具结果，只停止并保留原消息；队列里的消息仍按单按 Esc 撤回，被拒绝的撤回不会吞掉队列。撤回按分支回退实现，之后的历史前缀逐字节不变，供应商前缀缓存继续命中。
- 撤回已在 Pi 分支生效后，即使 SQLite 暂时拒绝保存，网页历史仍同步、输入仍交还草稿；保存错误会显示，整组记录清理保留到下次保存或关闭重试，不把“已撤回”冒充“已落库”。
- `prompt` 可带 `queueType: "steer" | "followUp"`；`session.configure` 可保存默认 `queueType`；`queue.withdraw` 可带 `recall: true` 并返回 `{steering,followUp,recalled}`（`recalled` 为 `{entryId,text,images}` 或 `null`）；`session.queue` 同步队列，attach 快照包含 `queue`。
- 输入框上方「+」行最右端显示任务计时器，口径就是侧栏绿点：绿点亮起开始计时，熄灭后定格，重新执行继续累加而不清零。不足 1 分钟显示 `45s`，之后 `3m 05s`、`1h 02m 03s`；运行中绿点脉动、文字提亮，停止后变为静态灰点，数字用等宽数字位（`tabular-nums`）避免每秒跳动，减少动态效果只停动画、不停计时。计时按会话落盘：`sessions.list` 与 `session.state`/`task.state` 事件附带 `elapsedMs`（已结算累计毫秒）与 `runningSince`（本段起点，空闲为 `null`），服务重启保留已结算累计值，未结算的运行段不补算。

## 协议

每个命令必须有请求 `id`；响应为 `{type:'response', id, ok, data?, error?}`。

```javascript
const ws = new WebSocket('ws://127.0.0.1:4319/ws', ['axiom']);
ws.onmessage = ({ data }) => console.log(JSON.parse(data));
ws.onopen = () => ws.send(JSON.stringify({id:'1', type:'session.create'}));
// 从响应 data.sessionId 取得会话 ID 后发送：
// {id:'2', type:'prompt', sessionId, text:'并行检查两个模块，读取结果并总结'}
// {id:'3', type:'session.attach', sessionId}  // 重连，返回快照并订阅
// {id:'4', type:'tasks.read', sessionId, taskId:'...', resultId:'通知中的 UUID'}
// {id:'5', type:'cancel', sessionId}          // 取消主 Agent 与当前子任务
// {id:'6', type:'session.close', sessionId}   // 释放会话与结果
```

`session.create` 自动订阅；断开连接不取消任务。重新 attach 返回状态、历史消息、当前流式消息、工具状态、任务结果与序号。快照后按事件 seq 接续，不要重复追加快照之前的内容。服务不保存每个增量的回放日志。

事件包含 `sessionId`、`seq`；Agent 事件包含 `agentId`，子任务另有 `taskId`、`parentAgentId`。类型为 `session.state`、`agent.message.start/end`、`agent.delta`、`agent.runtime`、`tool.state`、`task.state`、`error`。`agent.delta.data` 的 `type/contentIndex/delta` 对应内容块增量；thinking 是否可见取决于模型。`tool.state.data.partialResult` 为累计结果，替换展示而非追加。`agent.message.end` 的完整消息为最终事实。

主 Agent idle 不代表所有子任务完成，使用 task.state 判断子任务。任务 ID 只在其所属会话中有效。本机客户端能访问所有会话。

## 交互式提问

答题卡使用紧凑题签和选项行；同组问题按当前宽度预留最高内容区，切题时题签位置稳定。卡片不设独立滚动条，超长内容通过输入区域滚动查看；手机收起输入框时待答问题仍可见。自定义回答随换行自动增高，不受聊天框 240px 上限影响；切题保留已撑开的题面高度，调整窗口宽度后重测并保留输入焦点与选区。题签用编号/完成勾区分进度，方向键使用 SVG 键帽提示；主色沿用 Linear 紫色（#5e6ad2），完成状态使用成功绿（#27a644）。浏览器回归：`python tests/question-layout-ui.py`。

主代理内置 `question` 工具：需要用户澄清或决策时调用，等待网页答案后作为工具结果继续原任务；不另发聊天消息、不增加专用系统提示词。子代理不注册此工具。

参数为 `questions: [{ header, question, description, options: [{ label, description? }], multiple? }]`。`header` 是选项卡短标题，问题 `description` 必填，用于说明背景和选择影响；选项说明可选，`multiple` 默认 false。每次 1–10 题，每题 1–20 个不重名选项，页面自动提供自定义回答。工具输出为 `{ answers: string[][] }`，按题序返回选中标签或自定义文字。

页面显示多题选项卡，左右切题、上下移动选项焦点、空格选择、Enter 下一题（最后一题答完后提交）；Tab 正常切换控件，自定义输入内保留方向键编辑。问题首次出现聚焦选项，不默认作答；切题保留草稿，所有问题答完后统一提交。单题隐藏选项卡。取消等待中的提问后，底部显示「重新提问」：点击直接重新执行原问题，不让模型重新生成题目；回答后作为工具结果继续原任务。普通请求中断仍显示「重试」。

待回答状态属于会话，断线不取消，重新连接或刷新通过快照恢复；重复提交只生效一次。停止任务、删除会话或关闭服务会解除等待。等待对象仅在内存中，不支持跨服务重启续答；已返回答案随正常工具结果进入 Pi 历史。

## 委派工具

- `delegate({context:'交代背景与验收标准',tasks:[{task:'任务 A'},{task:'任务 B'}]})`：并行启动，立即返回 `{taskIds:[...]}`。`context` 必填且在本批任务间共用：子代理不继承主会话历史，这是它得到的全部背景。每个 `task` 只放一件能独立交付、几轮内做完的具体目标，不把整条流水线塞进一个任务（轮次预算见「会话标题与子代理轮次预算」）。
- `read_result({taskId:'...',resultId:'...'})`：仅在收到完成通知后，用通知中的随机 UUID 读取该任务结果。移除 `wait` 和批量 ID 参数，不提供轮询/等待入口；错配、跨会话或未完成均拒绝。重复读取保留结果，失败与取消也有可读结果。任务结果按模型原文落库与回读，`<title>` 等记忆标签不在落库时剥离，剥离只发生在网页展示层。
- `append({taskId:'...',text:'补充指令',mode:'steer'})`：给运行中的子代理追加内容，默认 `steer`（下一安全点插话），可选 `followUp`（当前工作告一段落后接续）。回执只表示入队，不表示已执行；启动中、已结束或取消中的任务拒绝追加。

子任务结束后生成独立 `resultId`，先把结果和待通知状态落盘，再主动触达主代理。通知只带 taskId/resultId/status，不塞完整结果或子代理系统提示词。当前主代理还在运行时先保留通知，等该次运行结束后合并通知并启动新一轮；空闲时直接唤醒，不进入可撤回的用户队列。主代理收到通知再调用 read_result，不轮询。停止会话会暂停自动唤醒，下一条用户消息恢复；服务关闭不再唤醒。重启会补发未确认送达的通知（崩溃窗口可能重复，同一 resultId 可重复读取），不会重跑已完成子任务；有持久化历史的未完成子任务会续跑。旧任务缺少凭证时在加载时补发凭证。通知状态表示通知轮已处理完，不保证模型一定读取了结果。

输入框「＋」上方显示当前会话进行中的子代理摘要：启动中/运行中每个一行，转圈图标与单行省略文本；点击或用 Enter / 空格激活后跳到会话内对应 `SUBAGENT` 卡片并聚焦，暂停自动跟随，不直接弹出详情。可继续点击卡片查看详情，或点「回到最新消息」恢复跟随。任务结束自动移除，无任务时隐藏，切换会话不混入其他会话任务。

无固定并发上限、任务超时、只读限制或结果截断。子 Agent 没有递归委派工具。并行修改同一文件可能冲突，应让主 Agent 分配不同文件，或使用不同工作目录/worktree。取消不回滚已发生的文件修改。主代理与子代理遇到模型限流、可恢复网络异常或意外中断时自动避让续跑，最多重试 45 次；间隔为 `2、2、5、5、10、10、30、60、120、240、480、960……秒`，480 秒之后翻倍，16 分钟封顶（全部耗尽纯等待约 9.3 小时）。Stop 会立即取消等待；凭证、权限、计费等永久错误不重试。可在会话配置中自定义错误词表（子串匹配、大小写不敏感）：白名单命中即强制重试（可越过内建黑名单，如供应商把瞬时故障报成 quota 文案），黑名单命中即不重试且优先于白名单与内建判定；词表由新建会话保存，主/子代理共用，重启恢复继续使用该会话原词表，修改默认设置不追溯改写旧会话。词表输入框回车添加一条，Backspace（输入为空时）或 × 删除，重复词不区分大小写；只打字未回车就离开输入框时也会补记该词，「默认新会话设置」里每次增删即自动保存；关闭再打开或刷新页面后，已保存的词会直接显示为标签，重复输入不会新增或隐藏已有标签。重试保留已完成工具结果，不重新发送原始任务；正常结束不凭空判断“任务未完成”，仅对明确的可恢复失败重试。重试详情仅显示次数、错误和预计继续时间，不收纳正文、思考或工具调用；成功后折叠，可手动展开。子代理重试直接按已落入 SQLite 的任务 ID（agentId）绑定，实时、刷新及重启后都固定放在该子任务说明后；不依赖子代理消息是否恢复或混合消息下标，旧记录有任务 ID 即可归位。主代理新记录保存首次重试的消息边界与关联消息 ID。历史迁移优先使用 JSONL 条目写入时间，不将排队消息的编写时间误当消费时间；可靠位置落盘后复用。撤回同步处理被移除区间的重试与其余边界；压缩区间内的重试收进对应摘要，主/子代理分别展示。无法可靠还原原位置的主代理历史记录、尚缺任务元数据的子代理记录放入顶部「历史重试记录（原位置无法确认）」折叠区（任务元数据到达后自动移回任务说明后），不再伪装成回答结束后的事件。终态清除当前等待字段，成功清除当前错误，尝试历史仍保留；记录随会话保存；主代理重启不自动继续，未完成子代理按持久化状态续跑。

若输出被截断（`length`）且正文为空、没有工具调用，Axiom 会保留已完成工具结果，从下一次请求中移除末尾截断回复，附加一句通用内部提示自动恢复一次；提示不冒充用户消息、不改原始日志，恢复结束后移除。恢复再失败即停止，不进入普通错误的多次重试；用户停止后不自动恢复。主代理和子代理共用此规则。

自动重试不覆盖的异常停止（手动 Stop、终态错误、重试用尽）在会话流末尾给出「上一次请求未正常结束。↻ 重试」入口：语义是续跑，删掉末尾失败的助手消息后接着上次中断的位置继续，不重发你的输入，已完成工具结果保留在上下文；续跑再遇可恢复失败仍走上面的自动退避。仅在主代理末尾消息确有异常证据（失败、被中止、被截断，或停在工具轮/半截轮次）、会话空闲且连接正常时出现，正常结束、空会话、运行中不显示；子代理独立在任务详情显示重试入口；点击后转入运行即自动收起。服务端在启动前同步校验可续性，不可续时直接回错，不产生空转运行。

实现参考 [OpenAI Node SDK](https://github.com/openai/openai-node#retries)、[Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript#retries) 及已安装 Pi SDK 的错误分类/安全继续机制。禁用底层重复重试，由 Axiom 统一计数；采用上述指定时间表，不额外加入随机抖动。SDK 消息边界未保留原始 HTTP Retry-After 响应头，因此这里不宣称支持按该响应头调整等待。

## 模块边界

```text
main.js     配置与组装
server.js   HTTP / WebSocket / 鉴权
protocol.js 请求校验
sessions.js 主会话、订阅、快照、取消
  goal.js  目标模式外层包装（计划/轮次/标记/持久化，复用共享引擎）
  tools.js  委派、凭证读取、追加指令的参数和适配
  tasks.js  子任务状态、并行执行、结果
pi.js       Pi SDK 创建、事件适配与释放
compaction.js 后台摘要、检查点校验与安全轮次提交
capabilities.js 原生能力发现、内存配置、MCP 快照与选择加载
```

任务状态只归 tasks 管理，工具不保存另一份状态；传输层不直接调用 Pi SDK。采用原生 JavaScript ES modules 和 Node 测试工具，不增加编译步骤或工作流框架。

模型配置、收藏、内置模型隐藏清单与凭据的读改写使用同一权威数据库连接进行原文比较后原子写入（CAS）；其他进程已修改时明确拒绝，不覆盖、不自动重放凭据回调。数据库中某一行不是合法 JSON 或顶层结构非法时，读路径按未配置处理并在配置页给出告警（启动与页面都打得开，用户有自愈入口），写路径明确拒绝——不知道原值是什么就写新值等于静默丢弃用户数据。派生模型文件仍有跨进程陈旧窗口，不能把权威库防丢更新等同于各进程 SDK 实时同步。

## 会话操作与断线恢复

- 左侧每条会话框内右侧提供中性色铅笔重命名、垃圾桶删除图标；无需切换会话即可操作。长标题使用省略号，图标保留固定空间，悬停可查看完整标题。删除确认默认聚焦取消，危险按钮及悬停均为红色；弹窗复用暗色边框与背景。
- WS 初次连接失败或断开后按 1、2、4、8、15 秒间隔自动重试，成功后重置；保留草稿并恢复会话快照。连接正常时不轮询，手动重试不创建并发连接。

内部子任务完成通知只用于唤醒主代理，不在会话正文显示；任务卡片与结果读取保持不变。

卸载入口通过显式传递服务操作避免模块循环等待；若旧版出现 `unsettled top-level await`，请使用上文手动卸载步骤；旧包名安装必须先完成「从旧包名迁移」，不要直接覆盖安装。

## SQLite 配置与管理存储

Axiom 使用数据目录中的 `axiom.db`（Node 内置 SQLite，WAL 模式），保存会话管理状态、任务与通知、全局默认与各目录配置、模型与明文凭据、收藏、内置模型隐藏清单、远程访问配置和守护维护记录。不需要安装数据库服务或手动编辑 Pi 配置。Pi JSONL 保留模型会话原文与重启恢复；数据库不重复保存主会话完整消息。

动态数据拆为 `sessions`（元数据）、`session_events`（压缩/重试）、`tasks`（单任务）三表；`store` 只保存小配置、凭据与迁移标记。改标题只更新会话元数据，通知确认仅修改单任务标志，不逐 token 写库。旧库首次打开时幂等清理已废弃的 `summaries` 表、`main_turn` / `memory_turn` / `progress` 列与 `summary_trigger` / `progress_delivery` 事件行，按实际表结构自检，不靠迁移标记，新库不执行任何清理。同一次开库还会给老库里没有身份的事件行补一个稳定 key（早期版本的事件行允许不带 id，读出来没有身份，重写会多出删不掉的重复行、撤回又删不中），补完读、写、删三条链路才认得同一行；已有身份的行不动，新库零行受影响。

迁移读取旧 `store.sessions` 与更早的会话 JSON，成功后新表是唯一动态数据来源，不双写、不支持旧版运行。首次实际导入前自动生成一致性备份 `axiom.db.pre-store-migration.db`（先写唯一临时文件，完整成功才发布；失败不导入、不标记）；逐会话事务与完成标记确保重跑不覆盖已迁移数据，重启不再读取已迁移的大 JSON；坏文件/坏行保留并警告，修复后可以重试。JSONL 缺失时会话仍在列表中，打开时报错，不创建空历史覆盖。具有持久化历史的运行中子任务重启后从原上下文继续，不重新发送已落盘的任务输入；已完成或用户主动取消的不自动运行。旧迁移源保留用于人工备份；删除会话仍按既有删除流程清理其关联文件。

模型配置页直接保存到数据库（唯一权威，models.compat.json 只是可重建的派生镜像，不双写）；一次导入门闩按来源独立：每个来源只看自己的迁移标记，models.json 与 auth.json 互不牵连。模型权威一经存在（页面配置或既往导入）且该来源没有遗留告警，就补打迁移标记退出导入来源——此后旧文件不再被读取，清空权威也不会复活导入，陈旧导入告警同时清除；仍有告警的来源保持窗口开着，坏文件/坏结构只去重告警、不打完成标记，修好后可重导（importModels/importAuth 都不覆盖已存在的权威行，重试只补缺失条目，UI 新值不会被旧源覆盖）；收藏来源结构非法同样记录告警，不静默跳过。收藏读取如实反映库内条目，每组 200 条上限只拦新增，超限的旧数据仍可被逐条取消，不在读取时静默截断。若入库成功但派生文件或 SDK 应用失败，页面保留新指纹并显示“已保存，但尚未应用”，通过“重试应用”重读并应用当前数据库配置，不重放保存或删除。`models.compat.json` 是为 Pi SDK 自动生成的派生文件，可重建，勿手改。API Key 明文存储，页面和普通接口遮挡密钥；备份应保护数据库、WAL 与派生文件，建议停止服务后连同 JSONL 一起备份。POSIX 在打开数据库前收紧主库与已有 WAL/SHM 权限至 `600`，新建侧文件继承主库权限；不改共享父目录。Windows 的 chmod 不替代 ACL，请将数据目录放在仅授权用户可访问的位置（自定义目录尤其要核对继承权限）。Pi 插件/技能资源与订阅登录入口继续沿用 SDK 能力，并非所有 Pi 文件都已移除。

### 当前会话的代理配置

输入框下方的「主代理 / 子代理」下拉用于切换要编辑的配置，后面的供应商、模型和思考等级复用同一组控件。切换角色不会改变消息发送对象。子代理模型和思考等级可选择跟随主代理；修改自动保存到当前会话，只影响之后启动的子任务，不修改默认新会话配置，也不影响已运行任务。
